## Attempt 2 — the migration (2026-08-27)

**What I did.** `assignment_scope_v002.sql` (v001 plus ADR 0026's two generated
columns, nothing else moved), `authz_grants_v002.sql` (all three chokepoint
grants re-stated), and revision `f3a5c92d8e14` executing both after a
`DROP VIEW`, following `b336333a2805`'s shape exactly.

**Worked.** `alembic upgrade head`, then `alembic check` silent ("No new upgrade
operations detected"), then `alembic downgrade -1` and `upgrade head` again, all
zero-exit. The four view/grant/drift suites are 103 passed — including
`test_identity_grants.py`, whose widened `SANCTIONED_VIEW_COLUMNS` was red in the
baseline.

**Learned.** `CREATE OR REPLACE VIEW` cannot add a column to an existing view's
projection, so the drop is not optional; and because a privilege cannot outlive
the object it sits on, the grant file is not optional either. Without it the
chokepoint would hold nothing on the view it reads every assignment through, and
every landing in the product would resolve to the no-access page — which no test
in this ticket could have told apart from a resolver that was simply wrong.
