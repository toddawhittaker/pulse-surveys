## 2. The mock's token endpoint, its scopes and its registration key (c85b603) — worked

Preceded by a pure refactor (bc81f39): `IssuerKey.sign` built the PKCS#1 v1.5
encoded message inline and verification needs the same encoding, so it is one
function now. No behaviour change; the mock's launch suite passed unchanged
before and after.

Then, as one behaviour commit:

- `TOKEN_PATH = "/token"` in `mock-lms/app/config.py` beside `DISCOVERY_PATH`,
  with a `token_url` property built off the issuer.
- A sixth setting, `MOCK_LMS_TOOL_JWKS_URL`, defaulting to
  `http://api:8000/lti/jwks` and stated as a Compose literal beside the other
  two `MOCK_LMS_TOOL_*` addresses. It is the tool's registration *at* the
  platform — the address a real LMS is given when a tool registers — rather than
  an address of the platform's own, which is why it is a setting and not derived
  from anything.
- `app/tokens.py`: the grant, the four RFC 6749 §5.2 codes, and
  `ADVERTISED_SCOPES` composed from `app.ags::ADVERTISED_SCOPES` and
  `app.nrps::MEMBERSHIP_SCOPE` (added there, beside the service that names it)
  with `openid` at the head. The discovery document and the endpoint answer off
  that one tuple.
- `app/signing.py`: `CompactJws.parse` and `verifies_with`, the same
  standard-library arithmetic read backwards. `alg` is taken from the file and
  never from the token, so a header naming `none` is refused rather than obeyed.
- `app.state.http`, built in the factory and closed in a lifespan, mirroring
  `backend/app/main.py`. The verification runs in a threadpool because the fetch
  and the RSA arithmetic are both synchronous.

The grant module went green first run: **18 passed, exit 0**. The mock's other
suites and the compose stack were unaffected — 103 passed and 165 passed, both
exit 0 — and `mypy mock-lms/app` is clean.

Two decisions worth naming because a reasonable engineer would go the other way,
and both are in ADR 0084: every key in the fetched set is tried rather than the
one the header's `kid` names (the tool publishes one key, and "select by `kid`
then trust" is the mutation the ticket's own test hunts), and the issued access
token is a JWS signed by the issuer key rather than an opaque string, so E1-11
can make the services require one without this process having to remember
anything.

## 4. The tool publishes its key set (ebf4960) — worked
