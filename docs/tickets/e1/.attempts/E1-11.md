## Attempt 3 — where the sync reads the enrollment-window extension from

ADR 0048's closing sentence forbids the obvious answer: "Nothing in `backend/` may
hardcode this URI. It is one platform's spelling of one vendor extension, and the
tool's side of it is an adapter." E1-11's boundary forbids building E3's adapters.
Three ways out, two rejected before writing a line:

- a constant in `roster_sync.py` — the thing the ADR forbids;
- a `Settings` field — a deployment-wide knob for a per-*platform* fact, wrong for
  every registration after the first, and a new environment variable;
- a column on `lti_platform` — where the fact honestly belongs, and E3's
  `PlatformProfile` to add along with the surface that fills it in; the fixtures
  that register platforms here would leave it NULL and no window would ever be
  read, so every window test would fail for a reason that is not the sync's.

Taken: find the extension by the two properties ADR 0048 *fixes* — a member key
that is an absolute URI whose value is an object carrying `start`. Recorded in ADR
0095 with all three alternatives, and with why this is not the "scan a member for
anything that parses as a date" that record's own context section rejects. Worked.

## Attempt 4 — `kid` on the outbound registration (D11)

`pylti1p3.Registration` has `get_kid` and no `set_kid`: it derives one from the
tool *public* key with jwcrypto. Measured on the locked versions that jwcrypto's
derivation and `app.lti.registration.rfc7638_thumbprint` agree byte for byte, so
`set_tool_public_key` would have worked — and would leave the identifier a
platform selects a verification key by computed by a dependency rather than by the
module that publishes the key set, which is the state `rfc7638_thumbprint`'s own
docstring warns about. Taken: an eight-line `ToolRegistration(Registration)`
carrying `set_kid`/`get_kid`, so there is one derivation. Worked.

Read back before the final run, and each of these was found by reading rather
than by a test:

- `MEMBERSHIP_SCOPE` was declared and never used, because
  `NamesRolesProvisioningService` carries the string itself — a second copy that
  could drift. Spent instead: the access token is now asked for *before* the first
  page, so a token-endpoint refusal leaves a call row at all rather than surfacing
  from inside the walk with nothing written. (The rest of the sentence that stood

- `_platform_of` ran the same lookup per member. Split into `_platform_for` and
  `_registration_for`, read once per sync. Committed separately as a refactor.
- The insert-tolerant `user` write caught `Exception`; narrowed to
  `IntegrityError`, which is what it is tolerating.

## Attempt 9 — the verify round's fourth repair: a docstring nothing asserted

The mutation battery found that removing the eager `get_access_token` before the
walk left every conformance assertion green, because `pylti1p3` fetches a token
per request by itself — so the eager fetch's *only* observable effect is the call
row it writes, and nothing was checking it. The test author wrote
`test_a_refused_token_is_recorded_against_the_roster_url_with_the_token_endpoints_status`
(committed as b58a3e4), and it was red: with the token endpoint answering 500, the
sync wrote one row for the section, under the roster's URL, with
`response_code: None`.

So my own module docstring's claim was false in the half nobody could see. The
eager fetch was there and did write a row; what it discarded was the status, and
D9 gives a NULL `response_code` exactly one meaning — the call never reached the
platform — which is the opposite of what had happened.

The repair: the token-fetch handler splits into `except LtiServiceException`, which
records the status the endpoint answered, and `except requests.RequestException`,
which keeps NULL for a genuine transport failure. The status extraction is a
`_answered_status` helper rather than a second copy of the same `getattr` chain,
because the roster read next door already had one and both write into the same
column with the same NULL meaning — `docs/MISTAKES.md` entry 13's shape, one level
below where it usually shows up.
