## 3. `iss=None` for the web door does not work, and could not have (2026-08-26)

First cut passed `iss=claims.get("iss") if door is Door.LAUNCH else None`, to
keep true the sentence in `app/services/session.py`'s `SessionClaims` docstring:
"`iss` is the platform's issuer URL, or `None` for the web door where a session
is not platform-issued."

**It fails**, and not on an assertion — every landing test died inside PyJWT:

    TypeError: Issuer (iss) must be a string.
    .venv/lib/python3.13/site-packages/jwt/api_jwt.py:139

`issue_session` writes `payload["iss"] = iss` unconditionally, and PyJWT refuses
a non-string `iss` outright (its issue #1039 guard). So `iss=None` is a value
that module cannot issue at all: the `str | None` in the signature, the
`payload.get("iss") is None` branch in `verified_session`, and the docstring
sentence above are all describing a state no caller can reach. Nothing in
`tests/unit/test_session_module.py` poses it — `issued()` defaults `iss` to a
string and no case overrides it with `None` — which is why E1-08 shipped green.

Resolved by passing `claims.get("iss")` at both doors: whoever issued the token
the session was minted from, the LMS platform at one door and the identity
provider at the other. One claim, no branch, and honest at both.

`app/services/session.py` is read-only for this ticket, so the false sentence
was not corrected here. It is recorded in ADR 0093's consequences with a "done
when", and reported to the orchestrator rather than fixed silently.

## 4. The error branch, the calm page, and the closed set (2026-08-26)

`finish_web_login` reads `error` before anything else, so a callback carrying
`error` and `code` together never reaches the token endpoint (the test watches
the transport seam, not the page). `cancelled_or_refused` logs one line — the
error code if it is exactly one of four, the literal `unrecognized` otherwise —
then compares the returned `state` to the carried one through
`same_opaque_value`, requiring both sides to be present. Match → the calm page
(`cancelled_page`, HTTP 200, `data-testid="web-login-cancelled"`, three
constants and no argument to put untrusted text in). Anything else → the
existing `refused()` shape. The login cookie is cleared on all three ways out.

Worked first time: `47 passed` in the module.

## 6. A gate run invalidated by edits that landed while it ran (2026-08-26)

The first full unit-and-integration run reported **30 failed, 26 errors**, and
it read exactly like a broken change — the whole web-door module erroring in its
fixtures, the key-set module failing beside it. It was not. The cause was
`ImportError: cannot import name 'cancelled_page' from 'app.services.landing'`,
from a `git checkout` and re-edit of that file that I made **while the run was
in flight**, splitting the work into separate commits.

Nothing shipped from it: the errors were read before they were believed, and the
run was thrown away and repeated on a still tree. The cost was seven minutes and
a result that, taken at face value, would have sent me hunting a defect that was
not there.

Rule, reported to the orchestrator as a candidate `docs/MISTAKES.md` entry:
while a gate is running, the tree is read-only. If an edit cannot wait, kill the
run first — a run whose inputs changed under it reports failures that belong to
no version of the code.
