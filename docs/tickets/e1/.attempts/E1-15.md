### What I built

**`mock-lms/app/tokens.py`** gains the other end of the grant, ~200 lines under
a new section header. `ServiceTokenError` carries the status and the RFC 6750 §3
challenge; `presented_credential` reads `Bearer <token>` off the header;
`verified_access_token` checks signature, `iss`, `aud` and `exp` against this
platform's own key; `authorised_token` is the one door and adds the scope test
as list membership.

Why `app.tokens` and not `app.nrps` (SPEC §13, "use an existing module"):
reading a token back is `issued_token`'s rules read in reverse — same issuer,
same audience, same key, same clock — and two copies of that arithmetic in two
modules is entry 13's shape. The scope stays with the service: the route names
`MEMBERSHIP_SCOPE`, the door asks no questions about what it means.

Decisions worth naming, all in ADR 0099:

- The challenge states **no `error_description`**. RFC 6750's ABNF excludes `"`
  and `\` from that value, so it is the one parameter where interpolating
  anything the caller sent lets the caller write the challenge's syntax. The
  full description goes in the JSON body instead. This was the alternative to a
  sanitiser, which would have been a silent repair (entry 29).
- `header.split()` requiring **exactly two parts** is what kills the
  `split()[-1]` near miss the test names — that mutation reads a genuine token
  out of `Basic <token>`.
- The credential is checked **before** the `role`/`limit`/`rlid` refusal and
  before `require_context`, so an unauthenticated caller learns neither the
  seeded context ids nor which filters exist.
- The handler is a synchronous `def`, so FastAPI already runs the RSA
  verification in a threadpool; no `run_in_threadpool` needed, unlike the token
  endpoint which is `async`.

## Loop A, round 3 — the page bound's home (2026-08-28, implementer)

The security review's LOW 1, tests committed red at `a500820`. Confirmed first:
`pytest tests/integration/test_mock_lms_nrps_requires_a_token.py -q` → **1
failed, 12 passed**, the failure being
`test_an_unauthenticated_read_is_refused_before_the_page_bound_is_checked`.

### The finding

`page` was declared `Annotated[int, Query(alias=PAGE_PARAMETER, ge=1)] = 1`.
FastAPI validates a route parameter before the handler is entered, so `?page=0`
answered `422` naming the parameter and its bound to a caller who had presented
no credential — the one exception to the ordering claim the route docstring and
ADR 0099 both make. `?page=abc` was the same hole in its other form: the *type*
is enforced there too.

### What I changed

`page` is now `Annotated[str | None, Query(alias=PAGE_PARAMETER)] = None` and
`app.paging::page_number` reads it behind `authorised_token`.

- **Where.** `app.paging`, not `main.py`: that module already owns
  `PAGE_PARAMETER`, the 1-based rule and `window`'s own `page < 1`, and the
  bound was living in two places (the signature and `window`). SPEC §13's "use
  an existing module".
- **Which status: 400.** E0-28 item 2's code, and `test_mock_lms_paging_and_
  service_urls.py:70` states the reasoning I am inheriting rather than inventing
  — "400 says the platform read the request and will not serve it … a 422 from a
  model that could not parse it is a different fact". The red test deliberately
  left the choice open (a 4xx, not 401/403, whose body names `page`). It is also
  deliberately **not** the 404 `window` raises for a page past the end: that is a
  client following a header into nowhere, and page zero is a cursor no collection
  could have.
- **Parsing.** `page_number` judges the string whole and repairs nothing (entry
  29). `int` accepts leading whitespace, a sign, and a Python literal's
  underscores, so `int(" 1_0")` is 10 — a request for page `1_0` would have been
  served page ten of a collection it never named. ASCII digits only, then the
  bound; absent is `FIRST_PAGE`.

### The two shapes the round asked me to decide, measured

A probe against the running application (`create_app()` + `TestClient`, no
credential) rather than reasoned:

| unauthenticated request | answer |
|---|---|
| no query, `?page=0`, `?page=abc`, `?page=`, `?page=1_0`, `?page=%202`, `?page=2` | **401**, `WWW-Authenticate: Bearer`, every one |

Authenticated, the refusal branch is executed by the new test's `?page=0` half,
which asserts a 4xx naming the parameter; `?page=abc` reaches the identical
branch, which is what the `page_number` table above shows rather than argues.
