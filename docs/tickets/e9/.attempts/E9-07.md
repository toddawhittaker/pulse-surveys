What worked:

- `views_sql/org_node_label_v001.sql` and migration `e9f6c8e0a706`
  (down_revision `e9a7c9e1b807`): one row per institution, college,
  department, prefix and course; a course is named "MATH 140 — College
  Algebra", `course_label`'s course form, built in SQL. Upgrade, `alembic
  check`, downgrade one and upgrade again all pass on the private database

- First version failed `test_every_relation_a_view_sql_file_names_is_schema_qualified`:

  that sweep reads as a `regclass` lookup. Fixed by dollar-quoting the five
  level names (`$$institution$$`), with a comment saying why.
- The read: `queries.org_node_labels_above` (a recursive walk up
  `parent_id` from each section's course) behind
  `authz.ScopedReader.org_node_labels(section_ids=...)`, which refuses any
  section outside the purview. `rollups._held_sections` reads the sections
  from `section`, then every name from that one call; the `College`,
  `Department`, `Course` and `Prefix` model reads and `course_label` are gone
  from rollups.
- EXPLAIN: no index. The owed read's `instructor_response` statement uses
  the existing `ix_instructor_response_section_id_week_id` as a bitmap index
  scan at 40 and 2,000 sections over a structural copy holding about 230,000
  rows (0.5 ms and 23 ms). The copy was used because the table's write
  trigger refuses synthetic rows; it has the same columns and indexes.
