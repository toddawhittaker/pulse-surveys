## 2026-08-21 — the security review's five findings, and the fix round (worked)

`d08083a`. The independent review ran the attacks rather than reading the diff,
and it found the ticket's own strategy applied one level short. Five findings,
graded three HIGH, one MEDIUM and one LOW; the MEDIUM is the one where a
**recorded decision was overruled** rather than a gap filled, and it is the one
worth reading cold:

1. **The service level was not a closed set.** `ALLOWED_TOP_LEVEL_KEYS` bounds
   which sections may appear and says nothing about what a service body carries,
   which is where nearly every host-reaching Compose key lives. Measured, each
   with the whole suite green: `volumes_from: - db` on `worker` (every mount
   `db` has, the entire Postgres data directory), `cgroup: host`, `uts: host`,
   `runtime:` and `develop.watch`. Closed by `ALLOWED_SERVICE_KEYS` — ten keys,
   enumerated from the documents *after* PyYAML resolves the `<<:` merges,
   because a list written from the visible lines is three keys short and fails
   the base file on its own anchor.
2. **`name:` and `driver:` on a named volume were admitted as inert metadata**
   and read by nothing. Both are the `external: true` argument word for word:
   a `name:` attaches the volume to a pre-created Docker volume under exactly
   that name, and `docker volume create --opt device=/ --opt o=bind --opt
   type=none` is one command. `READABLE_VOLUME_KEYS` narrowed to
   `("driver_opts", "labels")`, with the three "defined elsewhere" keys refused
   together and told apart from "this module cannot read the shape".
3. **A credential typed out as a literal was seen by nothing.** Every rule
   followed `${...}` references, so the superuser URL spelled out in `worker`'s
   `command:` passed. Answered by a recursive walk over every string in every
   service body, keys included, on every service including `db` — `command:`,
   `entrypoint:`, `healthcheck.test`, `labels:` and `build.args` all reach a
   container and none is an `environment:` entry.
4. **The relative privilege comparison was defeated by the shared anchor**
   (the MEDIUM). "No more privilege than `api`" was E0-03's decision and it read
   well; the override merges `x-development-source` into all three application
   services, so one line there grants all three at once and the comparison sees
   no difference. Measured green for `privileged: true`, `pid: host`,
   `network_mode: host`, `userns_mode: host`, `devices:` and
   `cap_add: SYS_ADMIN`. The rule is absolute over both files now, with
   exceptions in `ALLOWED_PRIVILEGE_GRANTS` — empty, and validated, so an entry
   for a key the named service does not declare is itself a failure. The
   argument for the comparison is kept beside the new rule rather than deleted:
   it is a good argument with a hole, and the next person to want it back should
   read why it went.
5. **Route 3's delivery accounting folded case.** A lower-case
   `alembic_database_url: ''` withdrew the upper-case `ALEMBIC_DATABASE_URL`
   from the accounting, so a service holding the credential reported clean.
   Compose folds neither and the container receives both. `delivered_values` is
   case-sensitive now; the one folded map left is for resolving `${...}`
   references, kept deliberately apart from the accounting.

Fixed tests-first by the original test author, so no test was written by whoever
was defending the code. **17 fix-round mutations, all killed**, and both original

counter is for preventions.
