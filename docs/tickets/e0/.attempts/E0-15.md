## Reading the surface before designing it

Read in this order: the ticket (including today's amendments inside the existing
sections), `docs/tickets/e0/README.md`'s "What the built tickets settled",
SPEC §2.2, §3.4, §7.3, §8 and §9.2, `docs/MISTAKES.md`, `mock-lms/app/` whole,
and the three test modules plus the E0-15 section of `tests/conftest.py`.

Four things the tests fix that the ticket does not spell, found by reading rather
than by failing:

  - `MockPlatform.paths()` skips any route carrying a path parameter, so the
    Advantage routes cannot collide with `path_named_after`'s fragment matching
    for `auth`, `jwks` or `openid-configuration`. Only `/mock/posted-scores` is
    parameterless and new, and it answers JSON, so `offers()` skips it on the
    content-type check rather than parsing it for a launch form.
  - `MockPlatform.local()` reduces an advertised absolute URL to path and query,
    so the services must advertise absolute URLs built from `settings.issuer`
    and must route on the path alone.
  - `test_the_enrollment_window_ends_the_dropped_member_and_nobody_else`
    compares the two sets across **every** seeded context, not within one, so
    exactly one member in the whole seed may carry an `end` and exactly that
    member may be non-`Active`.
  - `test_no_page_of_a_walked_roster_comes_back_empty` is the boundary case: a
    roster whose size is an exact multiple of the page size must not advertise a
    next page. The seed therefore holds one section of exactly one page's worth
    of members, so that case is exercised rather than described.

Result: no dispute. Every criterion is implementable as written.

## The implementation, in one pass

Two new modules beside E0-14's — `app/nrps.py` and `app/ags.py` — with the routes
in `main.py`, the path templates and URL builders in `config.py`, the two service
claims in `launch.py`, and the seed rewritten. `pages.py` changed one line: the
launch page's user selector now offers `platform.launch_users()`, the users
enrolled in every context, because the seed grew students who take one section
and the page's two selectors are chosen independently.

**35 passed** across the three modules, and 315 with `tests/unit` and E0-14's
launch module added. `ruff format`, `ruff check` and both `mypy` runs clean.

Choices worth recording because a later reader will wonder:

  - **Page size 5, as a constant rather than a setting.** Its only job is that
    the rosters divide, and a knob for it would exist to be turned to "all of
    them" — the arrangement paging exists to stop anyone shipping.
  - **Roster sizes 12, 7 and 5** against that page size. Five is the boundary
    case: a roster that is an exact multiple of the page size is where a platform
    advertising `next` whenever the page it served was full serves an empty page.
  - **`first`, `prev` and `last` ride along with `next`.** No test asks for them.
    A client written against a header that only ever carries one relation passes
    against a single-relation header and breaks on the first platform that sends
    two, and §7.3 names NRPS paging as a per-platform deviation.
  - **The score body is read with `json.loads` off the raw request**, never
    through a Pydantic model, because a model is precisely a thing that defaults,
    drops and re-renders. That is what makes "verbatim" true rather than likely.
  - **A score with no `scoreGiven` clears the user's result**, which is AGS 2.0's
    meaning for an absent one. Three lines, and **nothing asserts it** — declared
    in the pull request rather than left to be discovered.

## Verifying by mutation

Seventeen mutations, run with the controls `docs/MISTAKES.md` entry 16 asks for:
baseline recorded first (none failing), the failures each mutation *adds*
reported rather than an exit code, never `-x`, the replaced text asserted to

Fifteen killed, by the test named for the thing each broke. Two came back
SURVIVED, and they are different from each other:

  - **"the seed uses one start letter and one modality" was not a mutation.**
    It renamed `MATH-140-E1FF` to `MATH-140-R4WW`, and `NURS-8100-Q2FF` still
    supplied the second letter and the `FF` modality by itself. Renaming both of
    the other sections killed it immediately, on the two tests named for it.
    Recorded against entry 16, which is where its own warning about mutations
    that change no meaning lives.
  - **"the roster body ignores the context it was asked for" is a real gap.**
    `membership_page` reading `platform.contexts[0]`'s members while the
    container goes on naming the right context leaves all 61 tests green. This
    ships as a convention, is recorded against entry 2, and is reported in the
    pull request with the test it needs.
