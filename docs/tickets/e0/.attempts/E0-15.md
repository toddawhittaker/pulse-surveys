## Reading the surface before designing it

Read in this order: the ticket (including today's amendments inside the existing
sections), `docs/tickets/e0/README.md`'s "What the built tickets settled",
SPEC §2.2, §3.4, §7.3, §8 and §9.2, `docs/MISTAKES.md`, `mock-lms/app/` whole,
and the three test modules plus the E0-15 section of `tests/conftest.py`.

Four things the tests fix that the ticket does not spell, found by reading rather
than by failing:

  - `MockPlatform.paths()` skips any route carrying a path parameter, so the
    Advantage routes cannot collide with `path_named_after`'s fragment matching
    for `auth`, `jwks` or `openid-configuration`. Only `/mock/posted-scores` is
    parameterless and new, and it answers JSON, so `offers()` skips it on the
    content-type check rather than parsing it for a launch form.
  - `MockPlatform.local()` reduces an advertised absolute URL to path and query,
    so the services must advertise absolute URLs built from `settings.issuer`
    and must route on the path alone.
  - `test_the_enrollment_window_ends_the_dropped_member_and_nobody_else`
    compares the two sets across **every** seeded context, not within one, so
    exactly one member in the whole seed may carry an `end` and exactly that
    member may be non-`Active`.
  - `test_no_page_of_a_walked_roster_comes_back_empty` is the boundary case: a
    roster whose size is an exact multiple of the page size must not advertise a
    next page. The seed therefore holds one section of exactly one page's worth
    of members, so that case is exercised rather than described.

Result: no dispute. Every criterion is implementable as written.

## The implementation, in one pass

Two new modules beside E0-14's — `app/nrps.py` and `app/ags.py` — with the routes
in `main.py`, the path templates and URL builders in `config.py`, the two service
claims in `launch.py`, and the seed rewritten. `pages.py` changed one line: the
launch page's user selector now offers `platform.launch_users()`, the users
enrolled in every context, because the seed grew students who take one section
and the page's two selectors are chosen independently.

**35 passed** across the three modules, and 315 with `tests/unit` and E0-14's
launch module added. `ruff format`, `ruff check` and both `mypy` runs clean.

Choices worth recording because a later reader will wonder:

  - **Page size 5, as a constant rather than a setting.** Its only job is that
    the rosters divide, and a knob for it would exist to be turned to "all of
    them" — the arrangement paging exists to stop anyone shipping.
  - **Roster sizes 12, 7 and 5** against that page size. Five is the boundary
    case: a roster that is an exact multiple of the page size is where a platform
    advertising `next` whenever the page it served was full serves an empty page.
  - **`first`, `prev` and `last` ride along with `next`.** No test asks for them.
    A client written against a header that only ever carries one relation passes
    against a single-relation header and breaks on the first platform that sends
    two, and §7.3 names NRPS paging as a per-platform deviation.
  - **The score body is read with `json.loads` off the raw request**, never
    through a Pydantic model, because a model is precisely a thing that defaults,
    drops and re-renders. That is what makes "verbatim" true rather than likely.
  - **A score with no `scoreGiven` clears the user's result**, which is AGS 2.0's
    meaning for an absent one. Three lines, and **nothing asserts it** — declared
    in the pull request rather than left to be discovered.

## Round two — the review round's HIGHs and the MEDs taken with them

Baseline: **15 red**, all in the AGS module, and the three strengthened guards
from `b566a8a` green against the seed as it stood — the late add is already one
member later than a cohort of eleven, `end` is already a present key rather than
an omitted one, and the seed's ordinals already run contiguously from 01.

Read first: `docs/tickets/e0/E0-28-review-debt-from-e0-15.md` for what is
deliberately *not* mine, `gh pr view 31 --comments` for the reproductions, and
E0-15's new paragraph settling the two protocol questions — one of which reverses
an earlier brief, since an **equal** timestamp is accepted where the suite
asserted the opposite for a day.

Built in two commits, refactor first:

  - **`app/paging.py`**, extracted from `app.nrps` with no behaviour change. The
    line-item container has to page "exactly as `nrps.py` does", and that is a
    rule two copies of would be two things to keep in step. `page_url` gained the
    one thing a roster never needed — it preserves the query the collection was
    asked with — because a filtered container whose `next` drops the filter hands
    back page two of something else.
  - **The AGS rules.** Every check runs before the append, which is the half a
    status-only assertion cannot see: a refusal that stores the score and then
    answers 4xx is worse than an acceptance. The 409 carries its status on the
    exception rather than in the route, because AGS fixes that one code and
    leaves the rest to the platform.

Choices worth recording:

  - **The results fold takes the newest by timestamp, arrival order breaking a
    tie**, not the last to arrive. Those agree while the 409 holds — which is
    the point, not a redundancy: two guards face one hazard, and a later ticket
    relaxing the guard would otherwise silently regress every grade.
  - **The line-item container pages always, at five, rather than only when a
    `limit` is asked for.** A container that answers everything until somebody
    asks it not to is a container whose paging nobody exercises, which is the
    defect this finding is.
  - **`last_timestamp` is read off the log rather than cached beside it.** A
    cache of a fact the log already carries is a fact that can disagree with it,
    and the log is what the ticket makes authoritative.

## Verifying round two by mutation

Nineteen mutations, same controls as round one, baseline clean. **Fourteen killed**,
each by the test named for what it broke — including the two that matter most: the
score appended before it is checked (13 tests red) and the stale-score guard
truncated to the minute, which is the boundary the equal-timestamp ruling created.

**Four survived, and exactly one is a gap.** Written out because the ratio is the
lesson: a survivor is a result about the mutation until it has been read.

| Survivor | Why | Kept? |
|---|---|---|
| a non-positive score maximum is accepted | the disagreeing-maximum rule refuses it first, and `create_line_item` already refuses a non-positive line-item maximum, so a score maximum past both is positive by construction | yes — load-bearing the day ADR 0051's rule is relaxed |
| a naive timestamp is accepted | the offset check beside it is strictly stronger | yes — it produces the *true sentence* for a bare date |
| results fold by arrival order again | the 409 makes the log monotonic, exactly as `results()`'s own docstring predicts | yes — the two guards face one hazard |
| an unmatched filter falls through to everything | **a real gap**: every line item the suite creates carries a `tag` and a `resourceId`, so a filter widened to match line items *lacking* the member leaves all 28 tests green | reported, cannot be closed on this side of the test wall |

The three that stay now say in the code that a test cannot tell them apart from the
guard beside them, which is the honest version of keeping them.

## One thing found by probing rather than by the review

`datetime.fromisoformat` accepts a compact `+0000`; RFC 3339 does not, and ADR
0048 already holds an enrollment window's `start` to the spelling with the colon.
No test covers a score timestamp spelled that way, so the mock would have
accepted on one service exactly what it refuses on the other — `docs/MISTAKES.md`
entry 13, found by running every refusal branch before writing the commit message
rather than by reading the code and agreeing with it. Closed in the same commit.
