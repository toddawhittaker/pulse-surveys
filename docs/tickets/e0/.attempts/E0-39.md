## 2026-08-22 — layer 1 and layer 2 in `backend/app/config.py` — worked

Five `oidc_*` fields moved out of the defaulted "two entry doors' addresses"
block and into the required group, immediately after `environment`. Two
`field_validator`s at the foot of the class refuse the mock outside development:
one over the four URLs comparing `urlsplit(value).hostname` against
`MOCK_IDENTITY_PROVIDER_HOST`, one over `oidc_client_id` comparing the whole
value against `MOCK_IDENTITY_PROVIDER_CLIENT_ID`.

Two things decided while writing it:

- **Field validators rather than a model validator.** The tests require the
  refusal to *name the field*, and `_describe_invalid_settings` builds its lines
  out of the field name, the static `description=`, and pydantic's error code —
  it never uses the validator's own message. A model validator's error carries an
  empty `loc`, so it would render as "(unknown variable)" and both
  "names the field" tests would stay red. A field validator gets the name for
  free and keeps the module's existing idiom.
- **Reading `ENVIRONMENT` through `info.data`** makes declaration order
  load-bearing: pydantic validates in declaration order, so the five have to sit
  after `environment` or `info.data.get("environment")` is empty and nothing is
  ever refused. Written down in a comment at the block rather than left implicit.
  `_is_a_deployment` treats a non-string as *not* a deployment, which is safe
  because `environment` is itself required — a `Settings` that reaches the
  validator with no environment is already being refused for that variable.

Result: the new provider-configuration module was 53 passed, and the whole unit
suite was 3 failed / 569 passed — the three remaining failures being the compose
rows, which are the next commit's.

## 2026-08-22 — the development values move to Compose and `.env.example` — worked

The five went into `x-application-environment`, the shared anchor, rather than
into three service blocks: `api` merges that anchor inside its own `environment:`
and `worker`/`beat` take it through `x-application`, so one place covers all
three `Settings`-building services and there is no copy to forget. Spelled
`${OIDC_ISSUER:-http://mock-idp:8000}` and so on, which is the form the compose
module's `oidc_fallback_spelling` pins.

Measured all three directions with `docker compose config`, read-only, without
touching the running stack:

- merged base + override with the repository `.env`: all five resolve on `api`,
  `worker` and `beat`.
- base file alone with an env file holding only the nine `${...:?}` variables and

`.env.example`: the five entries moved from "Defaulted — optional" up into the

## 2026-08-22 — the refusal, read as an operator reads it — worked

`docker compose run --rm --no-deps` (a one-off container; the eight running ones
were never touched, checked with `docker compose ps` afterwards) built a real
`Settings` inside `api`, `worker` and `beat` against the merged environment: all
three came up in development, printing the mock's addresses. The same one-off
container with `-e ENVIRONMENT=production` refused, naming four of the five —
`OIDC_AUTHORIZATION_ENDPOINT` is `localhost:8081`, which is correctly permitted.

Reading that output found something the tests do not ask about.
`_describe_invalid_settings` builds the report from the field name, the static
`description=`, and pydantic's code; a validator's own message never reaches the
operator (ADR 0056). So the refusal printed "OIDC_ISSUER — rejected by this
setting's own validation" and a description about `iss` claims, and an operator
would go and re-type a URL that is spelled correctly. The rule was enforced and
nobody was told it existed — the same shape as `docs/MISTAKES.md` entry 1's
E0-37 instance, in reverse.

The fix is the one this module already uses: `ai_provider_base_url`'s description
carries its whole transport rule for exactly this reason, so each of the five now
ends with the sentence an operator has to act on. Re-measured in the container:
every line now says what is wrong. Descriptions are static strings, so this adds
no value to the log — the "never quote a value" test stays green. Unit suite
after the change: 572 passed.
