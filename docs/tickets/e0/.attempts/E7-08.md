## Attempt 1 — 2026-10-10 — how the pages tell the gate's 403 from other 403s

Found before writing: the frontend unit tests already serve a 403 with the
server's own sentence (ADR 0190's no-review-grant on the queue and the log; a
not-the-definer refusal on the set list and on a delete) and expect that
sentence on the page. So "map every 403 to not-your-role" would break them and
would change ADR 0190's answer to a dean, which the ticket puts out of scope.
Decision: the gate's 403 carries `WWW-Authenticate: Bearer
error="insufficient_scope"` (RFC 6750 section 3.1, the standard answer for a
valid token without the privilege), and `api/leadership.ts` reads a 403 with
that challenge as `not-your-role`. No other 403 in this stack carries a
challenge. Recorded in ADR 0196.
