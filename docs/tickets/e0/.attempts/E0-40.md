## Attempt 5 — the security review's fix round (worked)

Stopping rule declared before the round: these two fixes, the new red guard
green, one verifier re-run, stop.

**The red, confirmed first.** `test_every_makefile_recipe_that_runs_npx_installs_the_pinned_closure_first`
failed with three offenders — `lint`, `typecheck` and `e2e` — over a module of
9: **1 failed, 8 passed**.

**MEDIUM — `npx` on a clean clone fetches and runs whatever is latest**
(commit `a166013`). Two of the three offenders are this ticket's own: attempt 3
moved eslint and tsc from `cd frontend && npx …`, which never ran because the
directory is not there, to a bare `npx …` at the root, which does run. Making a
dead gate live is what turned an inert unpinned call into an executing one, and
nothing in the round noticed because `npx` succeeds. The third, `e2e`, predates
the ticket and stated its `npm ci` precondition in a comment above the target.

The fix is one `node-deps` target — `npm ci` behind the same root-manifest probe
the other node targets use — named as a prerequisite by `lint`, `typecheck`,
`e2e` and `licenses`. **The prerequisite form rather than four inline copies**,
because make builds a phony prerequisite once per invocation. That is measured
rather than argued: `make -n ci` shows one `npm ci` invocation (plus its banner
`echo`) serving four `npx` calls — eslint, tsc, playwright, license-checker.
`licenses` gave up the inline install it already had, which is why the count
went to one instead of two.

Executed, not read: `make lint` exit 0 (npm ci → ruff clean → eslint) and
`make typecheck` exit 0 (npm ci → three mypy runs → tsc).

**Mutation:** dropped `node-deps` from `lint`'s prerequisites, leaving the recipe
untouched. The guard went red naming `lint` alone, with the other two still
compliant through the chain. Restored from a snapshot; 9 passed.

**LOW — Dependabot watched a directory that has never existed** (commit
`401c30c`). `.github/dependabot.yml`'s npm ecosystem pointed at `/frontend`
while the repository's only `package-lock.json` sat unwatched at the root. That
is this ticket's founding defect in a second control: a probe aimed at a path
that is not there reports nothing and looks well. One entry at `/`, since there
is one lockfile; the React major-version ignores went with the directory they
were about, and E1 re-adds a `/frontend` entry with them. Also corrected: the
github-actions comment claiming it was the only ecosystem with anything to
watch. Parsed after the edit — five ecosystems, npm at `/`.

The file is under `.github/` and is not a workflow and adds no secrets
reference, so it is inside the charter; noted because the boundary is stated in
directories rather than in files.
