Two false starts worth recording:

1. `eslint.config.js` produced a `MODULE_TYPELESS_PACKAGE_JSON` warning on every
   run, because the file is ESM and `package.json` declares no `"type"`.
   Renamed to `.mjs` rather than adding `"type": "module"`, which would change
   how every other `.js` in this package is resolved for one config file's sake.

   `tseslint.configs.recommendedTypeChecked` at top level, so `npx eslint .`
   applied type-aware rules to every `.js` it met while walking the tree —
   including the JavaScript coverage.py vendors inside `.venv/`, which crashed
   the run (exit 2). Fixed by scoping the rule sets with `files:` **and**
   ignoring the non-source trees; both halves are needed, and the config says so.
