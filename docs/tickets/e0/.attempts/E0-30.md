# E0-30 — attempts

## 2026-08-21 — item 1, the error redirects. Worked.

**What I did.** Followed the ticket's design, with one addition it does not
spell: the split between "answered with a page" and "answered by redirect" is a
*type*, not a flag.

- `AuthorizationRequestError` now carries `error` (the RFC 6749 §4.1.2.1 code)
  and `description`, and every raise site names a code. `str(refusal)` is still
  the description, so `refusal_page(str(refusal))` was untouched.
- A second exception, `AuthorizationRedirectError`, carries the same two plus a
  `redirect_uri` that has already validated and the `state` to echo (or `None`).
  It is **not** a subclass of the first, so the two `except` clauses in
  `main.py` cannot be got the wrong way round by accident.
- `Flows.begin` keeps the three page refusals (unknown `client_id`,
  unregistered `redirect_uri`, and either of those two arriving twice) and then
  calls `Flows._pending_request`, which holds every other check. The wrapping
  `except AuthorizationRequestError: raise refusal.delivered_to(...)` sits in
  `begin` at the point the address becomes known good. **That split is why the
  ordering near miss cannot regress**: nothing in `_pending_request` can run
  before `redirect_uri` has been compared with the registered one.
- `Flows.sign_in` does the same around a new `_person_signing_in`, after
  `_spend_pending` — so a refused login still spends the request, and the
  refusal is delivered to the address the *pending request* holds rather than
  one the submission named.
- `begin` now takes the parameter **pairs** rather than a mapping, so the
  duplicate-parameter rule lives beside the other checks it is ordered against
  instead of in the router. `main.py::authorize` lost its pre-validation
  duplicate block entirely.
- `added_to_query(url, parameters)` in `flow.py` is the one place the
  "`&` where a query exists" rule lives; `authorization_response` and the new
  `error_response` both go through it.

**Two things I nearly got wrong, recorded so a future me does not repeat them.**

1. `state` has to be echoed on refusals raised *above* the check that `state` is
   present — `response_type` and the three scope refusals all fire before it.
   So `begin` reads it once with `submitted()` after the redirect check and
   hands it to `delivered_to`; `_pending_request` still calls `required()` for
   the presence refusal. Two calls, one edge read, no second parse.
2. Empty vs absent `state`. `submitted()` gives `""` for absent, and
   `delivered_to(..., state or None)` turns that into no `state` parameter at
   all — RFC 6749 §4.1.2.1's "if present". Emitting `state=` empty is the
   mutation the test names.
