# E0-30 — attempts

## 2026-08-21 — item 1, the error redirects. Worked.

**What I did.** Followed the ticket's design, with one addition it does not
spell: the split between "answered with a page" and "answered by redirect" is a
*type*, not a flag.

- `AuthorizationRequestError` now carries `error` (the RFC 6749 §4.1.2.1 code)
  and `description`, and every raise site names a code. `str(refusal)` is still
  the description, so `refusal_page(str(refusal))` was untouched.
- A second exception, `AuthorizationRedirectError`, carries the same two plus a
  `redirect_uri` that has already validated and the `state` to echo (or `None`).
  It is **not** a subclass of the first, so the two `except` clauses in
  `main.py` cannot be got the wrong way round by accident.
- `Flows.begin` keeps the three page refusals (unknown `client_id`,
  unregistered `redirect_uri`, and either of those two arriving twice) and then
  calls `Flows._pending_request`, which holds every other check. The wrapping
  `except AuthorizationRequestError: raise refusal.delivered_to(...)` sits in
  `begin` at the point the address becomes known good. **That split is why the
  ordering near miss cannot regress**: nothing in `_pending_request` can run
  before `redirect_uri` has been compared with the registered one.
- `Flows.sign_in` does the same around a new `_person_signing_in`, after
  `_spend_pending` — so a refused login still spends the request, and the
  refusal is delivered to the address the *pending request* holds rather than
  one the submission named.
- `begin` now takes the parameter **pairs** rather than a mapping, so the
  duplicate-parameter rule lives beside the other checks it is ordered against
  instead of in the router. `main.py::authorize` lost its pre-validation
  duplicate block entirely.
- `added_to_query(url, parameters)` in `flow.py` is the one place the
  "`&` where a query exists" rule lives; `authorization_response` and the new
  `error_response` both go through it.

**Two things I nearly got wrong, recorded so a future me does not repeat them.**

1. `state` has to be echoed on refusals raised *above* the check that `state` is
   present — `response_type` and the three scope refusals all fire before it.
   So `begin` reads it once with `submitted()` after the redirect check and
   hands it to `delivered_to`; `_pending_request` still calls `required()` for
   the presence refusal. Two calls, one edge read, no second parse.
2. Empty vs absent `state`. `submitted()` gives `""` for absent, and
   `delivered_to(..., state or None)` turns that into no `state` parameter at
   all — RFC 6749 §4.1.2.1's "if present". Emitting `state=` empty is the
   mutation the test names.

**Verification.** 112 passed / 0 failed across the five named modules; whole
unit suite 361 passed (the ADR 0062 AST sweep included — no new `strip`,

**Naming detour.** The redirect exception was first called
`AuthorizationErrorRedirect` and ruff's N818 refused it (exceptions need an
`Error` suffix). Renamed to `AuthorizationRedirectError`.

## 2026-08-21 — Round 2, the three security-review findings. Worked.

Three findings, all with tests already written and red. Step 1's measured reds
were seven cases: the two blank-`state` cases, **all three** NQSCHAR cases, and
the two registration cases as DID-NOT-RAISE. The one the test author could not
predict — `[a poisoned code challenge]` — was **red**, so the PKCE refusal quotes
the challenge like the other two raise sites do. Round 1's `PADDED_STATE` echo
case was green at HEAD and stayed green, which is what says the provider was not
already trimming `state`.

**Finding 1 (MED), `error_description` outside RFC 6749's grammar.** Bounded in
`app.flow.bounded_to_nqschar`, called from `error_response` — the single place
the redirect's parameters are built, which is the only place that holds for all
three raise sites the test drives. `NQSCHAR` is a frozenset built from Appendix
A.8's three ranges and every character outside it becomes `?`. **Substitution
rather than deletion**, one character for one character, so a non-empty
description stays non-empty without a second branch to guard `1*`. No swept name
is used, so the ADR 0062 gate is untouched.

**Finding 2 (LOW), a registration that presets `error`.** `RESPONSE_PARAMETERS`
in `config.py` is now four names rather than two. One set rather than two,
because `validate()` asks one question of it and a split set is a set one half of
which gets forgotten.

**Finding 3 (LOW), a blank `state` reflected on the refusal that says it is
absent.** This is the one with the trap in it. The tempting fix — strip `state`
— is what `PADDED_STATE` exists to kill, and the fix that is right is not about
`state` at all: `begin` was **re-deriving** presence as `state or None` after
`required()` had already judged it on the trimmed value. So the judgment moved
into `app.flow.carried()`, which returns the untrimmed value or `None`, and both
`required()` and `begin` read that one verdict. `delivered_to` already wanted
`None` for "no `state` arrived", so the call site got shorter rather than longer.
That is ADR 0062 rule 1 applied to its own implementation.

**Verification.** Five-module battery 120 passed; whole unit suite 363 passed;

**Records.** `docs/MISTAKES.md` entry 3 44 → 45 (the manifest's own rationale:
