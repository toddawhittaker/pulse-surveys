## Item 4b — worked

**Reproduced both before changing anything, and they are two different defects
that the ticket's one-line summary hides.**

- `regex`: `License-Expression: Apache-2.0 AND CNRI-Python`. A well-formed SPDX
  expression, split correctly, both halves permissive. The failure was that no
  rule knew `CNRI-Python`, so the conjunction took the worst of `allow` and
  `unknown`.
- `tiktoken`: no `License-Expression` at all. Its `License` field is the full
  1078-character MIT text. Measured: five case-insensitive `AND` connectors, four
  of them the lowercase "and" of prose (the first at offset 149, "of this
  software and associated documentation files"), splitting the body into six
  fragments of which only the first names a licence. The bug was treating a body
  as an expression.

**The discriminator is a newline, and the choice was measured rather than
argued.** Across the 99 installed packages, exactly one `License` field contains
a newline (tiktoken, 1078 chars); the other 98 are at most 36. The two
populations do not overlap, so no threshold needs choosing, and an SPDX
expression is a single-line grammar anyway. A length test also passes every case
— the battery confirms it — so this is a preference for the rule with no dial,
not a claim that length is wrong.

**What makes the unsplit scan safe is RULES' ordering**, not the discriminator.
Verified against the real texts in `/usr/share/common-licenses`: the full 35KB
GPL-3 body denies, the full LGPL-3 body reviews.

**A finding worth keeping:** the full GPL-3 body denies with the *Affero* rule's
reason, because its section 13 is headed "Use with the GNU Affero General Public
License". Verdict right, reason names the wrong family. Documented in the
docstring rather than fixed — narrowing it means deciding which mention is the
declaration, which is a bigger change and buys a better message, not a better
answer.

**Blast radius, measured by classifying all 99 packages with the old module and
the new one side by side:** `regex` and `tiktoken` move `unknown` -> `allow`.
Nothing else changes, and nothing moves out of `deny` or `review`. Unknowns go
from 2 to 0; the real `make licenses` run now prints no "no recognizable license"
section at all.

**Mutations** (`scratchpad/lic/battery.sh`), each confirmed landed, restored from
a snapshot rather than `git checkout`:

| mutation | result |
|---|---|
| delete the body branch | RED — tiktoken back to unknown, and the MIT-body-mentioning-GPL case flips to *allow*, because a body with commas takes the OR path and that path keeps the best fragment |
| drop `\bCNRI\b` | RED |
| Affero rule moved below the GPL rule | RED — **only the reason assertion fires** |
| an allow rule moved above the deny rules | RED |
| the blanket `MIT` rule this was told not to add | RED — the real GPL-3 and AGPL-3 bodies both allowed |
| length instead of a newline | GREEN (legitimate alternative) |
| `len(splitlines()) > 1` instead of a newline | GREEN (means the same thing) |

The third row is why every body case asserts the reason as well as the verdict,
and it is the MISTAKES entry 3 instance recorded with this round: an AGPL body
denies either way, so the verdict cannot see the ordering guarantee breaking.

## Not done, deliberately

- **No `--strict-unknown` added to any caller.** Nothing passes it, so `unknown`
  was already reported and already did not fail the build. This change does not
  unblock a red gate; it makes the classification honest so the flag becomes
  usable later. Said in the commit because a reader will assume otherwise.
- **Lockfiles, `pyproject.toml` and the dependency set untouched.**
- **`CNRI-Python-GPL-Compatible` still denies**, because the `\bGPL` deny rule
  sits above the permissive one. Conservative, pinned by a case, and widening it
  is not this change's business.
- Items 4a and 5 are not in scope here.

## Review round — a gate weakening I introduced, and the signal I walked past

The first version of the body scan classified the **real GPL-2 as `review`**, an
advisory that exits 0, where the old code said `deny`. Found by review. Cause:
the body was scanned in RULES order, and the GPL-2 preamble names the LGPL at
line 18, so the LGPL rule — which sits above the GPL rule so the narrower family
wins in an expression — outranked the title at the top.

**The signal was in my own fixtures and I did not read it.** I had trimmed the
GPL-3 excerpt to stop before section 13 because its "Use with the GNU Affero
General Public License" heading produced a confusing reason. That is the same
defect, met once, patched inside a fixture, and never generalised. A fixture
edited to make a test comfortable is a finding you have already made and
declined to name.

**Fix: `classify_body` takes the rule matching earliest in the text**, because a
licence names itself before it mentions any other. Chosen over a
declaration-region scan on measurement, not preference — a first-non-blank-line
region sends BSD and MPL-2.0 from `deny` to `unknown`, since BSD's first line is
a copyright notice and MPL's title does not match its own allow rule.
Earliest-match fixes GPL-2 and leaves both where they were, needs no region size,
and makes the Affero-reason wart disappear without a special case.

**Fixtures are now real excerpts**, the smallest that carries the declaring line
and the trapping phrase, each verified to give the same verdict *and* reason as
the full file. Pasted, never read from `/usr/share/common-licenses` at run time —
that path is absent on every CI runner and the case would pass vacuously.

**Two claims of mine that measurement falsified, both corrected in place:**

- I wrote that the AGPL title "pins the tie-break to list order". It does not:
  `Affero` matches at offset 4 and `General Public License` at 11, so Affero
  wins on position. No two of these patterns can match at the same offset at
  all, so the tie-break direction is a choice about an unreachable case and the
  docstring now says exactly that.
- My MISTAKES entry 3 instance said the `affero-below-gpl` mutation was the only
  thing catching the reason assertions. After the fix it does not fire at all;
  the catcher is `rule-order-body`, via the GPL-3 case's reason. The instance is
  rewritten around the fixture-trimming lesson, which is the sharper one.

**What the checker now accepts, measured two ways** — and the inventory alone is
what hid the defect, because only one of the 99 installed packages has a newline:

| | before | after |
|---|---|---|
| `regex`, `tiktoken` (inventory) | unknown | allow |
| tiktoken MIT body | unknown | allow |
| Apache-2.0, Artistic, CC0-1.0 bodies | deny | allow |
| LGPL-2.1, LGPL-3 bodies | deny | review |
| GPL-1, GPL-2, GPL-3 bodies | deny | deny |
| BSD, MPL-2.0 bodies | deny | deny (both wrong, pre-existing) |

**Recorded, not fixed:** the body path denies the BSD and MPL-2.0 texts. Both
predate this change, correcting either widens the gate beyond item 4b, and both
are now asserted in the self-test labelled recorded-not-endorsed so they cannot
drift silently. "Conservative" is not an accurate description of the body path
and the docstrings no longer use it.
