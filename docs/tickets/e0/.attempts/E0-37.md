## 2026-08-21 — commit 1, item 12: off-machine means https (worked)

The early return on a missing key is gone, so the rule reads the URL and nothing
else. The validator is `an_off_machine_endpoint_is_encrypted` now and no longer
takes `info: ValidationInfo` — it had no other use for it, and `ValidationInfo`
came out of the pydantic import with it. Its docstring lost the "What this
deliberately does not refuse" paragraph and the ADR 0056 citation that argued for
the cluster case, and carries the decided rule instead. The refusal message leads
with the comment and calls the credential "any provider credential configured
with it", so it no longer reads as though a keyless configuration had nothing at
risk.

One thing the brief did not name, found by grepping the fact rather than the
identifier: the `ai_provider_base_url` **field description** (`config.py:310`)
also said "it must be https when that key is set". That string is the
operator-visible one — the startup report is built from the field name and this
description rather than from the validator's message — so leaving it would have
printed the old rule at the moment the new rule refused something. Corrected in
the same commit.

`README.md` and `.env.example` both tied the requirement to the key. In
`.env.example` the rule moved to `AI_PROVIDER_BASE_URL`, where it belongs now
that it does not read the key, and the paragraph under `AI_PROVIDER_API_KEY` says
so explicitly rather than being deleted — that is the paragraph an operator with
a keyless vLLM would have read.
