## 4. `python-multipart` is not in the closure, and `request.form()` needs it (2026-09-01)

First version of `POST /dev/clock` read the field with `await request.form()`,
on the belief that Starlette parses `application/x-www-form-urlencoded` without
`python-multipart` and needs it only for `multipart/form-data`. **False on
Starlette 1.6**: `Request._get_form` asserts `parse_options_header is not None`
before it looks at the content type at all, and that name comes from
`python_multipart`. Four console cases failed with

    AssertionError: The `python-multipart` library must be installed to use form parsing.

Fixed by parsing the body directly — `urllib.parse.parse_qs` over
`(await request.body()).decode(...)`, four lines in `posted_field`. Adding
`python-multipart` to the locked closure was the alternative and was not taken: a
development scaffold is not a reason to widen the dependency set, and the body a
`<form method="post">` sends is exactly what `parse_qs` reads.

## 9. Both disputes ruled, and the security round on the method gate (2026-09-01)

`E2-04-01` and `E2-04-02` were both ruled the implementer's way. The route walk now
lives in `tests/fixtures/routing.py` and flattens `_IncludedRouter`, and
`RUNTIME_BASE_TABLE_PRIVILEGES` took `clock_override`'s three verbs. Nothing under
`backend/` changed for either.

Then the security review measured what the exposure module's method probe had
missed. The two clock paths were registered twice — a `POST`, and a second
registration naming the six other **standard** verbs — so a method token outside
that list matched no route at all and Starlette answered `405 Allow: POST` from the
router, before the in-handler gate ran. `TRACE` reaches it, and so does an
arbitrary token like `FOO`. Confirmed on HEAD before touching anything:

    AssertionError: `/dev/clock` answered {'TRACE': (405, 'POST'), 'FOO': (405, 'POST')}
    with `ENVIRONMENT` set to 'production'

That is `docs/MISTAKES.md` entry 35 in its usual shape, and it falsified the "404 to
every method" sentence in `dev.py`, in ADR 0109 and in the ADR index.

**The fix, and why it took a route class.** Widening the list would have been the
third enumeration. So each path is one route matching *any* method, with the handler
answering anything that is not `POST` with the same bare 404 the environment check
gives. Getting "any method" out of the pinned libraries took one measurement:

- `APIRouter.api_route` requires a `methods` list, and every route class FastAPI
  builds carries one — so this cannot be said in FastAPI's own vocabulary.
- `starlette.routing.Route.matches` treats `self.methods is None` as no restriction,
  but `Route.__init__` coerces `methods=None` to `["GET"]` **for a function
  endpoint** (only a class endpoint keeps `None`). So the route is built naming
  `POST` and the restriction is cleared on the next line — `AnyMethodRoute`, three
  lines including that one.
- Verified through `include_router` in a scratch script before any of it was written
  into `dev.py`: nine methods, 404 for all but `POST`, and no `Allow` header at all.

Costs, stated in the class docstring and in ADR 0109: the two paths leave the
OpenAPI schema (`get_openapi` walks `APIRoute` instances only) and lose `Depends`,
so `replace_the_override` and the clear handler open their own `SessionLocal()` —
the position `app.main.framing_ancestors` is already in, and the same answer.

**One route per path rather than a POST route plus a catch-all after it.** The
two-route arrangement also works, because a partial match only becomes a 405 when no
full match is found anywhere — but it makes the behaviour depend on the order of two
registrations, and the whole finding was that the router was deciding something the
handler should. One route per path leaves no ordering to get wrong.

ADR 0109 gained the accepted-residue paragraph the round asked for: the controls
take a plain form with no CSRF token, so a page a developer visits can post to their
own stack's clock. **A claim was corrected while writing it** — the first draft said
Compose publishes the API on `0.0.0.0:8000` and a same-LAN host could post directly.
`docker-compose.override.yml` publishes `127.0.0.1:8000:8000`, so that is false; the
paragraph now says the request has to come through a browser on the developer's own
machine, and the loopback publish is named as a narrowing rather than as a
hardening left untaken.

`docs/disputes/E2-04-01.md` still prints the old six-verb route table as the evidence
it was ruled on. That is a closed record of a measurement made on 2026-09-01 and it
is left as it stands rather than rewritten.
