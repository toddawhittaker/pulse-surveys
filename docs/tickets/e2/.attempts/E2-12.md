## 2026-09-02 — the floor measurement. BLOCKED, and not by anything in this diff.

`.env` in this worktree carried a blank `AI_PROVIDER_API_KEY`; the credential is
in the main checkout's `.env` and was piped into the run's environment without
being written anywhere or printed.

The provider the ruled `.env.example` value names refuses the request the gateway
makes. Measured, in this order:

1. One live call: `AIProviderRefusedError: The model endpoint answered HTTP 400`.
2. `GET /v1/models` on that account serves `deepseek-v4-flash`,
   `deepseek-v4-pro`, `deepseek-v4-flash-vision-exp` — so the model name is not
   the problem.
3. Posting `response_format: {"type": "json_schema", …, "strict": true}` by hand
   to both non-vision models: `{"error":{"message":"This response_format type is
   unavailable now", …}}`. Posting `{"type": "json_object"}` to the same model in
   the same second: HTTP 200 with a well-formed answer.
4. Captured what the gateway actually puts on the wire, against a loopback stub,
   rather than inferring it: `keys on the request: ['messages', 'model',
   'response_format', 'stream']`, `tools: null`, and the `response_format` is
   `json_schema` / `strict: true` carrying `CommentValidityOutputPayload` — which
   is ADR 0053's `NativeOutput` doing exactly what SPEC §7.4 asks of it ("no tool
   use").
5. Posted the **shipped prompt, unchanged**, under `{"type": "json_object"}`, and
   validated each answer against the shipped contract: `substantive`,
   `insufficient`, `nonsense`, `substantive` over the four probe comments —
   including one from each of the two families the character heuristic gets
   wrong.

So the blocker is the output *mode* and nothing else: not the prompt, not the
contract, not the model, not the credential. No floor was measured, and no floor
can be until it is ruled on — which is the ticket's own instruction for this
shape ("a finding to raise and wait on, not a quiet edit"), and the reason
nothing here was edited to get past it. The two available routes are named in the
report; both are decisions with an ADR attached, and neither is the
implementer's.

**The constraint worth carrying forward, stated once here because it is the part
that is easy to lose:** nothing in the suite can tell you a provider is
unusable. Every ordinary run reaches the loopback stub or `mock-ai`, and both
answer whatever they are asked, so an endpoint that refuses the gateway's output
mode is green in every gate until a live eval run meets it. Check structured
outputs before naming a provider on those two lines.

provider's, and the orchestrator holds the new one.
