## 3. The eighth red is disputed, not worked around

**What happened.** `test_a_deployments_stored_roster_host_is_not_exempted_from_the_pin`
is red with the finding fixed and was red with it unfixed. The set it reads holds
two entries — the token endpoint's (ADR 0101, every environment) and this ticket's
roster-host entry — and `platform_on_https` builds both URLs off one issuer, so
both entries are the string `roster-platform.invalid`.

**Proven by mutation rather than by reading** (`docs/MISTAKES.md` entry 3).
Disabling the token-host entry and re-running the pair did not make the test pass
on its own assertion: it failed earlier, at "The page's member … was not
ingested" — no token, so no page. The token entry is load-bearing for the call
ADR 0101 describes, and it is what puts this host in the set. The mutation was
reverted and the file compared before going on.

**What I did not do.** I did not time-scope the token exemption to the token
request, which would make the test green. It contradicts what ADR 0101 and the
work order both settle, it is not a local edit, and a set mutated at the end of a
run so a reader sees what it wants is a fix written for the test.

**Escalated:** `docs/disputes/E2-02-01.md`, with the test quoted, the two entries
named, the mutation's evidence, and the two test shapes that would be able to see
the difference. The narrowing itself stays in the branch — its development half is
proven by the passing pair member, and AC3 asks for the code and the docstring to
agree, which they now do.
