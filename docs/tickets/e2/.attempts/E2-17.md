**The e2e serving mechanism, settled before the browser half.** The Compose
stack serves `/opt/pulse/frontend`, baked into the api image by
`backend/Dockerfile` (`COPY --from=frontend /src/frontend/dist /opt/pulse/frontend`,
`ENV FRONTEND_DIST=/opt/pulse/frontend`). `docker-compose.override.yml` mounts
only `./backend`, so a frontend edit in this worktree is invisible to the
running stack, and there is no documented worktree-serving path — `make e2e`
assumes the stack is already up and does not build. The file-level swap is
therefore `npm run build --workspace frontend` here followed by
`docker cp frontend/dist/. pulse-surveys-api-1:/opt/pulse/frontend`. Starlette's
`StaticFiles` resolves each request against the directory, so no restart is
needed, no image is rebuilt and no container is stopped. The original directory
is copied out first and restored afterwards.

Two things that follow from it and are worth knowing cold: the container's
`/app/backend` is bind-mounted from the **main** checkout, so the browser suite
runs this branch's frontend against main's backend (no e2e spec asks for
`course_label`, so nothing here depends on the backend half); and while the swap
is in place the stack serves this bundle to any sibling worktree running e2e, so
it is put back as soon as the run finishes.

Everything else went green on the first browser run except two.

**The conditional-required announcement had to have its own live region.** It
was written into the same region as SPEC §3.3's bounce coaching, which broke
`student-survey.spec.ts`'s thin-comment test: that test chooses a rating of 2
before submitting, so by the time the bounce arrived the region was already
saying "A rating that low asks for a sentence…", `await expect(announcement).
not.toBeEmpty()` passed on the wrong sentence, and the quotation-mark assertion
read it. Two independent facts need two regions, each empty until its own is
true. The second one is clipped at all times — the flag and the helper are the
same fact on screen already.

**The slider-track colour test cannot be satisfied**, and that is
`docs/disputes/E2-17-01.md`. `getComputedStyle(input,
'::-webkit-slider-runnable-track')` returns the *input's own* style in Chromium
— proven by the height and width it answers with (44px and 200px, the input's,
not the track's declared 4px) and by a control reading an ordinary `::before`
correctly — so the painted colour it compares is `transparent`. Making the
input's own background the token satisfies that assertion and then makes
`effectiveBackground(slider)`, which starts its walk at the slider, answer the
same colour: ratio 1.00, and the assertion beside it wants more than 1.30. Both
directions are measured in the objection. The implementation is left as the
ticket asks (`--mist`, published, prototype in step) and nothing is written to
get past the test.
