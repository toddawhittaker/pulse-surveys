## 2026-09-02 — the prompt trim. Worked, and it was built rather than written.

`validity.v2.md` was produced by **slicing `validity.v1.md`**, not by retyping
it, and that was the whole method rather than a convenience. The brief requires
several regions byte-exact, and the sharpest of them is the closing passage's
final sentence: `mock-ai/app/rules.py` holds it as `MARKER_LINE` and extracts
every development-stack comment on it, so a reworded or re-wrapped line leaves
the mock hunting a boundary the prompt no longer has and answers the
extraction-failure 500 on every local classification. Retyping a sentence from
where you think it begins is how a wrap moves (`docs/MISTAKES.md` entry 3), so
nothing was retyped.

The build script asserts its anchors before it trusts its slice — a shifted file
would otherwise cut plausibly in the wrong place — and then checks eleven
properties of the result: no section symbol anywhere, the marker sentence present
*and on its own line as v1 wraps it*, the placeholder last, the whole closing
passage byte-identical in both files, the three verdict definitions, the
injection rule with its example, the JSON instruction, and each of the three
dropped regions absent. All eleven passed.

Independently confirmed by diffing v2 against the retained slices of v1: the only
differences are the two intended ones — the reworded line and the blank that
joins the two kept regions. v1 shows as unmodified in `git status`; only v2 is
new. 98 lines and 4,194 bytes become 83 lines and 3,646 bytes, so 548 bytes of
documentation stop riding in front of every student comment.

What went: the nine-line header, every section symbol inside the rules — each
rule keeping its *reason* in plain words, since the reason is what decides a
borderline case — and the paragraph forbidding a returned prompt version, which
the structured-output schema already makes impossible.

`app.ai.tasks.VALIDITY_PROMPT_VERSION` names `validity.v2` now. v1 is untouched
and stays: rows recorded against it have to keep resolving to the text that
produced them, which is the whole property the constant carries. The prompts
README grew a "Rendered?" column, and says in as many words that the column
describes the constant rather than being a second source of truth.

## 2026-09-02 — the model. Luna serves the output mode; it has no snapshot to pin.

**The output mode was verified before any value was committed**, because a
provider that refuses `json_schema` cannot hold the real triple at all and that
would reopen the provider question rather than being mine to settle. One
classification through the real gateway on the v2 prompt: `substantive`, under
`validity.v2`, in 1,041 input tokens and 17 output. Luna serves it. No stop.

**The pin could not be taken, and that is the one place this diverges from the
letter of the brief.** The instruction was to use the dated Luna snapshot rather
than the alias. There is no dated Luna build, checked three ways rather than
assumed:

1. the model listing serves 130 models, and exactly one of them contains "luna" —
   `gpt-5.6-luna`, with no dated variant, where every neighbouring family has one
   (`gpt-5-mini-2025-08-07`, `gpt-5.4-mini-2026-03-17`);
2. retrieving that model returns the same bare identifier and a null
   `shutdown_date`;
3. a completion's envelope reports `gpt-5.6-luna` unchanged — where `gpt-5-mini`
   resolved to `gpt-5-mini-2025-08-07` — and there is no `system_fingerprint`
   either.

So "use what it serves" and "use the snapshot, not the alias" point at the same
string, because the alias is all there is. The value is `gpt-5.6-luna` and the
*property* the pin bought is unavailable rather than declined: the weights can
move with nobody editing anything, a floor breach and a model change are
indistinguishable from here, and no configuration can detect it.

That is recorded where somebody would meet it rather than only in the report —
beside both configuration entries, in ADR 0120's consequences, and in the
deferral about the three untied identifier sites, which the switch sharpens: the
fourth thing that can now disagree with the other three is the weights, and no
test can read those. The paragraph in ADR 0118 arguing for a dated snapshot is
marked superseded in part, because it is now false as written.
