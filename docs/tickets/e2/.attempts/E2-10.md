### The three decisions that needed recording

**ADR 0116 — self-host the faces.** E1-04's deferred item 1 was due against this
screen and is closed in place in `docs/tickets/e1/deferred.md`. The alternative —
a `<link>` to a font host — is a third-party request made on a student's behalf
from inside their institution's iframe, which is E0-18's own reasoning
transferred. Measured on the branch: the payload the bundle gate counts is
**93,572 bytes gzipped with the faces and 93,353 without**, so the six
`@font-face` rules cost **219 bytes**; the faces themselves are **119,100 bytes
of woff2** the gate does not count, plus **147,028 bytes of woff** that ships
because each `@fontsource` stylesheet lists both and no supported browser fetches
it. The pre-ticket baseline at `62323c3` measured **85,487 entry / 87,878
total**, so the whole ticket is **+4,218 entry / +5,694 total**, of which the
webfont decision is 219.

**ADR 0117 — two `fetch` calls rather than a generated client.** SPEC §13's tree
draws "generated client from backend OpenAPI + TanStack Query hooks" and E1-04
left the choice to this screen in as many words. Two calls do not pay for a
generator, its output, a build step and a currency check, and the generated
client would still need the outcome mapping — which is the interesting half,
because what a status means here is which of `app.copy`'s sentences it carries.

**The copy split.** Question wording, the Likert bounds, the slider's range and
step, and §3.2's conditional rule all come off the question rows and are consumed
as they arrive; SPEC §3.2 quotes no wording for the two comments or the slider,
so their labels are this screen's. The bounce coaching and every refusal are
shown exactly as the server sent them.

Two governed sentences — the heading "Your weekly check-in" and the nothing-open
line — **moved** out of `frontend/src/lib/landings.ts` into the copy module,
verbatim, because the student route is no longer a landing view and E2-11 should
find one module per surface. `landing-views.spec.ts` holds its own copies of both
and stayed green untouched, which is the proof they did not change; the
`pulse-landing-student` testid did not move, because five specs address it.

### The end-to-end spec, and how it was proved

Three cases in `tests/e2e/student-survey.spec.ts`, against the running stack:
completing all five questions with the slider driven from the keyboard alone and
the week recorded; a thin comment coached where it was typed with every other
answer surviving and the fix going through; and the question wording on screen
being the API's, proved by altering the stored set.

**Each was verified by mutation before it was believed** (`docs/MISTAKES.md`
entry 3), one at a time, with the tree restored from a file snapshot between
each — never `git checkout`:

| Mutation | Result |
|---|---|
| `LikertInput`'s legend renders a hard-coded copy of §3.2's first question | case 3 red, 1 and 2 green |
| `isCommentRequired` always answers false | case 1 red |
| the bounce attaches to no field (`positions = []`) | case 2 red, 1 green |

Each killed exactly the case it should and left the others alone, which is what
says the three are about three different things.

**Two support modules.** `tests/e2e/support/clock.ts` holds the `/dev` clock
helpers, because `dev-clock.spec.ts` and `window-scheduling.spec.ts` each already
carry a copy and a third hand-copy is `docs/MISTAKES.md` entry 13 written out.
Those two specs deliberately keep theirs, for the reason `doors.ts` records for
the six specs it declined to refactor: they are this suite's proven-green
baseline for the clock and the new spec leans on that baseline, so putting a diff
on the control in the pull request that uses it is the thing that record refused.
The next ticket that edits either of them moves it over.
`tests/e2e/support/stack.ts` shells out to `docker compose` for the two things a
browser cannot do — running the hourly window derivation now rather than on the
half hour, and reading and writing the question set.

**Why the spec has to derive windows at all.** The three mock-platform contexts
reach this database through a launch (`app.services.provisioning`), so the
section is younger than the seed and has no materialized `survey_window` rows;
they arrive on `crontab(minute="30")`. A spec cannot wait an hour and must not
invent the rows — the read path answers exactly the materialized set (ADR 0111),
so a hand-written row would be the spec agreeing with itself about SPEC §3.1's
rhythm. The real task is called instead, in the `api` container.

**Why each case clears the week first.** ADR 0109 makes the development clock an
offset rather than a freeze, so setting it to the same pretended minute an hour
later in real time lands a few seconds *earlier* than the previous run reached. A
revision written against that clock carries a `last_submitted_at` before the
stored `first_submitted_at`, `response`'s own check constraint refuses it, and
the route answers 500. That is a real finding and it is in
`docs/tickets/e2/deferred.md`; the spec works around it rather than fixing it,
because the fix is in `app.services.submissions`.

### Two things about the local environment, for whoever comes next

The worktree's `.env` predated E2-07: it pointed `AI_PROVIDER_BASE_URL` at a
placeholder provider and carried neither `AI_PROVIDER_API_KEY` nor
`PUBLIC_BASE_URL`. Every submission therefore answered 503 through the honest
classifier-unavailable path (ADR 0114), which looked exactly like a broken form.
The two AI values were aligned with `.env.example` and the two missing names
added; the previous file is beside it as `.env.before-e210`, and nothing secret
was read or changed. CI copies `.env.example` wholesale, so CI never had this.

The stack serves the built frontend **out of the image** (`FRONTEND_DIST` in
`backend/Dockerfile`), and `docker-compose.override.yml` bind-mounts `backend/`
only. So a frontend change needs `docker compose up -d --build api` to be
visible. During iteration `docker cp frontend/dist/. pulse-surveys-api-1:/opt/pulse/frontend/`
does the same job in a second; the final verification was against a real image
build.
