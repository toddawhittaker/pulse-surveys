### Things worth knowing next time

* **The `week` grant was missing before this ticket.**
  `survey_windows.derive_windows_for_section` already selects `week` rows on the
  `pulse_app` connection and no revision had granted it. Repaired here because
  this read needs it; stated in the SQL header and in E2-09-02 rather than left to
  be found.
* **Every one of the five grants is load-bearing, measured one at a time.**
  Granting them in order, the read path stops on the next relation each time:
  `week` → `question_set` → `question` → `response` → `answer`. Without the
  revision at all, 12 of the 14 items fail with `InsufficientPrivilege` (36
  occurrences in one run); the two survivors are the route-table controls, which
  read no rows.
* **The grants ship as a `views_sql/*.sql` file, not inline in the revision.**
  ADR 0041's decision names the grants file explicitly ("the roles, two views, the
  `SECURITY DEFINER` reveal function, and the grants") and every grant in this
  tree follows it, E2-06's `survey_window_grants_v001.sql` a day ago included. The
  ticket's criterion 4 — "no new module under `backend/app/views_sql/`" — is read
  as forbidding a new **view**: it cites E2-01's sweep, whose exempt list is
  Python modules, and a grants file creates no view and adds nothing to the
  policed inventory. Flagged in the report and the PR body rather than decided
  quietly.
* **The Bearer-only shortcut was available and refused.** Making
  `require_student` ignore the cookie would turn E2-09-01 green in one line; it
  contradicts `session_from_request`'s documented contract, makes the CSRF
  double-submit machinery dead code, and would be a silent divergence from the
  contract E2-08 is building against.
* **A response body with a varying value would red the parameter test.**
  `test_naming_another_section_is_answered_exactly_as_naming_one_that_does_not_exist`
  demands byte-identical bodies across reads when two plain reads agree, so
  nothing in this answer may carry "now" or any other moving value.
* **The open/closed flag has to be a boolean that flips.** `booleans_in` collects
  every boolean by path and requires one that is `true` inside the window and not
  `true` on either side; `survey_is_open` is that field, and the window itself is
  `null` when nothing is open.
* **The test-edit hook matches the whole Bash command positionally.** `mv … &&
  pytest tests/…` is blocked because the `mv` sits before the `tests/` token. Two
  separate calls, with nothing suspicious ahead of the path, run fine.
