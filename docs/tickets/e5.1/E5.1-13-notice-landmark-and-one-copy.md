# E5.1-13 — The held-comment notice is not a landmark, and the question-set rule has one guarded home

**ID:** E5.1-13
**Branch:** `e5.1/notice-landmark-and-one-copy`
**Depends on:** 01, 07
**Lane:** light
**Size:** XS

## Context

Two E5.1 epic-boundary findings on e14da4a.

1. **MEDIUM (a11y-copy).** `frontend/src/components/SmallNNotice.tsx` (about
   line 48) renders the notice as `<section aria-labelledby>`, a named region
   landmark. Since E5.1-01 a week with both streams held renders two notices,
   so a screen-reader user's landmark list holds two regions with the same
   name, "No raw comments are shown here this week". WCAG 2.2 asks landmarks of
   one type to be distinguishable. The surrounding labelled group section and
   its heading already name the stream, so the notice needs no landmark.
2. **LOW (spec-conformance).**
   `tests/unit/test_each_services_rule_has_one_copy.py` (about lines 30-45)
   guards the current-question-set rule only by "survey_read has no
   `_current_question_set`". A new private copy in `grading.py` or
   `submissions.py` would pass. All three call `submissions.current_questions`
   today.

## Decisions (settled)

- The notice renders as a plain `<div>` with the same heading and text. Tests
  that find it by region role (`CommentGroup.test.tsx` about line 315,
  `tests/e2e/instructor-report.spec.ts` about line 566) switch to a test id or a
  text query. A test asserts a week with both streams held renders no region
  landmark named by the notice.
- The one-copy test gains a pattern entry for the current-question-set query,
  in the style of its other entries, with `submissions.py` as its home, so a
  copy anywhere else under `backend/app/services` fails it.

## Done when

1. No `section` or `region` role is rendered by the notice, with a test; the
   existing notice tests still pass with the new query.
2. Planting a private current-question-set query in `grading.py` fails the
   one-copy test (shown once by hand, recorded in the PR body).
3. CI is green on the head.
