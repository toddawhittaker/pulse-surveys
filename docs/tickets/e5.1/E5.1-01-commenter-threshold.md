# E5.1-01 — Raw comments need five commenters in their stream

**ID:** E5.1-01
**Branch:** `e5.1/commenter-threshold`
**Depends on:** none
**Lane:** heavy ⚠ (SPEC §14.3 puts the threshold query under line-by-line
human review)
**Size:** L
**Security-relevant:** the §4 suppression rule itself and the §4.1 item 3
invariant tests. A defect here shows one student's words under a week heading.

## Context

The comment gate counts responses, not commenters. In a week with six
respondents where one student wrote in the instructor stream, that one comment
is shown, and the gradebook ledger can name its author. Ruling 1 fixes the
rule: raw comments for a stream in a week are shown only when at least 5
distinct students commented in that stream that week. Below that, the stream's
comments are held for release batches.

The same code has a second defect. A comment that was released in a batch can
come back under its own week if the threshold setting is later lowered,
because the week read has no anti-join against `release_batch_member`.

Where the code is:

- `backend/app/services/report_comments.py`: `visible_comments` (`:289`)
  compares responses with the threshold at `:332`, and the count it reads
  (`:326-346`) has no anti-join against `release_batch_member`.
  `_held_comments` (`:635-722`) holds by response count (`:706`).
- `backend/app/services/reporting.py:437`: the small-N summary switch reads the
  week's response count.
- ADR 0153 line 113 says a week of exactly the threshold's responses shows its
  comments "with the same size of candidate set". That stops being true per
  stream.

Read first: SPEC §4 and §4.1 item 3, §5.2 (the notice states no count),
ADR 0153 whole, and `docs/MISTAKES.md` entry 50 (a threshold that protects
people is crossed by a count of people).

## Done when

1. **One stream hides, the other shows.** In a section-week with 6
   respondents, where 1 student commented in the instructor stream and 5 in the
   course stream, the instructor stream returns no raw comment and the course
   stream returns its 5. One test asserts both streams.
2. **The invariant test catches the old count.** §4.1 item 3's invariant test
   counts distinct commenters per stream. Swapping the count back to responses
   turns it red.
3. **Held streams go to release batches.** A held stream's comments enter
   `_held_comments` per stream, are cut by the existing release rules, and
   appear only in a batch with no week.
4. **A released comment never comes back under its week.** A comment that has
   a `release_batch_member` row is never returned by `visible_comments` for its
   own week, including after the threshold setting is lowered from 5 to 4.
5. **Summaries follow the stream's count.** A stream below the commenter
   threshold is summarized with the small-N prompt and passes the reuse guard.
   The test asserts the prompt version stored on the row.
6. **The notice states no count.** The per-stream notice states the threshold
   and gives no commenter count (§5.2). The copy inventory passes over the new
   wording.
7. **The records match.** SPEC §4 and §4.1 item 3 say "distinct commenters in
   that stream". ADR 0153 line 113 is corrected. ADR 0182 records the
   per-stream hold and the never-re-shown rule.

## Known traps

- **A count of responses or comments is not a count of people.** Count
  distinct students per stream (entry 50).
- **Emptiness satisfies nothing.** Every hidden-stream assertion sits beside a
  shown stream in the same world (entry 3).
- **Lowering the threshold is the near miss.** Criterion 4 must lower the
  setting inside the test, not start from 4.

## Out of scope

- Raising the threshold re-holding weeks already seen. That is carried to E11
  (hand-off 3, written by E5.1-09).
- Weeks with one or two responses. Ruling 2 keeps their figures.
