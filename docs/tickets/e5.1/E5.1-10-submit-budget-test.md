# E5.1-10 — The submit budget tests stop failing on one slow sample

**ID:** E5.1-10
**Branch:** `e5.1/submit-budget-test`
**Depends on:** none
**Lane:** light
**Size:** S
**Security-relevant:** no. Test-only change.

## Context

Two tests in `tests/integration/test_the_submit_path_follows_adr_0056s_taxonomy.py`
timed one submission and asserted it took less than SPEC §10's 2.5 seconds.
That figure is a p95, and one sample cannot test a p95. CI run 37166495313
failed one of them at 2.58 seconds on a commit that changed only
documentation (PR #265), and the same code had passed twice before.

The assertions exist to catch `docs/MISTAKES.md` entry 41's defect: a submit
that waits on a broker that is down, for six seconds or more on every
request.

## Owns

- the two budget tests in that module and their module docstring

## Done when

1. **Each budget assertion reads a median.** Each test makes three
   submissions (the first and two resubmissions, which ADR 0115 revises in
   place) and asserts the median is under the budget. The test says it does
   not prove the p95.
2. **Entry 41's hang still fails it.** `publish_once` without its bounded
   connection, run once locally, fails the broker-down test.
3. **The clock self-check still runs**, unchanged.
