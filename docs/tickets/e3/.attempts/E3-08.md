## 2026-09-05 — the two controls, built and probed against the running stack

The mock amendment route and the dev sync control went in as the work order
describes them, and both were probed by hand against the rebuilt containers
before any spec was re-run — because a green spec cannot say *which* refusal a
route makes.

`POST /mock/roster-amendments`: 422 on `{"nonsense": true}`, 404 on a section
the platform does not seed, 409 on an ordinal `NURS-8100-Q2FF` already holds,
404 on dropping a member that section does not hold, 422 on a `closed_at`
carrying no UTC offset, 400 on a body that is not a JSON object. An `add`
answered 201 and a `drop` 200, and restarting the container put the seed back —
which is how the per-process state was confirmed rather than assumed.

`POST /dev/roster-sync`: the console renders `data-testid="roster-sync-run"`;
a cross-origin POST is 403, `GET` is 404, `TRACE` is 404, and a same-origin POST
is 303. The gates are the route class's, so this is a check that the class was
applied and not a second implementation of them.

The one design choice worth recording: `SeededPlatform` lost `frozen=True`
rather than gaining an `object.__setattr__` escape hatch or a holder threaded
through five `_register_*` functions. Every route in `mock-lms/app/main.py`
closes over the one instance, so an amendment has to reach that object; the
records it holds stay frozen, so what an amendment changes is which enrollments
exist and never what one says.

## 2026-09-05 — the drive could not launch the third section: no NURS prefix

P1 failed with `section holds 0 rows with lms_context_id =
mock-lms-context-nurs-8100-q2ff` after three staff launches that all landed. The
API log said why, in one word: `unknown_prefix`.

`scripts/seed.py` seeded MATH, STAT, MIS, BIOL, PSYC, CSCI and BUSA, and
`_ingest_the_context` refuses a launch whose label names a prefix the
institution does not hold. So `NURS-8100-Q2FF` — the mock's third section, and
the only home of SPEC §3.4's undated tier — had never reached this database at
all. E2 met the same wall and recorded it in a spec comment
(`student-survey-confidentiality.spec.ts` and
`student-survey-heading-and-next-window.spec.ts` both say "seeds no NURS
prefix"); it worked around it by using other sections, which an exit table
naming that section's windowless member cannot.

Fixed by seeding the prefix under the Biology department. Not a department of
its own: every seeded department carries a chair, so a new one needs a person
invented to chair a prefix the demo seeds no course in. No course is seeded
either — the launch upserts the course it names. The two E2 spec comments are
now stale in one sentence each; they are behind the test wall, so they are named
in the pull request for the test author rather than edited here.
