## Step 1 — the mock's AGS routes ask for a token

Two commits. The refactor first: the translation from `ServiceTokenError` to a
status and an RFC 6750 §3 challenge lived inside the roster route, and six more
routes were about to want it, so it came out as `require_a_token`. Nothing else
changed and the roster suite stayed at 14 passed.

The behaviour then. `authorised_token` takes one scope or several and passes on
membership of any (`scope in granted`, never a prefix or a substring); the 403
challenge's `scope` parameter lists every accepted scope space-delimited. All six
AGS routes call `require_a_token` as their first statement, before the query
parameters and before `require_context`/`require_line_item`. Both containers'
`ge=1` bounds came out of the route signatures — `page` and `limit` are now
unbounded strings judged by `app.paging::page_number` behind the credential, and
a value that is not one answers 400 naming the parameter (`_not_a_page`).

**Worked.** `test_mock_lms_ags_requires_a_token.py` 48 passed. The four
neighbouring suites that drive these routes — the AGS line-item/score module, the
paging module, the NRPS enforcement module, the credentials grant, and the roster
conformance module — 103 passed together.

One thing to note for anyone reading `page_number` later: it is asked about
`limit` as well as `page` now. The grammar is the same one (a run of at most nine
ASCII digits, one or more), so the reuse is exact rather than approximate, and
`page_size` still clamps an over-large value rather than refusing it.

## Step 2 — the client

`backend/app/lti/ags.py` plus `backend/app/lti/platforms/{__init__,base,mock}.py`.
Green on the first run: `test_the_ags_client_is_a_conformant_service_client.py`
19 passed, mypy clean over all 76 backend sources.

Choices worth knowing about, because a later reader will wonder:

- **The request is made on the connector's own transport, not through
  `ServiceConnector.make_service_request`.** That method discards the status code,
  which is exactly what `ags_call` records and what ADR 0129 gives a meaning; and
  its `Link` reader is the one `roster_sync` documents as wrong in two ways. The
  token still comes from `connector.get_access_token([scope])`, so there is no
  unauthenticated path in the client.
- **`timestamp` is a `str`, not the `datetime` the work order's sketch names.**
  The tests hand a string (`fixtures/ags_client.py::A_TIMESTAMP`) and criterion 3
  asserts the platform received those exact bytes, `+00:00` and all. A `datetime`
  would be re-rendered by the client, which is the mutation ADR 0052 is about.
  Reported as a departure.
- **`scoreGiven` is placed into the JSON text rather than serialised.** The score
  is checked against RFC 8259's number grammar, a uuid marker stands in for it
  while `json.dumps` writes the rest, and the marker's quoted form is replaced
  once. A float round-trip is byte-stable only for canonical `repr` strings, so it
  would silently break on `61.50`.
- **The 409 re-read uses AGS's own `user_id` filter**, so the platform is asked
  about one student rather than the class — and the `ags_call` row is written
  against the *unfiltered* results address, because settled decision 5 keeps an
  LMS user id out of that table and the filter puts one in the query string.
- **`PinnedResolutionAdapter` is imported from `roster_sync` (a public name), not
  copied.** It is a security control and two copies are two places for one to go
  stale. The Link-header parser *is* copied, because the roster's is private.
  Rehoming both is proposed in the PR rather than done — it crosses a module
  boundary.
