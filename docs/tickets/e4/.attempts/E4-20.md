## 3. The seeder, and a green that meant nothing — the second attempt worked

First version: the module docstring's runbook, a raw `ENVIRONMENT` guard ahead of
every `app` import, and the world read through the section, its closed windows,
the question set and the roster. Both tests went green on the first run.

**That green was wrong and the tests could not have told me.** The environment
refusal I wrote said "…writes a term of invented survey responses and comments
for `BIOL-310-R7FF` into whatever database it is pointed at". The module's
section matcher is `SECTION_CODE.lower() in text.lower()`, so *the environment
refusal satisfied it*: a guard inverted to refuse development would have printed
the environment refusal, the section matcher would have matched it, and both
checks would still have passed. `docs/MISTAKES.md` entry 3.

Fixed by taking the section's name out of that one sentence — it now says "one
section of the mock platform's world" — with the reason written at the line, so
nobody puts it back.

Proved by mutation afterwards, each applied to the committed file and reverted
with `git checkout`:

- environment guard inverted (`==` to `!=`): **both** checks red, which is the
  pair working. Before the fix, only the first was.
- environment guard removed entirely (an early `return None`): the first red on
  the traceback assertion — under `ENVIRONMENT=production` the run dies inside
  `Settings` validation, which is exactly the near miss the manifest predicted.

## 6. Where the runbook disagrees with the work order

The work order's decision 4 lists the steps as: launch at the real clock, pipe
the seeder, run the two Monday jobs, *then* move the pretended clock forward.
That order writes nothing. The section starts 2026-09-07 and its first window
closes 2026-09-13, so at the real clock no window of it has closed, and this
seeder — and `generate_weekly_summaries` after it — writes for closed weeks only.

The docstring's runbook puts the clock move ahead of the seeder and says in as
many words that this is a departure and why. The seeder refuses, naming the
effective clock and the repair, rather than exiting zero having written nothing.

## 7. The write path, executed once — worked

No test asserts the generated data, by the owner's ruling, so the write half
would otherwise ship unexecuted (`docs/MISTAKES.md` entry 9). Probed from a
throwaway script in the scratchpad, never committed: a Postgres of its own on the
image `docker-compose.yml` declares, the two non-superuser roles `scripts/db-init`
creates, `alembic upgrade head`, then `scripts/seed.py` imported and run with one
extra `DemoCourse("BIOL", "310", …)` and one extra `DemoSection("BIOL 310",
"R7FF")` appended to its own catalogs — so the section, its weeks and its windows
come from the real seeder rather than from hand-written rows. Twenty `user` rows
carrying the mock platform's subjects, their enrollments and a clock override at
2026-10-19 stand in for the launch and the roster sync.

The dev cluster could not be used for this: `.env`'s `DB_SUPERUSER_PASSWORD` no
longer authenticates against the running `db` container (the app role does), so
nothing host-side can create or migrate a database there. Worth knowing before
reaching for the dev stack for anything needing DDL.
