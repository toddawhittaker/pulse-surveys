## Attempt 3 — the mock provider learns the summary task (worked, in two commits)

**The constraint that decided the design, found by reading before writing.**

1. **Refactor, no behavior change.** `failing_answer` holds the three markers

   rules. Measured on both sides of the commit: 42 passed.
2. **Behavior.** Dispatch on the summary marker line, the week read as
   blank-line-separated blocks after its last occurrence, and the stream read

   nothing a student wrote can move it or choose the stream.

## Attempt 5 — the security round's overclaimed-theme bound (worked)

A LOW from the review, ruled worth fixing: `summarize_stream` filed a validated
answer whose theme claimed more comments than the week held. The bound existed in
two places and neither is on the path a real provider's answer takes — the offline
eval check `overclaimed_themes`, and the mock's own arithmetic about answers it
invents itself. A crafted comment forging `Comment N:` boundaries could inflate a
prevalence figure an instructor reads, and §4 hides the raw comments below the
n-threshold, so in exactly those weeks the count is all they get.

Red confirmed first: the task module at 1 failed / 8 passed, the failure being
`test_a_theme_claiming_more_comments_than_the_week_held_is_refused`.

The fix is four lines after the existing stream check: collect the counts greater
than `len(comments)` and raise `AIResponseInvalidError` if there are any. Three
things decided while writing it, none of them obvious from the finding:

1. **The message names the counts and never a theme's label.** Naming the
   offending theme would read as more helpful and is the one part of an answer
   that can carry a student's words — a label is model output written after
   reading a week of comments. The tests only look for the planted needle, so this
   is a discipline the suite does not force; the docstring says so out loud.
2. **Nothing is clamped.** Refusing the answer whole was chosen over adjusting the
   count to something plausible, which would put a figure in front of an
   instructor that neither the model gave nor the week supports, and do it
   silently. The acceptance test pins that by reading the label and count back off
   the record.
3. **The boundary is `>`, so exactly the week's length is kept.** A small section
   where every comment is about the same lab is the ordinary case, and `>=` would
   refuse it.

The test author also folded the exception-chain walk into a `chain_text` helper
shared with the earlier no-leak test; nothing on the implementation side had to
change for that.

**Proved by mutation rather than by reading**, since the acceptance half passes
against a task with no check at all: `>` changed to `>=` reds
`test_a_theme_claiming_exactly_the_weeks_comments_is_kept` and nothing else, and
the check deleted reds the refusal test and nothing else. Each mutation was
reverted by an edit rather than a checkout, with the module re-run green after.

ADR 0148 gains a fifth decision item and its index row a clause, because that
