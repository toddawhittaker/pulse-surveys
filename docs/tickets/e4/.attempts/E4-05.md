**The risk that had to be measured rather than assumed.**
`tests/unit/test_ai_contracts.py` finds a task's contract by matching a name
fragment — `summary` / `summar` — against the class names in the module, and a

no-identity-field — then runs against the record and reaches the audit pair
through `summary.prompt_version`.

`tests/unit/test_the_weekly_summary_contract.py` = **68 passed**. No dispute
needed and no rename required.

## Attempt 2 — the prompt, the renderer and the task (worked)

`backend/app/ai/prompts/summary.v1.md`, the six constants,
`render_comment_blocks`, `render_summary_prompt(version, *, stream, comments)`
and `summarize_stream(comments, *, stream, response_count, gateway=None)`.

Three things that had to be got right and were not obvious from the ticket:

1. The renderer's parameter *count* is asserted, not only its names — three
   parameters, two of them keyword-only. A fourth, even an optional one outside
   the settled list, reds `test_the_renderer_cannot_be_handed_identity_at_all`.
2. The empty week's model id is the gateway's `NOT_A_MODEL`, imported rather
   than made a seventh constant. `FLOOR_MODEL_ID` beside it is the same value
   under a name that means the character floor, and reusing that name would file
   empty weeks under §3.3's floor for any reader selecting on it.
3. The stream placeholder is substituted with `stream.value`, never the enum. A
   `repr` reads as a class name, and the mock reads this token back off the
   rendered prompt to decide which stream to answer about.

The renderer, task and eval-case demonstration modules: **24 passed**.
`gateway.py` was not touched and did not need to be — its `_payload_model`
derives what the endpoint is asked for from the contract minus the audit pair,
so the redefined output travelled with no gateway change (work order item 5).

## Attempt 3 — the mock provider learns the summary task (worked, in two commits)

**The constraint that decided the design, found by reading before writing.**
`tests/unit/test_mock_ai_rules.py::test_this_modules_copied_marker_vocabulary_is_
the_one_the_mock_serves` compares the served marker list against a hand-copy on
the test side, sorted and with multiplicity. **A new `mock-ai:` marker would red
it**, and that file is behind the test wall. So the summary task reuses the four
markers that exist rather than adding one, and the wrong-answer path the
round-trip's re-ask test drives is the existing `mock-ai:malformed`.

The same module's `test_the_served_rules_document_publishes_every_part_of_the_
vocabulary` says in as many words that it is not an equality against a key set,
so *adding* members to the served document is safe. `summary_marker_line`,
`summary_stream_line_prefix`, `streams` and `tasks` were added there.

Split into two commits, because the second needed a seam the first opened:

1. **Refactor, no behavior change.** `failing_answer` holds the three markers
   that answer instead of the task; `answer_for` becomes the one entry point and
   `app.main` decides nothing. The stall deliberately stayed inside `classify`:
   moving it into the shared helper would have changed what `mock-ai:stall`
   answers for a short comment (`substantive` late today, `insufficient` late
   after the move), because rule 1 runs before the forced-verdict and length
   rules. Measured on both sides of the commit: 42 passed.
2. **Behavior.** Dispatch on the summary marker line, the week read as
   blank-line-separated blocks after its last occurrence, and the stream read
   from `Stream under review:` in the instructions — before the marker, so
   nothing a student wrote can move it or choose the stream.

Every mock-ai suite: **49 passed**. The round-trip integration module: **5
passed**, which needed the localhost `DATABASE_URL` rewrite.

One thing worth knowing for E4-06: `mock-ai:stall` is six seconds and the summary
task's budget is sixty, so on this path the stall drives a *late summary* rather
than a timeout. Lengthening it to reach the timeout row would hold a test for a
minute for a row the validity task already reaches; both records now say so.
