Decisions taken while building, each recorded in the code that holds them:

1. **A collapsed flagged comment has no text in the DOM.** The prototype
   collapses by `max-height: 0`, which leaves the words readable to a screen
   reader while the screen says they are hidden. The body is rendered only when
   the disclosure is open, and the brief's 200ms height ease is a CSS animation
   on the revealed region rather than a transition on a permanently present one.
2. **`CommentGroup` is told whether it carries the small-N notice**
   (`smallN: { threshold, withNotice }`). §4.1 item 5 allows confidentiality
   copy once per surface and a suppressed week suppresses both of a report's
   groups, so the surface placing them is the only thing that can decide. The
   field is required rather than defaulted so the choice is made at the call
   site; E4-11 makes it.
3. **Suppression is fail-closed**: a suppressed group renders no card whatever
   its comment array holds, and the fixture hands it a full week so the empty
   card list means the suppression rather than an empty list.
4. **`AiPanel` says "Drawn from N responses"**, the ticket's criterion 5
   wording. The prototype passes its panel a `meta` string from the report page
   ("Generated from 18 responses"), so the sentence is not the prototype
   component's own; SPEC §5.1's requirement is that the count be stated.
5. **`heldNote` is rendered as ADR 0148's `held_note_type`** — §5.1's sentence
   "One comment is held for review (privacy)." rather than the raw value on its
   own. The sketch's field is `held_note` with a null example, so the reading is
   stated here; E4-11 resolves any divergence from E4-07's schema (README
   decision 5).
6. **The small-N notice states no responded/enrolled fraction.** The prototype's
   version writes "Only 3 of 9 students have responded"; the sketch's `small_n`
   member carries the threshold alone, the report already states both rates in
   its participation section, and adding two props nothing in this diff can fill
   would be guessing at E4-11's assembly.

## Attempt 2 — 2026-09-06, the security review's fix round

Two accepted findings, and nothing else touched. The stopping rule was declared
before the round: these two, one re-verification, the security pass re-run over
the fix diff alone.

**MEDIUM — the suppressed group leaked the summary's held note.** `CommentGroup`
passed `summary.heldNote` to `AiPanel` unconditionally while the card list
fail-closed under suppression, so a below-threshold week whose payload populated
the note rendered "One comment is held for review (privacy)." SPEC §5.2 conceals
flagged comments from the instructor entirely below the threshold — "no chip, no
count, no flag-type hint" — and §5.1 permits the note only above small-N, so the
sentence named the very thing the concealment withholds. The group now passes no
held note in the suppressed state: the same fail-closed move the cards make,
obeying the suppression the payload already declared rather than deciding a
threshold here.

Written test-first and watched red: with the old code, `Tests 1 failed | 27
passed (28)`, the failure being the rendered sentence (`expected <p
class="pulse-ai-panel__meta">…</p> to be null`) rather than a setup error. After
the change, `Tests 28 passed (28)`. The other direction is asserted in the same
round — an above-threshold group with the same populated note renders it, and
that test passes in both runs, which is what stops the concealment assertion
passing because nothing ever renders the note. The group's own docstring was
corrected in the same commit, since it claimed the suppression covered the cards
alone.
