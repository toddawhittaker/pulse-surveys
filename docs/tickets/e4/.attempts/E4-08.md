Decisions taken while building, each recorded for the pull request body:

- **The axis spans the weeks the payload carries, and no further.** The
  prototype's axis runs a section's whole length and labels the weeks ahead by
  adding an offset to the course week. That offset is precisely the arithmetic
  SPEC §2.2 and this ticket's known-trap forbid — the term week under an
  unpublished week is a number no server ever said — so the axis ends where the
  data does. This is a deliberate departure from
  `design/PulseTrendChart.dc.html` and the only one in the diff.
- **Axis text is drawn inside the SVG** rather than as absolutely positioned
  HTML beside it, which is how the prototype places it. The rendered result is
  the same mono labels in the same places; the DOM is simpler and the geometry
  is assertable.
- **Chart type takes the ramp's smallest step.** The prototype sets the week
  label at 12px and the term sub-label at 10px, and `design/tokens.css`
  publishes nothing below `--text-1` (13px). Both take that step and the
  sub-label is quieted by colour (mist against spruce-60) rather than by a size
  the token file does not publish.
- **The legend names one line and appears once.** `design/Usage Rules.md` §1
  hides the legend in the single-line variant, which is the student-visible
  case; the ticket's first criterion asks for one legend on the instructor's
  pair, so the pair carries one, on the lower panel, naming the section's own
  line. No comparison or university wording exists anywhere in the diff —
  E4 has no comparison data, and §4.1 item 1 is why none may be implied.

## Attempt 2 — 2026-09-06, the fix round

The independent security review accepted the build with two LOW findings, both
taken. The week-navigation question raised above was ruled on the sources — the
prototype, SPEC §5.1 and this breakdown's README all say paging — so the
control stands and nothing about it changed.

- **Finding 1: the copy module's header said where it sits, not what that
  costs.** It now says plainly that the collector reads `frontend/src/copy/`,
  that this file is not in it, and that the invariant-marked checks on §4.1
  items 4 and 5 therefore read none of these strings — they are held by review
  and by the header until E4-12 collects them, and E4-12 owns closing it.
- **Finding 2: the forbidden-reach guard missed the clock**, which is this
  ticket's headline trap, along with the page location, the navigator, an event
  stream, a socket, a dynamic import and the double-quoted spelling of the API
  import. All seven are added and every existing entry is kept.

Two hazards engineered around, both entry-3 shapes:

- **`Date` is matched by usage rather than by name** — `new Date`, `Date.` and
  `Date(` — because `PulseTrendChart.tsx` documents that it constructs none, and
  a scan for the bare word would red on that sentence and drive the
  documentation off the file. Stripping comments before scanning was the
  alternative and is rejected in the test's own comment: a stripper is code that
  can be wrong about a `//` inside a string, and being wrong there hides the
  rest of a line rather than reporting it. The gap this leaves — the clock
  reached through an alias or through `globalThis` — is stated in the same
  place. One line of `PulseTrendChart.tsx`'s docstring was reworded so the
  sentence claims exactly what the guard proves; no behaviour changed.
- **Every entry carries a line that reaches that way**, and the test refuses any
  entry its own sample does not catch, so an entry that matches nothing cannot
  join the list quietly. Three lines copied whole out of the sources — the
  sentence about the clock among them — are asserted to stay allowed.

reddened and named that rule; each plant was checked to have landed before the
