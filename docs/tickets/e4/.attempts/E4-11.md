### Decisions taken while building, each recorded where it is held

1. **`comparison` is not on the client's types at all.** Breakdown decision 10
   says the page never reads it; a type with no member for it is the structural
   version of that rule, the same move `CommentCard` makes by having no prop
   for a timestamp. The fixtures carry the member so "renders no comparison" is
   a fact about a payload that had one.
2. **The section list's outcome type has three members, not four.**
   `app.api.instructor` says in as many words that the list "has no refusal of
   either kind, and that is not an omission" — a `not-found` variant would be a
   branch nothing can reach.
3. **One error state, carrying the API's sentence.** A 404 on an unpublished
   week and a 404 on somebody else's section both land there; criterion 6's
   not-found treatment is that state showing "There is no report for that week
   of this section."
4. **A `null` week search parameter is written on every validate.** A route's
   validated search is merged *over* the raw search, so a validator that
   refuses a value by omitting the member leaves the raw one standing —
   `?week=banana` reached the page as the string and the page asked the API for
   a report on week "banana". Measured, not supposed; four addresses hold the
   repair.
5. **Loading is derived, not stored.** The page holds `{to, load}` and shows
   loading whenever the address it was read for is not the address on screen,
   so there is no render in which last week's report sits under this week's
   heading — and no `setState` at the top of an effect, which the React hooks
   lint refuses.
6. **Both instructor routes carry `pulse-landing-instructor`.** Nine end-to-end
   specs assert it to say a launch landed, and an instructor who teaches one
   section never sees the dispatcher.
7. **An unrecognised comment status renders as the plain card.** The vocabulary
   is §5.2's three states and the service produces no fourth; drawing an
   unknown one flagged or excluded would put a verdict on a student's words
   that nothing recorded, and dropping it would take a comment off the report
   silently.
8. **The no-published-weeks state reads the section list to name its section.**
   One extra request, in the one state that has nothing else to say.

### Three defects found by running, each fixed in the commit that names it

- **The roster sync stamps `started_on` from the effective now and never
  rewrites it.** The first version of the e2e moved the clock before the staff
  launches, following `support/survey.ts`'s ordering, and left all twenty-four
  enrollment rows dated 2026-10-02 — after which `exit-weekly-survey`,
  `lti-launch`, `student-survey` and two specs beside it failed with a learner
  the door refused, none of them pointing anywhere near this file. The staff
  launches now run at the real clock and a tripwire in the hook asserts no
  enrollment carries a future start date. The dev database had to be rebuilt
  (`make down && make up && make migrate && make seed`) because nothing may
  repair those rows.
- **Provisioning `NURS-8100-Q2FF` collides with two student-survey specs.**
  It starts on 28 September, so a week of it can only be answered in October —
  and its week-1 window is open at `2026-10-02T19:00`, which is the minute
  `student-survey-accessibility.spec.ts` and `student-survey.spec.ts` pretend
  it is, both written against a screen with one section on it. The small-N
  section is `MATH-140-E1FF` instead, which ended on 26 September.
- **Shipping the report's component stylesheets reordered Tailwind's layers.**
  Vite emits stylesheets in module-graph order, `main.tsx` imported the router
  before `styles.css`, and the application's own `@layer components` block was
  then declared before Tailwind's `base` — so preflight won and every heading
  on the student survey rendered at body size (16px against `--text-3`'s 20px),
  which `student-survey-heading-and-next-window.spec.ts` measured. `styles.css`
  is imported first now. E4-08 recorded the precondition without knowing it was
  one: "the bundler drops their CSS from `dist` today; E4-11's import is what
  ships it."

### The fixture correction the coordinator added mid-build

E4-19's security round found that E4-08's component fixtures encode payloads the
server cannot emit: the backend derives a section's term week from its course
week with one per-section constant, so `termWeek - courseWeek` is the same for
every point in one report, and `PulseTrendChart.test.tsx` and
`TrendPair.test.tsx` held a break week (course week 3 at term week 10 beside
pairs at +6). Every pair now holds one offset, six, and the assertions naming
term week 10 name nine. This page's own fixtures held the property already and
now say so. No component behaviour changed.
