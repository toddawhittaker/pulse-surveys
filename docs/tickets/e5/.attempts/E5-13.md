## 2026-09-14 — reading the wall before designing the copy module

**Saved the change from being written twice.** The settled shape was "the eight
constants become `CopyEntry` values". Before writing it, grepped for every
reader of those names and found `tests/fixtures/named_sets.py:479`
(`refusal_sentence`), which E5-06's seven integration modules ask for every
expected refusal body. It walks `app.copy`'s modules for an attribute of that
name, keeps only values that are `isinstance(value, str)`, and fails if none of
the homes it finds is under `app.copy`. Turning the eight public constants into
entries would therefore have left the copy package with no string of those names
and reddened seven integration modules inside their own fixture — a red nowhere
near the change, in suites this ticket never names.

So the shape is: a private `CopyEntry` per refusal holding the words, a public
constant of the existing name holding that entry's own `text`, and `COPY` built
from the entries. The registry gains the eight governed keys, the texts are
unchanged, the application goes on importing a sentence by name, and the two
cannot drift because the constant *is* the entry's text. Verified the texts are
byte-identical to the shipped ones by importing the old file beside the new one
and comparing all eight.

Consumers (`app/api/deps.py`, `app/api/leadership.py`,
`app/services/comparison_sets.py`) therefore needed no change at all:
`served_text` in the test reads `.text` when there is one and the object itself
when it is already a string, so all three modules' constants compare equal to
their entries. `app.api.deps.NOT_LEADERSHIP`, the one constant the test demands
by name, is the imported string.

## 2026-09-15 — the ruling, and the half of it that is the implementation's

The objection was ruled on sources, both ways, and neither side was wholly
right. The full text is at the bottom of `docs/disputes/E5-13-01.md`.

**What the objection got wrong.** "No student can reach any of the eight" is
false for the first one. `app.api.deps.require_leadership` answers
`leadership_comparison_sets.not_leadership` to *any* session that is not a
leadership session, which includes a student's, and that sentence began
"Comparison sets are defined by leadership". SPEC §4.1 item 1 forbids exactly
that vocabulary in anything a student reads, so the sweep was right to red on
it. The other seven are behind the gate and a student cannot be served them.

**What the sweep got wrong.** Its mechanism — every entry in the registry — was
a faithful proxy for "what a student reads" only while every entry was a
student's. It is the closed-set guard of `docs/MISTAKES.md` entry 53 one level
out: what encloses the set is who can be served the string.

**Decision 1, mine. Worked.** `leadership_comparison_sets.not_leadership` now
reads "This request does not carry a leadership session." and names nothing on
the other side of the gate. The comment above it still argues one sentence for
the absent, malformed, expired, foreign and wrong-role session alike, and that
argument never needed the words it lost; a line was added saying why this one
refusal of the eight carries no comparison-set vocabulary. Nothing else in the
repository quoted the old sentence — checked with
`grep -rn "Comparison sets are defined by leadership"` over `*.py`, `*.ts`,
`*.tsx` and `*.md`, one hit, the definition itself. The sentence the
placeholder-era prose sweep quotes as a sample it must leave alone is
`SET_UNAVAILABLE`, not this one, so the reword did not touch it. E5-06's seven
integration modules read every expected refusal through
`tests/fixtures/named_sets.py`, which resolves the sentence from `app.copy` by
constant name rather than by literal, so they follow the reword:
`pytest tests/integration -k "comparison_set or named_set or leadership" -n 4`
came back **183 passed**.

**Decision 2 is the test author's** — the exemption by key, in ADR 0158's
small-N shape. Not mine to write and not written here.

**Decision 3, mine. Worked.** ADR **0177**, four sections: the sweep exempts by
key, not by surface, because the surface has one key a student can be served and
that key stays inside the sweep. Rejected alternatives are the three the ruling
names — exempting the prefix, rewording all eight, and an audience field on
`CopyEntry` that its two-field pin refuses. The consequence written down is the
standing one: a refusal in the tuple that later becomes student-reachable has to
leave the tuple in the same change, and the coverage given up is seven sentences
no student can be served. `docs/adr/README.md` gains its row.

**The sweep for what the ruling falsified** found three live claims, all
corrected in the same commit: ADR 0176's last paragraph and its README row both
said the item 1 sweep was red on this branch pending a ruling, and the deferred
entry this ticket closed said the eight texts were unchanged, which is true of
seven of them now.

**One thing to do differently.** The records commit was made with `git add -A`
in a checkout where the test author was working, and it swept their in-progress
exemption-tuple module into my commit. Their content was neither read for the
commit nor edited, and the commit message now says so, but the paths should have
been named. Stage by path in a shared checkout.
