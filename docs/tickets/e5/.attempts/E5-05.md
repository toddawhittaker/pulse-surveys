## 2026-09-14 — where the new schema models had to live, and why not in report.py

**Worked, after the first plan failed on a reading of the tests.** The work
order names five classes, two of which — `StreamBenchmark` and
`WorkloadBenchmarkView` — declare a member called `comparison`. So does
`InstructorReport`. E4-07 settled that the sealed comparison type is *found*
rather than named: `tests/fixtures/report_api.py::comparison_field_type` and
`tests/fixtures/report_benchmarks.py::report_payload_model` both walk
`vars(app.schemas.report)` for the one model carrying a `comparison` member and
`pytest.fail` if there is not exactly one. Declaring the new classes in
`app/schemas/report.py` would make that three, which reds E4-07's whole module
as well as this ticket's.

So the five models are in `backend/app/schemas/report_benchmark.py`, and
`report.py` does `from app.schemas import report_benchmark` — the module, never
the classes, because `from … import StreamBenchmark` would put the type straight
back into `vars(app.schemas.report)`. ADR 0170 records it; both modules carry the
reason in prose, because it is exactly the kind of odd-looking import somebody
tidies.

## 2026-09-14 — the revalidation has to be on every model on the path, not only on the holders

**Measured rather than assumed.** The work order asks for
`revalidate_instances="always"` on "every class holding a `ComparisonFigure`".
That is necessary and not sufficient: pydantic's `revalidate_instances` is
configured on the *nested* model and decides whether an instance of it is
re-validated when it appears as a field value. A three-level probe confirmed it —
with the middle model at the default `never`, the leaf's field validator never
ran and a `model_construct`-built value passed straight through.

So `StreamsView` and `StreamReport` gain the same config. Without them the seal
on `streams.<stream>.benchmark.comparison.points[].mean` is one a caller walks
past by building a *stream* with `model_construct`, which is E4-07's defeat one
level out at a new depth.

## 2026-09-14 — the assembly, and a first pass that failed on ordering

`_benchmark_members` sits beside `_payload` and does six reads of
`app.services.benchmarks`: `benchmark_trend` per panel per population, and
`benchmark_workload` per population at the reported course week. Two tiny
converters turn the service's dataclasses into the payload models. Nothing in
any of them counts or averages.

The first version put the call *after* the `streams` comprehension that consumes
it: `UnboundLocalError: cannot access local variable 'benchmarks_by_stream'`, on
every integration test. Moved above the comprehension; 15 of the 20 integration
tests went green immediately.

## 2026-09-14 — `docs/disputes/E5-05-01.md`: the smuggling module re-validates a served payload

**Stopped on this item; three tests left red.**
`test_every_benchmark_member_refuses_an_unsealed_figure.py` reaches the payload
through `drive_one_member`, which does `model.model_validate(body)` over the
serialized body the route just served. Once a benchmark figure is *shown*, that
call raises: a figure rebuilt from a mapping carries no seal, and
`refuse_an_unsealed_comparison` admits an unsealed value only when it is
suppressed and empty. It is a property of any implementation meeting criterion 1,
not of this one, and E4-07's own module does the same thing and is green only
because its world has no comparison set.

I proved the property the module is *about* separately, by hand: a report built
from chokepoint-sealed figures validates and serializes (control), and the same
report with one member rewritten to an unsealed `model_construct` figure is
refused at each of the three members, with the refusal's `loc` naming the
member. The objection carries the evidence and a repair that keeps the module's
intent.

## 2026-09-14 — `docs/disputes/E5-05-02.md`: the university control is false for the course panel

**Stopped on this item; two parametrizations left red.** The `[COURSE]` halves of
the two minimum tests assert a control — the university line at the near-miss
week is shown "over the same rows plus the hero" — that the world does not have.
`tests/fixtures/report_api.py` writes a course rating only in `FULL_WEEK`, which
is course week 1, and this ticket's world plants into weeks 2 to 5. So the hero
contributes no course-stream respondents and no course-stream section at weeks 3
and 4, and the university course line is suppressed there exactly as the
comparison one is. The `[INSTRUCTOR]` halves pass, and so does every other
assertion in both tests.

The only implementations that would show that figure seal a rating mean with
counts that are not the rating's own — the defect E5-04's security round removed.
