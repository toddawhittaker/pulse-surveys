## 2026-09-13 — the eight SQL files, the migration and the two wrappers

Worked. What it turned on:

- **Course week is derived per section, in SQL**, as the term week the response
  hangs on less the whole weeks between the section's own start date and its
  term's: `week.number - floor((section.start_date - term.start_date) / 7)`.
  `floor` rather than integer division, so a section that somehow began before
  its term does not truncate towards zero and land a week out. The property
  test draws all twenty seeded cohorts and passes.
- **The workload-and-counts pair is built over `response` with the hours joined
  on the left.** Built the other way — over the workload answers — every other
  test in the ticket still passes and a cohort week whose responses carry no
  hours disappears with its three true counts. Both null-workload tests catch
  exactly that.
- **`level` is exposed as the stored enum, not cast to text.** Measured first:
  psycopg sends a Python `str` in a way Postgres resolves against the enum, so
  the tests' `level = :level` filter works. Probed on the running server before
  writing any SQL, because the failure mode is an operator-does-not-exist error
  that reads as a broken test.
- **A new NOLOGIN role `pulse_benchmark_definer`** owns both functions, with
  column-grain `SELECT` on the six relations the two bodies name and nothing
  else. Its grants stay disjoint from `pulse_resolve_definer`'s, which is the
  reason the reuse was refused. The grants are exercised by every test that
  calls a function, because a `SECURITY DEFINER` body runs as its owner whoever
  calls it.
- **No validity filter.** Neither `report_rating_distribution` nor
  `report_workload` filters `response.is_valid`, and nothing in this ticket asks
  for one; making the benchmark disagree with the section's own figures would be
  a decision nobody has taken. Recorded in `docs/tickets/e5/deferred.md` for
  E5-04, which owns the policy.
