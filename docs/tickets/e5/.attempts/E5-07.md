## Attempt 3 — 2026-09-13, the security review's LOW

**The finding.** `drawnPoints` read `series.suppressed` for truthiness and the
notice was gated on `=== true`. The client casts the report JSON into its
TypeScript shapes without a runtime parse, so a `suppressed` that arrived
renamed, missing or null would be falsy: the series would be **drawn**, and
because the notice asked a different question it would be drawn silently. A
payload slip in this field resolved to "show the figure", which is the wrong
direction for SPEC §4.1 item 7 to fail in. The file already defended the
opposite direction — a suppressed member arriving with points is emptied — and
this closes the matching one.

**The fix, as ruled.** One function, `isSuppressed`, and one reading: a series
is drawn only if its flag is exactly `false`. The line, the legend entry, the
table and the notice are now all decided by that one question asked one way, so
there is no gap between them for a malformed flag to fall into — a series that
draws no line always says why. The notices carry no reason token, so there was
nothing to make generic. The cost is written into the function's docstring: a
payload that stopped sending the flag shows notices everywhere rather than
lines, which is loud and withholds nothing a reader was entitled to.

`TrendPair` gates nothing — it hands each panel its stream's two members and the
panel decides — so it needed no change, and a test now proves the pass-through
does not undo the panel's reading.

**The boundary the fix must not cross, held by its own test.** A *malformed
member* is still a member: the payload said something about the series and the
chart could not read it, so it says so. An *absent prop* said nothing at all —
§4.1 item 1's case — and still renders exactly the E4 chart, no notice, no node.

**Six tests added** (three malformed shapes: dropped flag, null, the string
`'false'`; the exactly-`false` near miss; the absent-versus-malformed boundary;
the pair pass-through). Three mutations, each proven to land:
