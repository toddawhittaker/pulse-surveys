## 2026-09-13 — the red tests, and two things the work order could not settle

Wrote the failing tests for all eight acceptance criteria, the definer-reach
test the deferred file asks for, the rewrite of the comparison-set grant module
and the two `RUNTIME_BASE_TABLE_PRIVILEGES` entries. What the writing turned up:

- **The definer equality cannot be a `(relation, column)` equality yet, and the
  reason is a missing record rather than a missing test.** The work order asks
  for `BENCHMARK_DEFINER_PRIVILEGES` "transcribed from
  `backend/app/views_sql/benchmark_definer_v001.sql`'s six GRANT lines". A
  constant transcribed from the SQL it polices asserts that the SQL equals
  itself, which is `docs/MISTAKES.md` entry 19 and which
  `test_each_definer_holds_exactly_the_column_privileges_its_job_needs` refuses
  in its own docstring: "the expected sets are derived from the records' own
  sentences rather than copied from the migration". The records that could
  supply the columns do not — ADR 0165, E5-03's attempts log and
  `docs/tickets/e5/deferred.md` all stop at the six *relations*. So the test
  asserts every grain the records do settle (the six relations as an equality in
  both directions, `SELECT` and no other verb, no column of `user`,
  `user_identity` or `person`, and nothing held at the grain of a whole
  relation, which ADR 0165 rejects by name) and says in its own docstring that
  the column equality is owed. **The answer is a record rather than a narrowed
  deferral.** ADR 0165 is the definer's own record and gains a sentence naming
  the exact `(relation, column)` `SELECT` pairs — a claim a reviewer can weigh in
  this pull request, with the SQL never entering a test. The equality then
  extends to column grain derived from that sentence, in the sibling test's
  shape, and the deferred entry closes in full. The test as written is the red
  run's version; the column grain lands on top of it in this same ticket.

  **Done, 2026-09-14.** The amendment is at the head of ADR 0165 and names
  eighteen `(relation, column)` pairs over six relations.
  `BENCHMARK_DEFINER_PRIVILEGES` is transcribed from that list; the six
  relations are derived from the eighteen pairs rather than written a second
  time; the equality runs in both directions. The three narrower assertions run
  before it — the relations, the verb, and the absence of any `user`,
  `user_identity` or `person` column — because each fails with a sentence rather
  than with a diff of eighteen tuples. The whole-relation assertion runs after
  it, because it is the one thing the equality cannot say:
  `has_column_privilege` answers true for every column of a table granted whole,
  so a table-wide grant would satisfy the equality on the eighteen and carry
  every other column silently. The test is now
  `test_the_benchmark_definer_holds_exactly_the_columns_its_two_counting_bodies_read`,
  and nothing in it reads `benchmark_definer_v001.sql`.
- **The work order and the wave brief disagree about a migration.** The work

  `backend/app/views_sql/comparison_set_grants_v001.sql` and "a new migration off

  add one … E5-02, E5-04, E5-08 must add NO migration". The tests are written to
  the work order, because the ticket's own scope names the grant ("the first read

  `RUNTIME_BASE_TABLE_PRIVILEGES` entries stay red until that revision exists,

  same day: the work order governs.** This ticket ships the grants file and a

  written.

## 2026-09-13 — the service, and why it does not import `views_sql/queries.py`

The red run reproduced first: the four planter controls, the provenance-check
control, the six write refusals and the definer relation-grain test are green on
the tree as it stands, and 21 assertions are red — the eighteen service tests
(five suppression, six population, seven provenance parameters), the two
`SELECT` grant parameters and the `RUNTIME_BASE_TABLE_PRIVILEGES` equality. That
is the manifest's twenty rows counted by parameter rather than by row.

`backend/app/services/benchmarks.py` turned all eighteen service tests green on
its first run. What it took to write:

- **The service cannot import `app.views_sql.queries`, and E5-03's comment on
  that module says the opposite.** That comment reads "Written here rather than
  in the service that will call them so that E5-04 has no reason to spell a
  statement of its own — which is the state
  `test_the_org_views_are_read_only_through_the_grant.py` exists to prevent".
  The sweep's import half does the reverse: it excuses exactly one importer of
  that module, `backend/app/services/authz.py`, and reds every other module
  under `backend/app/` that imports it, by name or relatively. So importing the
  two typed wrappers would have turned a green gate red, and moving them out of
  `queries.py` is not open either — E5-03's own suite reads them there by name.
  The two statements are therefore spelled in `benchmarks.py`, which is the
  route `backend/app/api/dev.py` already takes for `section_enrollment_count`
  and says so in its own comment. Neither set function is a relation that sweep
  polices — the inventory is parsed from `CREATE VIEW` bodies and both are
  functions — so no exemption is involved and the sweep is green. The
  duplication of two statements is real and is recorded in
  `docs/tickets/e5/deferred.md`; the false sentence in `queries.py` is corrected
  in this pull request's records commit.
- **Everything else is read through SQLAlchemy Core**, because `section`,
  `course`, `lead_faculty_course` and the four cohort views *are* in that
  sweep's policed inventory and a statement naming one in SQL text would be an
  offender. `app.services.reporting` reads the report views the same way.
- **The counts a rating figure is suppressed against come from the workload row
  for the same week.** `benchmark_set_rating_week` answers `rating_count`, which
  counts ratings rather than people, so neither minimum can be compared against
  it; `benchmark_set_week` is where `section_count` and the distinct count of
  people live. Both functions are called for a trend.
- **The empty section list is answered without a round trip.** An empty Python
  list gives the driver no element type to infer for the `uuid[]` argument, and
  the error that produces would read as a defect in the function — which is the
  reason the benchmark world fixture gives for keeping the empty call out of its
  own helper. No sections means no rows, which is a suppressed figure at every
  call site.
- **A section with no lead, and a section id that names nothing, resolve to no
  sections rather than raising.** No criterion covers either; both withhold a
  figure rather than failing a report on an input the caller read out of the
  same database, and both are stated in the resolvers' docstrings.
- **`named_set_term_axis` answers the cohort the set declares rather than its
  member courses.** The term-axis views are keyed by `(length, level, term,
  start date)` and hold no course, so there is no way to narrow one to a
  membership list. Stated in the function's docstring and in ADR 0166 rather
  than left for E5-06 to discover.

## 2026-09-14 — the fix round's red tests: a figure is sealed against its own contributors

The security review found two HIGHs with one root cause, and the cause is
`docs/MISTAKES.md` entry 50's class: a figure sealed against a count of
something other than what the figure is about. A rating point took the week's
overall section and respondent counts, though its mean comes from the per-stream
read; the workload mean and median took the same counts, though they are
computed only over the responses that carry hours — which ADR 0165's
null-figure decision makes a deliberate subset. The term axis carried it a third

`tests/integration/test_a_benchmark_figure_is_sealed_against_its_own_contributors.py`:
each stream's point where its own stream spans too few sections and where too
few people answered it; the workload pair where too few people reported hours

holding two start cohorts so that the control is a figure in the same answer;
and two that must stay green — the hours world with one `workload=` value
changed, standing at exactly both minimums, and the world where nothing diverges
at all. Those last two are the guard against the cheap fix, which is to seal
every figure against the smallest count in sight and empty half the report.

Nothing binds to a column name. Every world's *overall* counts clear both
minimums and one figure's contributors fall one short in exactly one currency,
so a test says which count was used; every control stands **at** a minimum
rather than above it, which is where the boundary pair lives.

One thing the mutation battery asked for and this pass folded in: the provenance
world planted one hours value for everybody, so the cohort's mean and median
were the same number and a mutation serving one of them twice was undetectable
by construction. Two thirds now report the low value and a third the high one,
which puts the median on the majority value and the mean above it. The
all-pass test asserts both numbers and asserts that they differ, so the
arithmetic cannot quietly collapse again.

`test_the_comparison_member_is_reachable_only_through_the_suppression_helper.py`
is in that set deliberately: E5-04 is a caller of the chokepoint it polices, and

## 2026-09-14 — the security fix round: a figure's own contributors

The review's two HIGHs are one defect: a figure was sealed against a count of a
population other than the one it aggregates. The red module reproduced exactly
as briefed — five failed (the two rating currencies, the two workload
currencies, the term axis), two passed (the two over-suppression guards) — and
the provenance module was green beside it.

**Two premises the brief rested on turned out to be false, and both were
measured rather than argued.**

- **`CREATE OR REPLACE FUNCTION` cannot add an `OUT` column.** Two more columns
  in a `RETURNS TABLE` is a changed return type and Postgres answers `cannot
  change return type of existing function` (42P13). Probed against the migrated
  database as the migration identity, inside a transaction that was rolled back.
  So each `_v002.sql` drops its own function first and re-issues the owner, the
  `REVOKE` and the `EXECUTE` grant, because a dropped function takes its ACL
  with it. The downgrade drops and restores the `_v001` bodies for the same
  reason in the other direction — fewer columns is also a changed return type.
- **The term-axis view cannot be widened from this branch.** Applying the
  prescribed two columns to `benchmark_cohort_term_axis` and then evaluating
  what the guards read: the surplus against the view contract is exactly
  `['workload_respondent_count', 'workload_section_count']`, so the column-list
  equality goes red; and `pulse_app` gains those same two column privileges, so
  the readable-column equality goes red too. Both expected sets live under
  `tests/`. Rolled back; the view is untouched. The other two routes are blocked
  the same way — a third definer function needs a ninth name in the executable
  inventory, and computing the axis from the set's own sections would reverse an
  alternative ADR 0166 rejected three commits ago. Written up in
  `docs/disputes/E5-04-01.md` with the measurements and the two options; that one
  test stays red and nothing was worked around to hide it.

**What the fix is.** `benchmark_set_week` gains `workload_respondent_count` and
`workload_section_count` (a `FILTER` on the hours being present, since ADR 0165
keeps the row when they are not) and `benchmark_set_rating_week` gains
`rating_respondent_count` and `rating_section_count` (no `FILTER` needed — the
grouping is already per stream). The service's `_sealed` now takes one
`_Contributors` rather than two loose integers, so the pair is read off the same
row as the number it describes and a caller cannot supply a count it merely had
to hand. The week's overall counts stay on both functions and this module selects
neither.

**What was checked beyond the tests.** The definer's column grants are unchanged
across the migration — eighteen pairs, `SELECT` only, equal to ADR 0165's
amendment — which is the claim the brief asked to be asserted rather than
assumed. The migration round-trips: down restores the six-column and four-column
shapes with owner, `SECURITY DEFINER` and the application's `EXECUTE` intact, up
restores the eight and the six. E5-03's own contract suites stay green, because
the functions' column lists are a floor there rather than an equality — unlike
the views', which is exactly the asymmetry that blocks the term axis.

  and nothing else; the previous full run passed 3585, so the fix added six

- The §4.1 invariant pass alone: **395 ran, 394 passed, 1 failed** — the same
  test, which is `invariant`-marked because it asserts item 7. Nothing skipped,

- `ruff check .` and `ruff format --check .`: clean, 511 files.
- `mypy` as CI scopes it: no issues in 90 source files.
- `alembic check` clean and `alembic upgrade head` applied; the revision walked
  down and back up with the function shapes, owner, `SECURITY DEFINER` and the
  application's `EXECUTE` verified at both ends.
- The eight touched integration modules with `.env` moved aside: **100 passed, 1
