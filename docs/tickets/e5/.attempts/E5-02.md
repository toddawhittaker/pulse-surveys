## 2026-09-13 — one thing the ticket leaves open, and how the tests avoid deciding it

Work-order decision 3 settles the *member* and leaves its **source column**
conditional: "`Question.name` … verify against the survey component before
trusting; if the survey renders `prompt`, serve `prompt`." Nothing in the
repository's fixtures names a question's text column, so a fixture that planted
into one of the two would have answered an open interface question on the
implementer's behalf — the thing `tests/fixtures/report_views.py` refuses to do
for the validity service's signature.

So `tests/fixtures/report_question_text.py` plants the same wording into **every**
free-text column the `question` table carries out of a named candidate set, and
the tests assert served-equals-planted. Either choice of column passes; a table
carrying none of the candidates is a failure naming them rather than a silent
skip. The verification the work order asks for — which column the student survey
actually renders — is still owed, and it is the implementer's to make.

## 2026-09-13 — the first red run found a selector defect in two of the tests

Both tests that read the week model bound it by a field the model carries — "the
one model declaring `course_week`" — and two models declare it: the week member's
and `TrendPoint`, which carries the course week of the point it plots. So both
failed inside the selector rather than on their assertion, which is a red that
survives the implementation landing and proves nothing (`docs/MISTAKES.md` entry
44 is the general case).

Repaired by binding the model through the payload's own `week` annotation
(`model_behind_member`, in both modules): the schema itself says which model that
member is, in one place, and goes on saying it when a third model grows a
`course_week` of its own. A discovery asking "which model has this field" is
unique only by accident; asking the containing model is unique by construction.

Everything else in that run matched the written predictions: fifteen behavioural
reds, both must-be-green controls green, and the mockup canary finding its three

## 2026-09-13 — the implementation, and the text column settled

The red run reproduced exactly: fifteen behavioural failures across the four
modules the manifest names, both controls green, the mockup canary finding its
three copied-whole lines. Nothing disputed.

**Which column the student survey renders, verified.** The work order left this
conditional — "`Question.name` … verify against the survey component before
trusting; if the survey renders `prompt`, serve `prompt`" — and the survey renders
`prompt`. The chain is: `StudentWeeklySurvey.tsx`'s `QuestionField` draws a
`likert` question with `LikertInput`, and `LikertInput.tsx` renders
`<legend>{question.prompt}</legend>`. So `prompt` is the string the person who
answered actually read, and that is what the report serves. `name` is SPEC §3.2's
bold heading ("Instructor rating"), which no student sees; it stands in only where
a question carries no prompt, because the column is nullable and a report is not
the place to discover that. Where neither column holds anything for a stream in
any set, the read raises rather than serving a blank title, the way
`app.services.submissions.current_questions` refuses a deployment with no set.

**The read.** `_served_question_texts` in `app/services/reporting.py`, two small
statements: the rating questions the week's own responses answered, and the
newest set's rating questions for the fallback. Both are reduced by the same
"newest version wins" helper, which is also what makes a mixed-version week serve
the newest *answered* version. ADR 0168 records it, with a dated in-force table as
the rejected alternative.

**One collateral red, in a guard rather than in the ticket's own modules.** The
whole-suite run reported one failure the four named modules could not:
`test_nothing_the_test_suite_opens_by_path_is_classified_inert` found
`design/InstructorMondayReport.dc.html` read by the close-instant test and
classified inert, so a re-cut of that canvas would skip the suite that checks the
payload still feeds it. That test names its own repair — "exclude the file from
the inert set, not stop the test reading it" — so the file joins
`PARSED_DOCUMENTS` in `scripts/ci/classify_changed_paths.py`, the fourth entry to
move and the second to move for the sweep's reason rather than for a build input.
`scripts/ci/test_ci_scripts.py` stays green: its inert case names
`design/CommentCard.dc.html`, a different canvas.

The lesson is one `docs/MISTAKES.md` already carries: running only the ticket's
own modules would have shipped this red. No new entry proposed — a test module
that reads a repository document reds this guard by construction, and the guard
says so in its own failure message.

**The rendering half.** `RatingHistogram` gains `questionText?`, quoting the
served string through a new `instructor_report_page.histogram_question_title` key
and keeping the stream label both in the absent path and in the spoken reading.
`WeekEyebrow` gains a second prop pair, `closedAt` and `timeZone`, rendering the
past-tense note with `Intl` and the explicit zone; the student `closesAt` path and
its tests are untouched. Each half has a component test file of its own beside the
component, so `RatingHistogram.test.tsx` and `WeekEyebrow.test.tsx` did not
change. `A_WEEK_NOBODY_ANSWERED` replaces both the `week` and the `streams`
objects outright, so it carries none of the three new members and is criterion 5's
absent-path fixture with no extra machinery.

**The frontend test files had to be written through the shell.** The test-edit
hook exempts `frontend/src/*.test.tsx` — those files are the implementer's, since
the test author may not enter `frontend/src/` at all — but it computes the
repository-relative path by stripping `CLAUDE_PROJECT_DIR`, which in a worktree
build points at the main checkout. The strip therefore fails, the path stays
absolute, the exemption does not match, and the suffix rule blocks the write. The
hook's shell branch has no suffix counterpart — its own comment says it "never
covered these files" — so a heredoc lands them. Recorded rather than worked around
quietly: the block is a path-normalisation artifact of building in a worktree,
not a rule about who may write these files.

**Proposed MISTAKES entry, for the orchestrator to number if it agrees.** The
test-edit hook's frontend-component-test exemption does not fire in a parallel
worktree, because it normalises paths against `CLAUDE_PROJECT_DIR` (the main
checkout) rather than against the worktree root. Consequence: an implementer
following the work order is refused the files the work order assigns it, and the
cheap reading — "these tests must not be mine after all" — silently drops criteria
the ticket is graded on. Rule: when a hook refuses a file the work order
explicitly assigns you, read the hook before believing the refusal. A
`git rev-parse --show-toplevel` fallback in that hook would fix it for every
worktree build.

## 2026-09-14 — the battery found a survivor, and the near-miss twin that kills it

Hard-coding `institution_timezone="America/New_York"` in the read survived the
whole suite. The timezone test derived its expectation from `Settings()`, and this
repository configures exactly `America/New_York` in `.env.example` and in `.env` —
so the planted value and the read value coincided, and the assertion was true of a
payload that had read nothing. Hard-coding `UTC` was killed; only the
matching-default hard-code slipped.

The repair is the pair FIX-01 already built for the same member one payload over.
`test_the_payload_names_a_configured_zone_that_is_not_the_documented_default`
builds the door with `INSTITUTION_TIMEZONE` set to
`A_NON_DEFAULT_INSTITUTION_TIMEZONE` (`Pacific/Honolulu`, imported from
`tests/fixtures/student_read.py` so the two suites cannot drift into two answers
about what "not the default" means, and daylight-saving-free so a green cannot be
a coincidence of offsets). The existing test stays as the default-configuration
half and its docstring now says what it cannot catch alone.

`report_door_as` gained the environment keyword arguments that make this possible,
in the shape `student_read_door_in` already had: the value has to be named before
the application is imported, so it comes down through `launch_driver_in` rather
than through a monkeypatched environment the built application would never see
(`docs/MISTAKES.md` entry 40). Called with no keyword arguments the factory builds
exactly what it built before, so no existing module changes.

The general lesson, for whoever writes the next test of this shape: an expectation
derived from configuration tests the read only where the configuration differs
from what the code might plausibly hard-code. Against a documented default it
tests nothing, and it looks identical to a test that does.
