## 2. Where the refusal sentences may live (2026-09-14)

Worked, after one measurement. The named-set fixture's `refusal_sentence`
requires each sentence to be a plain `str` attribute of a module under
`app.copy`, and the submit fixture's `copy_texts` requires every module in that
package to publish a `COPY` mapping. Publishing the eight sentences as entries
under a `leadership_sets.` prefix was measured against the shipped-copy
inventory and is red: no row in its governance map claims that prefix, and an
ungoverned prefix is a body of strings SPEC §4.1 items 4 and 5 are checked over
by nothing. The same probe with an empty `COPY` is green there and on the
submit-path copy module.

So `backend/app/copy/leadership_sets.py` holds the eight sentences as module
constants and publishes an empty `COPY`, with the reason in its docstring.
E5-13's scope already names "set-management copy"; `docs/tickets/e5/deferred.md`
carries the gap with its done-when.

## 3. Letting the database refuse a level, and telling two membership refusals apart (2026-09-14)

Worked, first try, after two measurements rather than one guess.

The wire model types the level as a plain `str`, and the question was whether
SQLAlchemy would let `"ug"` reach Postgres or raise a `LookupError` of its own
against the mapped enum. Measured: `Enum(CourseLevel).validate_strings` is
`False` and `_db_value_for_elem("ug")` answers `"ug"`, so the string is sent and
the database answers `22P02` — no cast, no `text()` statement, and the refusal is
the one the criterion asks for.

The harder half was that a cross-level member and a member key that is no course
both violate the *same* composite foreign key if the row is written with the
set's level in both columns, which makes two refusals indistinguishable. The
membership insert reads the course's own level in a scalar subquery instead:
a real course of another level lands its real level and the `the_levels_agree`
check fires, and a key that is no course leaves the column empty and `NOT NULL`
fires. Both are still the database's refusal, and they are two different ones.

The constraint names are read off the models' metadata rather than transcribed:
the naming convention's prefix is applied at DDL time, so the migration's
`ck_comparison_set_member_the_levels_agree` is a string that would have had to be
kept in step by hand in a second file.

codebase's commonest write shape, eleven sites across the services — and taking
it would be dodging a name match with a second call shape rather than satisfying
a rule, so it was not taken.
