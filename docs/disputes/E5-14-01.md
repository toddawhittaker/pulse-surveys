## What I believe it asserts incorrectly

The expected set is the pre-E5-14 set. The owner's freeze-at-close ruling, which
this ticket implements, makes the two `SECURITY DEFINER` set functions decide
whether each response was fixed by a cutoff. Deciding that needs exactly four
columns the definer did not hold:

- `response.last_submitted_at` — "its `last_submitted_at <= T(w)`";
- `survey_window.section_id`, `survey_window.week_id` — the join key from a
  response to "the window it was submitted in (its section's `survey_window` for
  its `week_id`)";
- `survey_window.closes_at` — "has `closes_at <= T(w)`".

The E5-14 tree grants those four and nothing else, column-grain, in
`backend/app/views_sql/benchmark_definer_v002.sql`. So the equality should hold
twenty-two pairs over seven relations, and `survey_window` is the seventh. No
column of `user`, `user_identity` or `person` is added, no verb other than
`SELECT`, and no table-wide grant; the other three assertions in the test stay
green.

The test itself says what should happen next: the ADR 0165 amendment moves
first, and "this constant follows it in the same pull request". The amendment is
a record, which the orchestrator writes for this ticket, and the constant is
behind the test wall. So this is the order that test asks for, not a disagreement
about the rule.

## The spec text I am relying on

SPEC §4.1 item 7: "No figure computed from a comparison set is shown below the
benchmark minimum — a mean, a median, or any other statistic, not only a drawn
line. A comparison figure over fewer than the configured number of sections is
suppressed exactly as a line is (§5.1)."

And the owner's ruling of 2026-09-22 in the E5-14 work order, "Freeze at close":
"A comparison or university figure for course week *w* on a section's report
counts only responses that were fixed at the moment the report's own section's
week-*w* survey window closed. Concretely, with *T(w)* = the reported section's own
`survey_window.closes_at` for course week *w*: a response contributes to week *w*
only if the window it was submitted in (its section's `survey_window` for its
`week_id`) has `closes_at <= T(w)`, **and** its `last_submitted_at <= T(w)`."

The orchestrator's SQL-shape ruling puts that decision inside the `_v003` bodies,
which run as `pulse_benchmark_definer`: "New `_v003` bodies ... Owner,
`SECURITY DEFINER`, pinned `search_path`, and EXECUTE-only-to-`pulse_app` exactly
as `_v002`."

## What I tried

1. The `_v003` bodies without the grant. Every freeze test fails with
   `permission denied for table response` (measured: the migration's
   `benchmark_definer_v002` step replaced with `pass`, then
   `tests/integration/test_the_benchmark_set_functions_count_only_what_each_weeks_cutoff_had_fixed.py -x`
   stopped on its first case with that error; restored afterwards). So the grant
   is load-bearing, not incidental.
2. Looking for a way to decide "fixed by the cutoff" without the two relations.
   There is none inside the function: the window's close is stored only on
   `survey_window`, and a revision after the close is visible only in
   `response.last_submitted_at`. Passing either in from the caller would mean the
   application computing per-response facts and handing them to a function that
   counts, which is the second implementation of a benchmark figure ADR 0165
   exists to prevent. A second definer role would move the same four columns to
   a different owner and still need its own equality.

## Why I believe the test rather than my code is at fault

The code implements the ruling as the order specifies, with the smallest reach
that can: four columns, column-grain, `SELECT` only, none of them reaching a
person. The test's expected set predates the ruling, and the test's own message
names this exact situation ("If a seventh is legitimate, the amendment is where
it is argued and this constant follows it"). What is owed is the ADR 0165
amendment naming the four columns (orchestrator) and then the constant updated
to the twenty-two pairs (test author), in this pull request.
