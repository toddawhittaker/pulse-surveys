# E2-08-01 — the submit route cannot be found, because the walk that looks for it cannot see an included router

**Ticket:** E2-08
**Test:** `tests/integration/test_the_submit_test_machinery_stands_up_what_it_claims.py::test_the_submit_route_is_the_one_post_route_the_student_api_defines`, and through `SignedInStudent.submit` every one of the 23 integration tests in this ticket

## The test

The test itself is three lines; the reading it rests on is the fixture helper
below, which is what this objection is about.

```python
def test_the_submit_route_is_the_one_post_route_the_student_api_defines(
    open_submit_tool: Any,
    mock_ai_endpoint: Any,
) -> None:
    """`app.api.student` defines exactly one `POST` route, registered on the application.

    E2-08's work order settles the module and settles no URL, so this is how every
    other test in this ticket addresses the route: it finds the one POST endpoint
    that module defines. Two things have to hold for that to work, and each is a
    different missing piece — the module exists and defines the route, and
    `app.main.create_app` registers its router "beside the others".

    **This is not a control and it will be red until the route lands.** It is
    written separately so that "E2-08 is not built" reads as one failure with a
    name rather than as every submission test failing on a 404.
    """
    client = open_submit_tool(ai_base_url=mock_ai_endpoint.base_url)
    path = submit_route(client)

    assert path.startswith("/"), (
        f"The submit route's path is {path!r}, which is not an absolute path and cannot be "
        "requested."
    )
```

And `tests/fixtures/submit.py`:

```python
def submit_route(client: Any) -> str:
    """The path template of the one `POST` route `app.api.student` defines.

    **Discovered, not named.** E2-08's work order settles the module — "the submit
    route goes in a new file `backend/app/api/student.py`" — and settles no URL,
    so the module is the fact this reads and the path is whatever the ticket's
    author registered it at. A constant here would be this suite choosing an
    address the ticket left open.
    """
    routes = [
        route
        for route in getattr(client.app, "routes", [])
        if "POST" in (getattr(route, "methods", None) or set())
        and getattr(getattr(route, "endpoint", None), "__module__", None) == STUDENT_API_MODULE
    ]
    if len(routes) != 1:
        registered = sorted(
            f"{sorted(getattr(route, 'methods', None) or [])} {getattr(route, 'path', '?')} "
            f"({getattr(getattr(route, 'endpoint', None), '__module__', '?')})"
            for route in getattr(client.app, "routes", [])
        )
        pytest.fail(
            f"`{STUDENT_API_MODULE}` defines {len(routes)} POST routes on the built application; "
            "E2-08 ships exactly one, the submit route. The application registers: "
            f"{registered}. The module is the work order's ('the submit route goes in a new file "
            "`backend/app/api/student.py`'), and the router has to be registered in "
            "`app.main.create_app` for a request to reach it at all."
        )
    return str(routes[0].path)
```

## What I believe it asserts incorrectly

Not the property — the property is right, and it is how every other test in this
ticket addresses the route. The **reading** is impossible on the FastAPI this
repository pins.

`submit_route` walks `client.app.routes` and keeps the members that carry a
`.endpoint`. On `fastapi==0.141.1` / `starlette==1.6.0` (both in
`requirements.txt`), `app.include_router(...)` does not copy the router's routes
onto the application. It appends a single `fastapi.routing._IncludedRouter`,
which is a `starlette.routing.BaseRoute` carrying `handle`, `matches`,
`effective_candidates`, `original_router` and **no `path`, `methods` or
`endpoint` at all**.

Measured on this branch, with the module written and the router registered:

```
$ python -c "from fastapi import FastAPI, APIRouter; r = APIRouter();
             r.post('/x/y')(lambda: {}); a = FastAPI(); a.include_router(r);
             print([(type(x).__name__, getattr(x,'path',None),
                     getattr(getattr(x,'endpoint',None),'__module__',None)) for x in a.routes])"
[('Route', '/openapi.json', 'fastapi.applications'),
 ('Route', '/docs', 'fastapi.applications'),
 ('Route', '/docs/oauth2-redirect', 'fastapi.applications'),
 ('Route', '/redoc', 'fastapi.applications'),
 ('_IncludedRouter', None, None)]
```

So the list comprehension is empty for any route reached through
`include_router`, and the helper fails with "`app.api.student` defines 0 POST
routes on the built application" — which is the same message it printed on HEAD,
before a line of this ticket was written.

**This is the reading `docs/disputes/E2-04-01.md` raised and the arbitrator ruled
on, on 2026-09-01.** That ruling required the repair to close the whole class
rather than one caller: `tests/fixtures/routing.py` now exists, its docstring
begins "one walk, for the two suites that ask", and it names
`docs/MISTAKES.md` entry 13 as the reason. `submit_route` is a third walk of the
same route table, written the blind way.

## The spec text I am relying on

None — this is not a disagreement about what the system should do. The work
order settles the module and this branch puts the route in it:

```
$ python -c "from app.api import student; print(sorted(
      (r.path, sorted(r.methods)) for r in student.router.routes))"
[('/student/submissions', ['POST'])]
```

and `app.main.create_app` registers it beside the other four routers, in the
place the work order names (`backend/app/main.py`, the `include_router` block).

## What I tried

1. **Wrote the implementation and ran the module.** With
   `/student/submissions` on `student.router` and that router included by
   `create_app`, this test is still red with the identical message it printed on
   the untouched tree. That is the mutation proof in both directions: the test is
   red with the feature absent and red with the feature fully built, so it
   discriminates nothing about E2-08 (`docs/MISTAKES.md` entry 24).
2. **Ran the repository's own repaired walk against the built application**, to
   check that the property survives the flattening rather than only the failure:

   ```
   $ python -c "import sys; sys.path.insert(0,'tests')
                from app.main import create_app
                from fixtures.routing import every_route
                print([(getattr(r,'path',None), sorted(getattr(r,'methods',[]) or []))
                       for r in every_route(create_app())
                       if getattr(getattr(r,'endpoint',None),'__module__',None) == 'app.api.student'])"
   [('/student/submissions', ['POST'])]
   ```

   Exactly one, which is what the test asks for. An application whose routers
   were never registered appends no `_IncludedRouter` to recurse into, so the
   near miss the helper exists to catch — a module that defines a route nothing
   registers — still fails.
3. **Considered registering the route on the application directly**, with
   `app.add_api_route(...)` or by splicing `student.router.routes` into
   `app.router.routes`. Both would make this helper find it. I did not do either:
   it is working around a test rather than satisfying one, it makes this one
   router unlike the four beside it for no reason a reader could later recover,
   and E2-04-01's implementer rejected the same move on the same ground with the
   arbitrator agreeing.

## Why I believe the test rather than my code is at fault

The helper asserts a property no implementation reached through
`include_router` can satisfy on the pinned FastAPI, and it fails identically with
the feature present and absent. The repository has already ruled on this exact
reading and has already shipped the fix as a shared helper; this is that helper
not being used by a walk written after it.

The repair is one import and one call, and the property survives intact:

```python
from fixtures.routing import every_route

def submit_route(client: Any) -> str:
    routes = [
        route
        for route in every_route(client.app)
        if "POST" in (getattr(route, "methods", None) or set())
        and getattr(getattr(route, "endpoint", None), "__module__", None) == STUDENT_API_MODULE
    ]
    ...
```

I have not written it: `tests/**` is read-only for me, and the shape of the
helper is the test author's to choose.

**What this blocks.** `SignedInStudent.submit` calls `submit_route` on every
request it makes, so all 23 integration tests in this ticket die here. To measure
the rest of the ticket while this is outstanding I ran the suite under an
out-of-band pytest plugin that replaces this helper with the flattening version
above, and reported those results as what they are — measurements taken with the
objection applied, not passing tests on the tree as it stands. With that one
substitution (and `E2-08-02`'s), all 46 of the ticket's tests pass.

**One neighbouring fact worth the arbitrator's attention**, because it is the
same class one level out: `tests/fixtures/routing.py`'s docstring says the E2-04-01
ruling required "one walk and not two" so the class would close rather than
recur. It has recurred, in a fixture written the day after the ruling, in a file
that does not import the helper. Whatever is decided about this test, the thing
that stops the fourth copy is not another repair.
