# E5.1-02-01 — an invariant-marked control asserts only inside a helper, so the §4.1 assertion scan fails the suite in every state

**Ticket:** E5.1-02
**Test:** `tests/integration/test_teaching_members_and_test_users_hold_no_student_enrollment.py::test_a_member_the_walk_read_as_a_learner_still_lands_as_a_student`
(and, through it, `tests/unit/test_the_invariant_gate_halves_agree.py::test_the_collector_and_the_assertion_scan_count_the_same_invariant_tests`)

## The test

```python
def test_a_member_the_walk_read_as_a_learner_still_lands_as_a_student(
    launch_driver_in: Any,
    landing_ground: Any,
    committed_rows: Any,
    metadata_tables: dict[str, Any],
    stored_signing_key: str,
    roster_sync: Any,
    application_session: Any,
) -> None:
    """The landing pair: listed as a Learner, the same subject lands as a student.

    **The mutation this kills:** a sync that closes every enrollment it walks, or
    a landing that refuses every launch after a walk — both of which pass the test
    above. Green today.
    """
    member = a_launching_member(launch_driver_in, landing_ground, committed_rows, metadata_tables)
    member.walkable.walk(
        roster_sync, application_session, [roster_member(member.subject, roles=A_STUDENT)]
    )
    landed, _ = member.driver.launch(member.offer)
    session_token_at(landed, STUDENT_LANDING, "A launch by a subject the walk listed as a Learner")
```

The module is marked `pytest.mark.invariant` at module level, so this function is
an invariant test.

## What I believe it asserts incorrectly

Nothing about its behaviour is wrong; it passes. What is wrong is its shape. Its
body contains no `assert`, no `pytest.raises` block and no `pytest.fail` call: its
only check is inside the helper `session_token_at`
(`tests/fixtures/student_read.py:1124`). The repository's §4.1 gate,
`scripts/ci/check_invariant_assertions.py`, does not chase helpers (E0-36 §3) and
refuses an invariant-marked test whose body asserts nothing. So:

```
$ python scripts/ci/check_invariant_assertions.py tests
FAIL: 1 `invariant`-marked test(s) assert nothing. ...
  tests/integration/test_teaching_members_and_test_users_hold_no_student_enrollment.py:343: test_a_member_the_walk_read_as_a_learner_still_lands_as_a_student
  The body must contain an `assert`, a `with pytest.raises(...)` block, or a
  `pytest.fail(...)` call. An assertion inside a helper the test calls does not
  count (E0-36 §3: helpers are not chased); move one line into the test.
exit=1
```

That exit makes `tests/unit/test_the_invariant_gate_halves_agree.py::test_the_collector_and_the_assertion_scan_count_the_same_invariant_tests`
fail in the full suite, and it would fail CI's isolated invariant pass the same
way.

## The spec text I am relying on

Not the spec: the project's process. `CLAUDE.md`, "CI and build discipline":
"**The §4.1 invariant suite may never be skipped.** CI runs it in an isolated
pass and treats a skip, an xfail, or an empty collection as a failure;
`scripts/ci/check_invariants.py` enforces this." And the checker's own rule,
quoted above, which E0-36 item 3 established.

## What I tried

Nothing on the code side can change this: the checker reads the test file's
syntax tree, which no implementation touches. Shown red in both states: the test
tree at the branch head is byte-identical to 9ed5492 (`git diff --stat 9ed5492
HEAD -- tests` is empty), and the checker exits 1 over it with the implementation
in place, where the test itself passes. The full suite, run with the
implementation, is otherwise green (1 failed, 3944 passed; this is the one).

## Why I believe the test rather than my code is at fault

The red does not depend on the code at all, so no implementation can turn it
green; only the test's body can. The fix is one line in the test, for example:

```python
    token = session_token_at(landed, STUDENT_LANDING, "A launch by a subject the walk listed as a Learner")
    assert token, "The learner's launch carried no student session."
```

or an `assert` on `landed`'s location in the body, as the staff half beside it
already does.

## Ruling

The test was wrong. `scripts/ci/check_invariant_assertions.py tests` was run and
exited 1 on this test alone, for the reason given above: its only check sat
inside a helper, and the checker does not follow helpers (E0-36 item 3). The test
author added an `assert` to the test's own body that states the landing outcome
(a session was issued, and the redirect goes to the student route), keeping the
helper's checks. The checker then exited 0 and the module passed. No code
changed.
