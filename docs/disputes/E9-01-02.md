# E9-01-02 — a per-parameter invariant mark makes the two halves of the invariant gate disagree

**Ticket:** E9-01
**Test:** `tests/unit/test_the_invariant_gate_halves_agree.py::test_the_collector_and_the_assertion_scan_count_the_same_invariant_tests`
(red because of `tests/integration/test_the_purview_walk_holds_over_generated_forests.py::test_the_generated_worlds_draw_each_shape_the_ticket_names`, added at 1bd94352)

## The test

The existing gate test (unchanged by this ticket) fails in the full backend run:

```
E           collected by `pytest -m invariant`:                 701 function(s)
E           read by check_invariant_assertions.py tests:  700 function(s)
E       assert 701 == 700
```

The new test that causes it marks one parameter, not the function:

```python
@pytest.mark.parametrize(
    "shape",
    [
        pytest.param(
            "an instructor edge into a lead on another person's course",
            marks=pytest.mark.invariant,
            id="instructor-edge-into-a-lead",
        ),
        pytest.param("an assistant-dean insertion", id="assistant-dean-insertion"),
        pytest.param("a two-hat person", id="two-hat-person"),
        pytest.param("a cross-department led course", id="cross-department-lead"),
    ],
)
def test_the_generated_worlds_draw_each_shape_the_ticket_names(shape: str) -> None:
```

## What I believe it asserts incorrectly

Nothing in the gate test is wrong. The new test applies the `invariant` marker
through `pytest.param(..., marks=...)`. `pytest -m invariant` collects that
function (one parameter is marked); `scripts/ci/check_invariant_assertions.py`
reads only decorators and module-level `pytestmark`, so it does not count it.
The two halves of the §4.1 gate then count 701 and 700. This is the "marker held
in two currencies" shape. It is independent of the code: both halves read test
sources, so it was red at 1bd94352 before any code changed, and it is outside
the predicted manifest because the manifest ran only the ticket's own modules.

## The spec text I am relying on

CLAUDE.md: "The §4.1 invariant suite may never be skipped. CI runs it in an
isolated pass ... `scripts/ci/check_invariants.py` enforces this." The gate test
exists to keep the collector and the assertion scan counting the same tests.
`scripts/ci/` is a path builders may not change.

## What I tried

Nothing in the code can change either count. I confirmed the cause by reading
the scanner (`marked_tests` and `module_is_marked`) and the new test module: it
is the only `marks=pytest.mark.invariant` in the new tests.

## Why I believe the test rather than my code is at fault

No application change affects either half. The repair belongs to the test
author: mark the whole function `@pytest.mark.invariant` (the four shapes are
the same assertion, and the ticket names all four), or split the
instructor-edge case into its own decorated function. Changing the scanner to
read `pytest.param` marks would be a `scripts/ci/` change and a gate change in
its own pull request.

## Ruling (orchestrator, 2026-10-12)

The test file is wrong: an `invariant` mark on one `pytest.param` is invisible to the assertion scan (MISTAKES entry "a marker held in two currencies"). The test author moves that case into its own test decorated with `@pytest.mark.invariant`, with an `assert` in its own body.
