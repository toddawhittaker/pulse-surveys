# E5-14-02 — Under the revised round-3 ruling, A's and B's comparison figures cannot be byte-identical

**Ticket:** E5-14
**Test:** `tests/integration/test_a_readers_own_sections_are_one_group_for_every_benchmark_figure.py::test_two_sections_one_instructor_teaches_share_one_frozen_snapshot`

## The test

The third assertion, after the two "unmoved" assertions (which pass):

```python
    assert a_after == b_after, (
        f"A's and B's reports carry different benchmark members at course week {REPORTED_WEEK}: "
        f"{moved(a_after, b_after)}. The ruling: 'two sections one instructor teaches in one term "
        "get byte-identical comparison and university figures for the same course week'."
    )
```

`a_after` and `b_after` are `benchmark_members_of(...)` for A's and B's reports:
`streams.instructor.benchmark`, `streams.course.benchmark` and `workload_benchmark`,
each of which carries both the `comparison` (default set) and the `university`
members.

The failure on the round-3 implementation:

```
A's and B's reports carry different benchmark members at course week 2:
['streams.course.benchmark', 'streams.instructor.benchmark', 'workload_benchmark'].
{'workload_benchmark': '{"comparison": {"mean": {"figure": 8.3, ...}, ...}' !=
{'workload_benchmark': '{"comparison": {"mean": {"figure": 9.25, ...}, ...}'
```

The comparison members differ. The university members' course-week-2 figures are the same in both (instructor 3.667, course 2.833, workload 9.25 and 8.5, read off the `-vv` diff); I did not diff the full university series, whose weeks follow each report's own published axis.

## What I believe it asserts incorrectly

It requires A's and B's **default-set** figures to be the same bytes. Under the
revised ruling the two default sets are different populations:

- A's default set is the lead's matching sections **minus A**, so it holds B;
- B's default set is the lead's matching sections **minus B**, so it holds A.

A and B have different answers (in this world the hero A carries the planted
hero rows and B carries none), so the two figures differ whatever the cutoff.
Both reports are cut at the same instant — the earliest week-2 close in the
reader group, *T_A* — and both "unmoved" assertions above pass: X's row moves
neither report. What is left is not a freeze difference; it is two different
populations, which the ruling now keeps.

The sentence the test quotes, "two sections one instructor teaches in one term
therefore get byte-identical comparison and university figures", was written
beside the **"Exclude R"** bullet, where both default sets exclude all of *R*
and so are one population. The revised ruling supersedes that bullet
("Populations are resolved as before: the default set excludes only A; the
university includes A") and keeps the one-cutoff rule, but the byte-identity
sentence only follows from the two together.

## The spec text I am relying on

The E5-14 work order, "Round 3 ruling, REVISED (it supersedes the 'Exclude R'
bullet above)":

> - Populations are resolved as before: the default set excludes only A; the
>   university includes A.
> - A figure is shown only if (a) its population meets both minimums; (b) its
>   population minus *R* is empty or meets both minimums; and, for the
>   university only, (c) university − *R* − default set is empty or meets both
>   minimums. (b) and (c) replace the ce9df73 conditions that were written with
>   A in place of *R*.
> - The one-cutoff-per-reader-group rule stands.

And the superseded bullet the byte-identity sentence depends on: "**Exclude
*R*** from the default set and from the university population ... The default
set already excluded A; now it excludes all of *R*."

SPEC §5.1 ("The default comparison set is the same Lead Faculty's courses
filtered to matching length+level") and ADR 0166, decision 5 (the hero is
excluded from its own default set) are unchanged by either.

## What I tried

One approach: the revised ruling as written — populations as before, sealing
on (a), (b), (c) over *R*, and the group's earliest in-term close as each
week's cutoff. Every other round-3 test is green (591 of 592 in the affected
modules), including this test's two "unmoved" assertions and the one-section
control. The only implementation that makes the third assertion green is
excluding all of *R* from the default set (or including A in its own), which is
the withdrawn ruling and would empty the seeded hero's comparison.

## Why I believe the test rather than my code is at fault

The code follows the revised ruling, and no implementation of that ruling can
make two different default sets serialize to the same bytes. The freeze property
the test exists for — X's row reaches neither report because both are cut at
*T_A* — is already asserted by its first two assertions and holds. I suggest
the third assertion compare only the `university` members at the reported
week (one population for A and B), or be dropped; the property "B minus A is
X's student" is closed by the shared cutoff, not by the comparison members being
equal.
