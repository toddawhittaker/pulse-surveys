# E5-05-01 — The smuggling tests re-validate a served payload, which no payload carrying a shown figure can survive

**Ticket:** E5-05
**Test:** `tests/integration/test_every_benchmark_member_refuses_an_unsealed_figure.py::test_a_series_points_mean_refuses_a_figure_the_chokepoint_never_sealed`, and the two beside it
(`::test_the_workload_benchmarks_mean_refuses_a_figure_the_chokepoint_never_sealed`,
`::test_the_workload_benchmarks_median_refuses_a_figure_the_chokepoint_never_sealed`)

## The test

All three tests reach the payload through one helper in the same module:

```python
def drive_one_member(
    door: ReportDoor, contract: Any, *, path: Sequence[Any], named: str
) -> Smuggled:
    """Smuggle an unsealed figure into one member and ask the wire boundary about it.

    The payload is a real one, fetched from the route, with exactly one member
    rewritten — so every other member is what the route serves and nothing in this
    walk is a shape the test invented.
    """
    body, _answered = door.payload(course_week=WEEK_CLEAR)
    model = report_payload_model(contract)
    validated = model.model_validate(body)

    unsealed = an_unsealed_figure(contract.comparison_type(), figure=A_SMUGGLED_MEAN)
    smuggled = with_member_replaced(validated, path, unsealed)

    # Read before the boundary is asked anything, so the canary the test asserts
    # describes what went in rather than whatever survived.
    before = smuggled.model_dump(mode="json")
    served, what_happened = through_the_boundary(model, smuggled, named=named)
    return Smuggled(before=before, served=served, what_happened=what_happened)
```

Each test body then asserts the canary and the outcome, for example:

```python
    outcome = drive_one_member(
        report_door,
        report_api_contract,
        path=(WORKLOAD_BENCHMARK_MEMBER, COMPARISON_POPULATION, MEAN_FIELD),
        named=MEAN_FIELD,
    )
    member = f"{WORKLOAD_BENCHMARK_MEMBER}.{COMPARISON_POPULATION}.{MEAN_FIELD}"

    assert carries_number(outcome.before, A_SMUGGLED_MEAN), the_canary_complaint(
        outcome, member=member
    )
    assert not reached_the_wire(outcome), the_wire_complaint(outcome, member=member)
```

## What I believe it asserts incorrectly

The line `validated = model.model_validate(body)` asks the report schema to
re-validate a payload **it has just served with real benchmark figures in it**.
`body` is the serialized JSON object, so every comparison figure inside it is a
plain mapping. Validating a mapping into `ComparisonFigure` builds the value
through pydantic, which presents no token, so the value is unsealed — and
`refuse_an_unsealed_comparison` refuses any unsealed value that is not
"suppressed and carrying no figure". A shown figure is exactly the other case.

So the call raises before the test has smuggled anything:

```
ValidationError: 15 validation errors for InstructorReport
streams.instructor.benchmark.comparison.points.1.mean
  Value error, This comparison figure was not produced by
  `app.services.reporting.comparison_after_suppression`: it carries no seal ...
```

That is not a property of my implementation. It is a property of any
implementation that satisfies this ticket's criterion 1, which requires the
route to serve figures that are shown. The three tests are unsatisfiable as
written: the only way to make `model_validate(body)` succeed over a payload with
a shown figure is to admit unsealed figures carrying numbers, which is SPEC §4.1
item 7's chokepoint removed.

## The spec text I am relying on

SPEC §4.1, item 7:

> No figure computed from a comparison set is shown below the benchmark minimum
> — a mean, a median, or any other statistic, not only a drawn line. A
> comparison figure over fewer than the configured number of sections is
> suppressed exactly as a line is (§5.1).

And the repository's own record of how that is enforced, which is what makes the
round trip impossible — `app.services.reporting.refuse_an_unsealed_comparison`:

> **A value that shows nothing needs no provenance, and that is the first line
> below.** SPEC §4.1 item 7 is a rule about figures being *shown*: a member that
> says it is suppressed and carries no figure discloses nothing whoever built
> it, so it is admitted unsealed. That is what lets a report be validated from
> its own serialized JSON — every E4 report's comparison member is exactly that
> shape — and it gives up nothing …
>
> Anything else — a figure present, or a value claiming it was not suppressed —
> has to carry the seal.

The sentence says in as many words that round-tripping a report through its own
schema works *because* E4's only comparison member is suppressed and empty. E5-05
is the ticket that ends that condition.

## What I tried

1. **Built it as the work order settles it** — a field validator per figure
   member calling `refuse_an_unsealed_comparison`, and
   `revalidate_instances="always"` on every model on the path from
   `InstructorReport` down to a figure. The smuggling this module performs is
   refused, correctly and at the right member. I proved that separately rather
   than assuming it: a report built by hand out of chokepoint-sealed figures,
   with one member at a time rewritten by `model_copy(update=...)` to an
   unsealed `model_construct` figure carrying 4.25, and then validated. The
   sealed report validates and serializes (the control); each of the three
   tampered reports is refused, and the `loc` of the refusal names the member —
   `streams.instructor.benchmark.comparison.points.0.mean`,
   `workload_benchmark.comparison.mean`, and
   `workload_benchmark.comparison.median`. That is exactly what
   `through_the_boundary` asks for. The same change makes the other seventeen
   tests of this ticket green.
2. **Looked for a way to let a served payload round-trip.** There is none that
   keeps the guarantee: the seal is a private attribute over the field values,
   deliberately not serialized (a serialized seal is a forgeable one), so a
   figure rebuilt from JSON can never carry it. Re-sealing on validation would
   mean any caller could mint a shown figure by handing the schema a dict, which
   is the chokepoint with a door beside it.
3. **Checked whether the tests could be green over a world with no shown
   figures.** They cannot, and should not: they call `benchmark_cohort(...)` and
   read `WEEK_CLEAR`, the week planted at both minimums exactly, which is the
   only honest place to smuggle into.

## Why I believe the test rather than my code is at fault

The property the module is written to prove — an unsealed figure must not reach
the wire through any of the three new members — is true of the implementation and
provable. Only the *route into* the payload is wrong: the module re-validates a
serialized body, and E4-07's own module
(`test_the_comparison_member_is_reachable_only_through_the_suppression_helper.py`,
line 714) does the same thing and is green today for the one reason that stops
applying when this ticket lands — its world has no comparison set, so every
figure in its payload is suppressed and empty.

A repair that keeps the module's intent and costs it nothing is to start from an
object the service built rather than from a serialized body: call the report
service (or `door.payload`'s route) for the `InstructorReport` instance, smuggle
into that with `model_copy(update=...)` exactly as `with_member_replaced` already
does, and hand it to `through_the_boundary`. That is the report a route actually
returns — figures as sealed instances — so `revalidate_instances="always"` is
being exercised on the object the response layer really re-reads, which is the
layer the tests say they are about. It also removes an accidental second way for
these tests to be green, since today the first `model_validate` would refuse a
payload for reasons that have nothing to do with the smuggle.

I have implemented everything else in this ticket and left these three tests red
rather than working around them.
