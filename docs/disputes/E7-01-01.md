## The test

`tests/fixtures/staff_names.py`, `StaffNameWorld.a_week_of`:

```python
    def a_week_of(self, section_id: Any, index: int = 0) -> Any:
        """The `index`-th `week` of the section's own term, by week number."""
        week_table = require_table(self.tables, "week")
        week_terms = foreign_key_columns(week_table, "term")
        if len(week_terms) != 1:
            pytest.fail(f"`week` has {len(week_terms)} references to `term` ({week_terms}).")
```

and the same premise in the body of
`test_a_response_keyed_to_a_week_of_another_term_is_refused`:

```python
    week_term_columns = foreign_key_columns(week_table, "term")
    assert len(week_term_columns) == 1, f"`week` references `term` by {week_term_columns}."
```

## What I believe it asserts incorrectly

`foreign_key_columns(table, "term")` (`tests/fixtures/supervision.py`) returns
every column of `table` that is part of any foreign key pointing at `term`.
`week`'s only key to `term` is the composite
`(term_id, term_length_weeks) → term(id, length_weeks)` (`backend/app/models/term.py`,
`Week.__table_args__`, unchanged since E0-06). So the helper answers
`['term_id', 'term_length_weeks']` on every tree, before and after any fix, and
the guard fails every time:

```
Failed: `week` has 2 references to `term` (['term_id', 'term_length_weeks']).
AssertionError: `week` references `term` by ['term_id', 'term_length_weeks'].
```

These are the first failures of all eleven tests at b5fd2849. The manifest
predicted a `term_id` 42703 or a refusal assertion instead.

## The spec text I am relying on

Not a spec question. SPEC §8: "Containment: … sections to exactly one course and
one term." The schema fact is in the model, not the spec: `week` carries
`(term_id, term_length_weeks)` as one reference to `term (id, length_weeks)`
(`backend/app/models/term.py`, the `Week` docstring and its `ForeignKeyConstraint`).

## What I tried

Nothing in the code can satisfy this: the guard counts columns of an existing
table that E7-01 does not own, and changing `week` would be outside the ticket
and would break E0-06's guarantee. I built F1 to F6 anyway and checked them with
a throwaway SQL probe on a migrated database (results in the PR and the
attempts file), since these tests cannot reach them.

## Why I believe the test rather than my code is at fault

The guard is satisfiable by no implementation of E7-01. A likely repair, for the
test author: pick the column whose key targets the referenced table's `id`, for
example
`[key.parent.name for key in week_table.foreign_keys if key.column.table.name == "term" and key.column.name == "id"]`,
in both places, and the same narrowing in `only_reference` (the `section` case).

## Ruling

The test is wrong. A helper that counts every foreign-key column toward a target misreads a composite key; `week`'s only key to `term` is `(term_id, term_length_weeks)` and F4 makes `instructor_response`'s key to `section` the composite `(section_id, term_id)`. The test author narrows `a_week_of`, the term test's body and `only_reference` to the key column that targets the referenced table's `id`. No product code changes.
