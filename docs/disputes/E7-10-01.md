# E7-10-01 — the draft eval set binds `A_WEEK_WITH_NO_THEMES` twice, and mypy fails on it

**Ticket:** E7-10
**Test:** `tests/evals/response_draft/cases.py` (the `rd-nt-001` case), read by
`tests/evals/draft_check/cases.py` and
`tests/unit/test_the_draft_eval_cases_can_go_red.py::test_the_draft_set_has_each_new_family_and_a_breach_for_each`

## The test

`tests/evals/response_draft/cases.py` binds the name twice at module level:

```python
# E7-10 done-when 4's three new families.
ON_BEHALF_VOICE = "on_behalf_voice"
A_STREAM_WITH_NO_SUMMARY = "a_stream_with_no_summary"
A_WEEK_WITH_NO_THEMES = "a_week_with_no_themes"
...
# E7-10 done-when 4: a week with no themes. Both streams have a summary and
# neither names a theme; the course stream is held.
A_WEEK_WITH_NO_THEMES = (
    StoredSummary(
        stream=INSTRUCTOR_STREAM,
        ...
)
...
    DraftCase(
        case_id="rd-nt-001",
        family=A_WEEK_WITH_NO_THEMES,
        summaries=A_WEEK_WITH_NO_THEMES,
```

and the unit test keys its family map on the same name:

```python
    families = {
        module.ON_BEHALF_VOICE: lambda case: case.on_behalf,
        module.A_STREAM_WITH_NO_SUMMARY: lambda case: any(s.text is None for s in case.summaries),
        module.A_WEEK_WITH_NO_THEMES: lambda case: all(not s.themes for s in case.summaries),
    }
```

## What I believe it asserts incorrectly

The second binding replaces the first, so `rd-nt-001`'s `family` is the tuple of
summaries, not the string `"a_week_with_no_themes"`. The unit test passes only
because it looks the family up by the same rebound name, so it compares the tuple
with the tuple. Nothing at runtime notices; mypy does:

```
tests/evals/response_draft/cases.py:295: error: Incompatible types in assignment (expression has type "tuple[StoredSummary, StoredSummary]", variable has type "str")  [assignment]
tests/evals/response_draft/cases.py:405: error: Argument "summaries" to "DraftCase" has incompatible type "str"; expected "tuple[StoredSummary, ...]"  [arg-type]
tests/evals/draft_check/cases.py:142: error: Argument "summaries" to "CheckCase" has incompatible type "str"; expected "tuple[StoredSummary, ...]"  [arg-type]
Found 3 errors in 2 files (checked 112 source files)
```

mypy is a CI gate, so the ticket cannot go green while these stand, and the
code under test has nothing to do with them. This is `docs/MISTAKES.md` entry
60's shape (a name rebound at module level, the linter silent).

## The spec text I am relying on

None: this is not a reading of the spec. The ticket's done-when 4 asks for "a
week with no themes" family with a breach that fails its grader; the family's
name has to be a family name for the set to say that.

## What I tried

Nothing in the code: the three errors are all inside `tests/**`, which this lane
may not edit.

## Why I believe the test rather than my code is at fault

The errors are type errors in the test files themselves, independent of any
backend change. The fix the draft-check set already uses is the one I would
propose: rename the response-draft family constant to
`A_WEEK_WITH_NO_THEMES_FAMILY` (as `tests/evals/draft_check/cases.py` spells
its own), use it for `rd-nt-001`'s `family`, and key the unit test's map on
`module.A_WEEK_WITH_NO_THEMES_FAMILY`. The summaries tuple keeps the name
`A_WEEK_WITH_NO_THEMES` that `draft_check/cases.py` imports.

## Ruling

Test wrong. Fixed on the test side in its own commit (37a150d4), with the
smaller rename: the summaries tuple becomes `A_WEEK_WITHOUT_THEMES`, and the
family constant keeps its name, so the unit test's family map now keys on the
string as it meant to. mypy is clean over the repository, and the unit test
still passes.
