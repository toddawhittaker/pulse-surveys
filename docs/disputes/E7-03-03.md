# E7-03-03 — The copy governance map has no row for the leadership response screens

**Ticket:** E7-03
**Test:** `tests/unit/test_the_shipped_copy_inventory_holds_to_items_four_and_five.py::test_every_collected_key_belongs_to_a_governed_surface`

## The test

```python
GOVERNED_SURFACES = {
    "student_survey": SURVEY,
    ...
    "leadership_comparison_sets": COMPARISON_SETS,
    "entry": ENTRY,
    "leadership_moderation": LEADERSHIP_MODERATION,
}
```

and the assertion that every collected copy key's prefix (the part before the
first dot) is a key of that map:

```
AssertionError: These collected keys belong to no governed surface: [...].
... Adding the surface is one row in `GOVERNED_SURFACES`, plus its confidentiality
key in `CONFIDENTIALITY_KEY_OF_SURFACE` if that surface carries the line.
```

## What I believe it asserts incorrectly

Nothing about the rule; the map is one row short, exactly as in
`E6-05-02.md`. E7-03 adds two refusals the leadership response routes answer
(work order decisions 2 and 5), registered in `app/copy/response_loop.py`:

- `leadership_response.no_policy_to_set` — the policy switch's one 404;
- `leadership_response.on_behalf_unavailable` — every on-behalf door's one 404.

They belong to the screens E7-07 builds (the policy page, the responses-owed
list and the on-behalf composer), which are not the moderation screens and not
the named-set screen. Filing them under `leadership_moderation.` would turn this
test green by counting another screen's refusals toward the moderation surface,
which is the mutation that map's own comment names as rejected.

The two instructor refusals E7-03 adds are filed under `instructor_report.`
(`response_already_published`, `response_not_editable`): the composer is on the
report page (E7-05), so they are the report surface's words, as the report's
other API refusals are.

## The spec text I am relying on

SPEC §4.1 items 4 and 5 (the vocabulary rule and one confidentiality line per
surface), and the ruling on `E6-05-02`: "The test's map is one row short. The
rule stands. The test author adds `leadership_moderation.` to
`GOVERNED_SURFACES`, and adds a confidentiality key only if that surface carries
the confidentiality line."

## What I tried

Re-keying to an existing governed prefix. The only candidates are
`leadership_moderation.` and `leadership_comparison_sets.`, both other screens.

## Why I believe the test rather than my code is at fault

The map enumerates surfaces, and E7 adds one. The likely repair is one row,
`"leadership_response": <a new surface constant>`, with no confidentiality key
until E7-07 decides whether its pages carry the line (E7-07's own test can add
it). With that row, `test_every_governed_surface_collects_at_least_one_string`
is satisfied by the two keys above.
