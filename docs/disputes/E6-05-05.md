## The test

```python
def test_a_lead_who_teaches_a_section_of_their_led_course_does_not_see_its_held_comments(
    lead_review: LeadReviewWorld,
) -> None:
    review = lead_review
    review.teaches(review.lead, LEADS_TAUGHT_COHORT)
    assert_the_taught_section_is_left_out_of_the_queue(
        review, review.lead, taught=LEADS_TAUGHT_COHORT, canary=LEADS_CANARY_COHORT
    )
```

The other three have the same shape: every assertion is inside
`assert_the_taught_section_is_left_out_of_the_queue` or
`assert_a_decision_on_the_taught_section_is_refused`.

## What I believe it asserts incorrectly

The assertions are correct, and all four pass against the fix. The problem is
where they are. The module is marked `invariant`, and
`scripts/ci/check_invariant_assertions.py` requires the body of every
invariant-marked test to contain an `assert`, a `with pytest.raises(...)`
block or a `pytest.fail(...)` call. It does not follow helpers (E0-36 §3).
Run over `tests`, it exits 1:

```
FAIL: 4 `invariant`-marked test(s) assert nothing. ...
  The body must contain an `assert`, a `with pytest.raises(...)` block, or a
  `pytest.fail(...)` call. An assertion inside a helper the test calls does not
  count (E0-36 §3: helpers are not chased); move one line into the test.
```

So the full suite has one failure, the gate-halves test, and CI's invariant
gate would refuse the branch.

## The spec text I am relying on

CLAUDE.md: "The §4.1 invariant suite may never be skipped ...
`scripts/ci/check_invariants.py` enforces this." The assertion scan is that
gate's other half, and its message prescribes the remedy: "move one line into
the test."

## What I tried

Nothing to the tests. The code fix for ruling 7 is built, and the four tests
pass. The rest of the full suite passes too: 4415 passed, with this one failing.
The serial invariant pass shows 713 passed, because it runs the tests and does
not scan them.

## Why I believe the test rather than my code is at fault

No production code can satisfy a static scan of a test's body. The fix is in the
test file: have each helper return what it checked and assert that in the body,
or move one of its assertions into the body, as the scan's message says.

## Ruling

The tests are wrong in form, not in substance. The invariant assertion scan requires each invariant test to assert in its own body, and that gate stays as it is. The test author moves each test's deciding assertion into the test body, for example by having the helpers return what they read and asserting on the result in the body. The assertions themselves do not change.
