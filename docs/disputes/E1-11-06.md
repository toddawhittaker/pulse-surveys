# E1-11-06 — Two roster-sync controls require the mock to serve a roster to a credential it did not issue

**Ticket:** E1-11 (fix round on `e1/nrps-token-enforcement`)
**Tests:**
`tests/integration/test_the_roster_sync_is_a_conformant_service_client.py::test_the_wire_carries_a_request_to_the_platform_and_refuses_an_unmounted_host`
`tests/integration/test_the_roster_sync_is_a_conformant_service_client.py::test_the_wire_refuses_a_service_read_that_carries_no_bearer_token`

## The test

Both drive the mock platform's real memberships route by hand, over the
`ServiceWire` transport, rather than through `pylti1p3`. The first, in full:

```python
def test_the_wire_carries_a_request_to_the_platform_and_refuses_an_unmounted_host(
    synced_section: Any, service_wire: Any
) -> None:
    """The transport under every assertion in this module, exercised both ways.

    A `requests.Session` that answered nothing would make every "the client called
    this" assertion below unfalsifiable and every "it did not call that" assertion
    trivially true. So it is required to *fetch* — the section's own stored roster
    address, through the real mock — and to *refuse* a host nothing mounted, which
    is what stands between "the sync resolved the wrong platform" and a silent
    pass (deferred E1-10 item 1's failure mode).

    **A red here means these tests are broken, not the sync.**
    """
    session = service_wire.session()

    answered = session.get(str(synced_section.address))
    assert answered.status_code == 200, (
        f"The wire answered {answered.status_code} for the section's own stored roster address "
        f"{synced_section.address!r}. Body begins {answered.text[:200]!r}."
    )
    assert isinstance(answered.json().get("members"), list), (
        f"The wire carried back {answered.text[:200]!r}, which is not an NRPS membership "
        "container. Every ingestion assertion in this suite rests on the mock's real container "
        "reaching the client through this transport."
    )
    assert service_wire.to_host(synced_section.host), (
        "The wire recorded no call to the platform's host, so its record is empty and every "
        "assertion in this module that reads it would be satisfied by a client that made no "
        "request at all."
    )

    with pytest.raises(Exception, match="no application is mounted"):
        session.get("http://a-platform-nobody-registered.invalid/memberships")
```

The second, in full below its docstring:

```python
def test_the_wire_refuses_a_service_read_that_carries_no_bearer_token(
    synced_section: Any, service_wire: Any
) -> None:
    """The gate AC1's forbidden state is asserted with, proven able to fire.

    `refusing_unauthenticated_reads` is a harness gate rather than the platform's.
    It was built when E1-06's ruling stood and the mock required no token; E1-11's
    fix round made the mock refuse too, and the gate stays because this suite
    asserts over the wire the client's requests are recorded on rather than over
    the mock's status codes. A gate nobody has watched refuse anything is a comment
    (`docs/MISTAKES.md` entry 9), and the test that rests on it —
    `test_the_sync_has_no_unauthenticated_path_to_the_roster` — would then be green
    against a client that attaches nothing.

    Both directions, one request apart: the same URL with a bearer token and
    without one.

    **A red here means these tests are broken, not the sync.**
    """
    service_wire.refusing_unauthenticated_reads()
    session = service_wire.session()

    granted = session.get(
        str(synced_section.address), headers={"authorization": "Bearer a-token-shaped-string"}
    )
    assert granted.status_code == 200, (
        f"The wire refused a read carrying a bearer token with {granted.status_code}, so its gate "
        "refuses everything and the pair below would be about nothing."
    )

    refused = session.get(str(synced_section.address))
    assert refused.status_code == 401, (
        f"The wire answered {refused.status_code} for a read carrying no `Authorization` header "
        "while its unauthenticated gate was on. That gate is what AC1's forbidden state is "
        "asserted through — it refuses on the wire, where a second path in the client is visible "
        "rather than inferred — so with it inert, that state cannot be asserted at all."
    )
```

`ServiceWire.deliver` passes a request through to the real mock application
whenever no roster, canned answer, failure or redirect is installed for its host
and path (`tests/fixtures/roster_sync.py`), and none is installed in either
test. `synced_section.address` is the memberships URL of a section seeded from
the real mock, so both requests land on `mock-lms/app/main.py::memberships`.

## What I believe it asserts incorrectly

Two assertions require the mock platform to serve a membership container to a
request the enforcement this ticket exists to add must refuse:

1. `answered.status_code == 200` for `session.get(synced_section.address)` with
   **no `Authorization` header at all**.
2. `granted.status_code == 200` for the same URL carrying
   `Authorization: Bearer a-token-shaped-string` — a string this platform's
   token endpoint never issued.

Those are the exact two cases
`tests/integration/test_mock_lms_nrps_requires_a_token.py` requires to be
refused, on the same route, on the same platform, with no signal that could
distinguish one caller from the other:

- `test_a_roster_read_carrying_no_authorization_header_is_refused_with_a_bearer_challenge`
  requires 401 for case 1.
- `test_a_credential_the_token_endpoint_never_issued_is_refused_as_an_invalid_token`
  requires 401 `invalid_token` for case 2, and names the mutation it kills as
  "an enforcement that checks the header is present and well formed and never
  asks whether the token is one this platform issued … hands the roster to
  anyone who types the word".

No implementation satisfies both suites. The requests are identical in method,
URL, transport and process; the only difference is which test issued them.

The second test's own docstring, as amended on this branch, states the fact its
code contradicts: "E1-11's fix round made the mock refuse too, and the gate
stays because this suite asserts over the wire … rather than over the mock's
status codes." That is the correct reading of what the gate is for — and the
two `== 200` assertions are then reading the mock's status codes anyway.

## The spec text I am relying on

SPEC §14.3, E1's exit line (line 540), quoted whole:

> *Exit:* a student, an instructor, and a Dean each land on the right (empty)
> view from either door; the seeded two-hat person enters by both doors and
> resolves to the same stored identity row; a synced section shows correct
> derived dates; a replayed or state/nonce-tampered launch is refused; and a
> roster read succeeds as an authenticated service call, not an unauthenticated
> GET.

The last clause is the one at issue: the exit proof has to distinguish an
authenticated service call from an unauthenticated GET, and only the platform
can tell them apart. A platform that answers 200 either way makes the clause
unwitnessable.

SPEC §3.4 is the other half of the picture, and it is why AGS is untouched:
grade passback belongs to E2, so no AGS client exists and the mock's AGS routes
stay open. Nothing in this dispute is about AGS.

## What I tried

1. **Enforcement on the NRPS route as the work order specifies**, validating
   against the token store `mock-lms/app/tokens.py` already issues from. All ten
   tests of `test_mock_lms_nrps_requires_a_token.py` pass, and 61 of the 63
   tests in the roster-sync suite pass, including every assertion about what the
   client *sent* — the conformance claims themselves are unaffected, because
   `pylti1p3` obtains a token before every service call.
2. **Looked for a distinction the enforcement could legitimately draw** between
   the two suites' requests: a different application instance, a different host,
   a marker on the transport. There is none. `roster_platforms` builds a real
   mock application and `ServiceWire` mounts it by host; the requests are
   indistinguishable at the route.
3. **Considered narrowing the enforcement** to refuse only a malformed header
   while accepting any bearer token. That satisfies test 2's first assertion and
   is refused explicitly by
   `test_a_credential_the_token_endpoint_never_issued_is_refused_as_an_invalid_token`,
   whose docstring names it as the mutation it exists to kill. It also fails
   test 1, which presents no header at all.

That is the honest list: one implementation, plus two rejected ways of bending
it. The contradiction is between two test modules, not between a test and my
code.

## Why I believe the test rather than my code is at fault

The two suites cannot both be right, and only one of them is about the mock's
enforcement. `test_mock_lms_nrps_requires_a_token.py` was written for this fix
round as the contract; these two are *controls on a transport*, and their own
docstrings say what they are for — that the wire fetches and records, and that
the harness's gate can fire. Neither purpose needs the mock to answer 200:

- Test 1 needs the transport to carry a request to the platform and bring an
  NRPS container back. It can do that with a token attached, exactly as every
  other read in the suite now does.
- Test 2 needs the harness gate to refuse an unauthenticated read and to let an
  authenticated one past. Its "let past" half currently uses a made-up token —
  which passes the *harness* gate (it only asks whether the header starts with
  `Bearer `) and is then refused by the *platform*. The gate can be shown to
  fire without asking the platform to serve anyone.

So the fix is on the test side and it is small: obtain a real token the way the
rest of the suite now does, and assert the pair over the wire's own gate rather
than over the mock's status code. I have not made that change, and will not —
`tests/**` is the test author's.

The alternative reading — that my enforcement is wrong — requires the mock to
serve its roster to a credential it never issued, which is the state SPEC
§14.3's exit clause and this ticket's whole red suite exist to end.
