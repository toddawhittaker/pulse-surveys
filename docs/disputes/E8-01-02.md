# E8-01-02 — "no statement names `answer`" also forbids the threshold and moderation gates the ticket tells the read to keep

**Ticket:** E8-01
**Test:** `tests/integration/test_the_students_comment_reads_go_through_the_comment_view_and_never_the_answer_table.py::test_the_students_week_read_returns_the_weeks_comments_through_the_view_alone`

## The test

```python
def test_the_students_week_read_returns_the_weeks_comments_through_the_view_alone(
    hold: HoldWorld,
) -> None:
    world = hold
    with statements_recorded() as recorded:
        returned = call_student_read(
            world,
            STUDENT_COMMENTS,
            section_id=world.taught,
            week_id=world.week_id(1),
            stream=INSTRUCTOR_STREAM,
        )

    assert sorted(text_of(item) for item in returned) == sorted(FULL_WEEK_COMMENTS), (...)
    assert view_reads(recorded), (...)
    assert (
        answer_reads(recorded) == []
    ), f"`{STUDENT_COMMENTS}` read `answer` itself: {answer_reads(recorded)}. Done-when 4."
```

`answer_reads` takes every recorded statement matching
`\b(?:FROM|JOIN)\s+(?:"?public"?\s*\.\s*)?"?answer"?(?![\w"])`.

## What I believe it asserts incorrectly

The first two assertions pass. The third fails on exactly two statements, and
neither reads a comment's text for the student:

1. `_unmoderated_section_weeks` (ADR 0187, `section_week_moderated`):
   `SELECT response.section_id, response.week_id, answer.comment_text FROM answer
   JOIN response ... JOIN question ... WHERE question.kind = 'comment' AND
   answer.comment_text IS NOT NULL AND NOT EXISTS (moderation classification) AND
   response.section_id = ? AND response.week_id = ?` — the rule that a week shows
   nothing until every comment in it holds a verdict. It has to read `answer`:
   the comments it looks for are exactly the ones v004 leaves out.
2. `_commenters_by_stream_week` (ADR 0182, `stream_is_suppressed`):
   `SELECT commenters FROM (SELECT ..., count(DISTINCT response.user_id) FROM
   public.report_comment JOIN answer ON answer.id = report_comment.answer_id JOIN
   response ON response.id = answer.response_id ...)` — SPEC §4.1 item 3's
   threshold, counted in distinct people. It has to reach `response.user_id`
   through `answer`: v004 carries no person, by design.

Both are the gates `visible_cards` applies before it reads any text, and the
ticket tells the student read to filter `visible_cards`. The comment text
itself is read from `report_comment` only (the statement the test's
`view_reads` finds). So the assertion as written forbids the two gates, not a
second copy of v004's text rule.

## The spec text I am relying on

The ticket, "Comments a student may read": "Two new functions in
`services/report_comments.py`, `student_comments` and
`student_released_comments`, filter `visible_cards` and `released_cards` (which
read `report_comment` v004) to the `published` and `kept` statuses."

Done-when 4: "... The read goes through v004, and no student read queries
`answer` itself."

SPEC §4.1 item 3: "Below the n-threshold — fewer than that many distinct
commenters in that stream that week — raw comments in that stream are hidden
from instructors and students alike."

SPEC §4, small-N handling: "fewer than the threshold's number of distinct
students commenting in a stream in a reporting week".

The test's own docstring names the mutations it is for: "the read written
against `answer` joined to `response` and `moderation_state` (a second copy of
v004's rule that misses the Care exclusion), or the view read and then `answer`
read again 'for the text'." Neither gate statement is either of those.

## What I tried

One approach: `student_comments` is `visible_cards` filtered to `published`
and `kept`, returning text and stream only. It passes the first two assertions
and fails the third on the two gate statements above.

The way to pass the third assertion is to drop the gates from
`student_comments` (read the view directly, filtered by section, week, stream,
batch membership and status) and rely on the route's `_held_streams` check in
`reporting.student_streams` to withhold a small or unmoderated stream. I did
not do that: it would make `student_comments` on its own return the text of a
stream below the threshold, and of a week still awaiting a verdict, to any
caller, and it is not "filter `visible_cards`" any more. That is implementing
something I think is weaker just to get green.

## Why I believe the test rather than my code is at fault

The ticket's two sentences meet here. "Filter `visible_cards`" keeps the
threshold and the whole-week moderation rule inside the student read, and both
rules can only be evaluated against `answer` (one counts people v004 does not
carry, the other finds comments v004 leaves out). "No student read queries
`answer` itself" is right about the text, and the test's docstring shows that
is what it means, but its matcher cannot tell a gate's count from a text read.

A narrower assertion keeps the test's purpose: no statement that selects
`comment_text` (or returns rows to the student read) names `answer`, or the
statements that name `answer` select no comment text into the result and are
the two named gates. If the arbitrator instead reads done-when 4 as forbidding
the gates inside the student read, that is a ruling on where SPEC §4.1 item 3
is enforced for students, and I would want it written into ADR 0197.

**Status of the code meanwhile:** `student_comments` keeps the gates. Every
other E8-01 test that exercises it (the small-N, status, order and sibling
tests) is green.

## Ruling

Test wrong, in its matcher. The student read keeps both gates inside it: the
threshold (SPEC §4.1 item 3) and the whole-week moderation rule (ADR 0187)
stay where `visible_cards` enforces them, so the read is safe for any caller.
Done-when 4 forbids reading comment text from `answer`, not the two gates. The
test author narrows the third assertion: the statements that name `answer` are
exactly the two gate statements (matched by their distinctive shapes: the
`NOT EXISTS` moderation check and the `count(DISTINCT response.user_id)`
commenter count), and no other statement names `answer`. A second copy of
v004's rule, or a re-read "for the text", is still a new statement naming
`answer` and still goes red. ADR 0197 says where the threshold is enforced for
students.
