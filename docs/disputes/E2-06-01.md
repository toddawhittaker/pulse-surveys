# E2-06-01 — The all-cohorts test seeds twenty sections into one course and term, and the seeding helper can only spell thirteen

**Ticket:** E2-06
**Test:** `tests/integration/test_at_most_one_survey_window_is_open_at_a_time.py::test_no_two_windows_of_any_seeded_cohort_overlap_and_none_is_inverted`

## The test

```python
def test_no_two_windows_of_any_seeded_cohort_overlap_and_none_is_inverted(
    fall_2026: Any,
    survey_window_service: Any,
    window_settings: Any,
    db_session: Any,
) -> None:
    """Criterion 2 over the whole seeded start-letter map, deterministically.

    Every one of §2.2's twenty Fall 2026 cohorts, derived into one term, and three
    properties over each set: the windows are one per course week, each opens
    before it closes, and each opens strictly after the one before it closed. The
    third is what "exactly one open survey at a time" reduces to for a sequence of
    intervals on a line.

    **The mutations this kills.**

      - *A window that closes before it opens.* The Friday and the Sunday taken
        from different weeks, or the two swapped, gives a section a window nothing
        can ever be submitted into — and a `closes_at < opens_at` row is not
        refused by anything in E2-05's schema.
      - *Windows on the term's weeks rather than the section's*, which for a
        cohort of fewer than eighteen weeks writes more rows than there are course
        weeks and duplicates some of them.
      - *Every course week written against the same term week*, which is what a
        derivation reading the section's start date instead of the course week's
        offset produces. Twelve identical windows overlap perfectly and the
        one-open rule is broken twelve ways.

    **The non-emptiness guard is not ceremony** (`docs/MISTAKES.md` entry 3): "no
    two windows overlap" is true of a section with no windows, and true of a
    service that wrote nothing at all. Each cohort's count is asserted against the
    length its start letter carries before any interval is compared.
    """
    calendar = fall_2026.build()

    for letter in sorted(SEEDED_COHORTS):
        length_weeks, _first, _start = SEEDED_COHORTS[letter]
        _row, section = calendar.cohort(letter)
        survey_window_service.derive_windows_for_section(
            db_session, section, settings=window_settings
        )
        windows = calendar.windows_of(section)

        assert len(windows) == length_weeks, (
            f"Cohort {letter!r} runs {length_weeks} course weeks and derived {len(windows)} "
            f"windows: {windows}. SPEC §3.1 gives a section one window per active course week, "
            "and every interval property below is vacuous over a set that is empty or short."
        )
        for window in windows:
            assert window["opens_at"] < window["closes_at"], (
                f"Cohort {letter!r}'s window on term week {window['term_week']} opens at "
                f"{window['opens_at']} and closes at {window['closes_at']}. A window that closes "
                "before it opens is one no student can ever submit into, and nothing in E2-05's "
                "schema refuses the row."
            )
        for earlier, later in pairwise(windows):
            assert earlier["closes_at"] < later["opens_at"], (
                f"Cohort {letter!r}'s windows on term weeks {earlier['term_week']} and "
                f"{later['term_week']} overlap: the first closes at {earlier['closes_at']} and the "
                f"second opens at {later['opens_at']}. SPEC §3.1: students see exactly one open "
                "survey at a time per section, and consecutive Friday-to-Sunday spans cannot "
                "overlap unless the derivation put two course weeks on one term week."
            )
```

The `cohort` helper it calls twenty times is
`tests/fixtures/survey_windows.py`'s:

```python
    def section_row(self, letter: str) -> Any:
        """One section of the cohort `letter`, as the inserted row's mapping."""
        length_weeks, _first_term_week, start = SEEDED_COHORTS[letter]
        return self.seed(
            SECTION_TABLE,
            self.chain,
            **{
                SECTION_LENGTH_COLUMN: length_weeks,
                SECTION_START_COLUMN: start,
                SECTION_END_COLUMN: start + timedelta(days=length_weeks * 7 - 1),
            },
        )
```

`self.chain` is built once by `build()` and reused, so all twenty sections are
seeded under the same course and the same term. Nothing names
`lms_section_code`, so the seeding helper invents it.

## What I believe it asserts incorrectly

Nothing. The property it asserts is criterion 2 and is correct. **The test cannot
run at all**: it fails inside its own seeding, on the eleventh cohort, with

```
sqlalchemy.exc.IntegrityError: (psycopg.errors.UniqueViolation) duplicate key
value violates unique constraint "uq_section_course_id_term_id_lms_section_code"
DETAIL:  Key (course_id, term_id, lms_section_code)=(…, …, H3WW) already exists.
```

raised from `tests/fixtures/survey_windows.py:353` in `section_row`, through
`tests/fixtures/supervision.py:560` in `seed_row` — before
`derive_windows_for_section` is called for that cohort. This is
`docs/MISTAKES.md` entry 13's closing sentence exactly: a test failing inside its
own fixture.

The cause is the generator that invents a section code
(`tests/fixtures/supervision.py`):

```python
GRAPH_COLUMN_VALUES = {
    ("course", GRAPH_COURSE_NUMBER_COLUMN): graph_course_number,
    ("section", GRAPH_SECTION_CODE_COLUMN): lambda: f"{graph_letters(1)}3WW",
}
```

`graph_letters(1)` takes the next value of a session-wide counter and returns one
upper-case letter, so it repeats every 26 calls — which `graph_course_number`'s
own docstring says in as many words: "That draws from a session-wide counter one
letter wide, so it repeats every 26 calls; a course number built the same way
would reintroduce a rarer and order-dependent version of this same defect."

**Measured, not inferred.** I wrapped `graph_letters` in a pytest plugin outside
`tests/` and ran this test alone. It draws the counter 34 times in the test, of
which 12 are the width-1 draws that become section codes:

```
PROBE width-1 draws (section codes): ['H', 'N', 'P', 'R', 'T', 'V', 'X', 'Z', 'B', 'D', 'F', 'H']
PROBE strides between section-code draws: [6, 2, 2, 2, 2, 2, 2, 2, 2, 2, 2]
```

Each section seed advances the counter by two — its code and its
`lms_context_id` — so the letters step by two and the alphabet closes after
thirteen. The twelfth cohort draws `H` again and collides with the first. The
stride is a property of the columns a `section` row has, not of the counter's
starting value, so this fails on every run and in every order: I ran it alone
three times and got the same `H3WW` collision each time.

Twenty distinct section codes under one course and one term are not obtainable
from this helper. Thirteen are.

## The spec text I am relying on

The spec is not what is at issue — the disagreement is between two test-side
files — but the constraint the seeding violates is E0-06's, standing on SPEC §2.2:

> Section codes follow `{startLetter}{ordinal}{modality}` (e.g., `R3WW`, `Q2FF`):
> the start letter encodes length + start date within the term via a per-term
> **start-letter map** … Section start/end dates derive from the letter + term
> calendar; nothing is hand-entered per section.

and `app/models/org.py`'s `Section`:

> **A section code identifies a section within a course *and* term.** Hence
> `(course_id, term_id, lms_section_code)` rather than a pair: `BIOL 215 R3WW`
> runs again next fall, and a rule without the term forbids it.

So the constraint the seeding hits is correct and is not the thing to change.

## What I tried

One approach, and there is not a second one on my side of the wall.

The derivation reads `section.length_weeks` and `section.start_date` and never
the section's code (except to name it in the missing-week warning), so nothing
about my implementation influences which code the fixture invents or how many it
needs. I confirmed the failure is upstream of the service by reading the
traceback: the last three frames are the test, `Fall2026.cohort`,
`Fall2026.section_row`, `seed_rows`, and the `INSERT` that raises is the
fixture's own.

The other nineteen tests in the two E2-06 integration modules pass, including the
Hypothesis property over the same twenty cohorts
(`test_no_instant_falls_inside_two_of_one_sections_derived_windows`) — that one
seeds **one** section per example and rebuilds the chain each time, so it never
asks for two codes under one course.

I did not work around it. The workarounds available to me are all wrong: seeding
fewer cohorts changes what the test asserts, and there is no way to name a
section code from the implementation side.

## Why I believe the test rather than my code is at fault

The failure is an `IntegrityError` on an E0-06 constraint, raised from a fixture,
from an `INSERT` that names no column E2-06 owns and runs before the service is
called. No implementation of `derive_windows_for_section` can pass it, and no
implementation can fail it differently: the twelfth `calendar.cohort(...)` call
raises whatever the service does.

The repair is on the far side of the test wall and there are at least two shapes
of it, which is why I am not choosing one here:

- seed each cohort under its own course — `fresh_scope("course")` in
  `tests/fixtures/supervision.py` already exists for "two courses under one
  prefix", and the property this test asserts is per section, so nothing about it
  needs the twenty to share a course;
- or name the section code from `SEEDED_COHORTS` in `Fall2026.section_row` — the
  cohort letter is in hand there, and `f"{letter}1WW"` is both unique per cohort
  and §2.2-shaped, which would also make the seeded row's code agree with the
  cohort it is supposed to be. That second property is worth something on its own:
  today a cohort-`H` section is seeded carrying a code beginning with whatever
  letter the counter was on.

Either is a change to `tests/`. Under E2-06's lane I may not make it, so this is
the objection and I have stopped on that test.

## Ruling (orchestrating session, 2026-09-01)

Test-wrong, at the fixture. The test fails inside its own seeding — MISTAKES
entry 13's corollary, suspect the fixture first, and the measurement above
proves it: the session-wide letter counter exhausts a 13-letter alphabet at the
twelfth cohort. The assertion itself is sound and stays. The repair is the
seeding helper's: draw the twenty cohort letters from a source that cannot
collide for this test (its own alphabet, or reuse of the seeded
start-letter-map letters), on the test author's side of the wall.
