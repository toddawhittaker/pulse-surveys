# E8-01-03 — the narrowed gate matcher reads the real commenter count as "both gates"

**Ticket:** E8-01
**Test:** `tests/integration/test_the_students_comment_reads_go_through_the_comment_view_and_never_the_answer_table.py::test_the_students_week_read_returns_the_weeks_comments_through_the_view_alone`

## The test

As narrowed after the ruling on E8-01-02 (dba777b0):

```python
GATE_SHAPES = {
    "the moderation gate": re.compile(r"\bNOT\s*\(?\s*EXISTS\b", re.IGNORECASE),
    "the commenter count": re.compile(
        r'\bcount\s*\(\s*DISTINCT\s+(?:"?\w+"?\s*\.\s*)?"?user_id"?', re.IGNORECASE
    ),
}

def gate_of(sql: str) -> str | None:
    """Which gate a statement naming `answer` is, by shape, or `None` if it is neither or both."""
    matched = [name for name, shape in GATE_SHAPES.items() if shape.search(sql)]
    return matched[0] if len(matched) == 1 else None
```

## What I believe it asserts incorrectly

The commenter count the code actually sends (`_commenters_by_stream_week`, ADR
0182) carries the release-batch anti-join as well, so it matches **both**
shapes and `gate_of` answers `None`:

```sql
SELECT anon_1.commenters
FROM (SELECT public.report_comment.section_id AS section_id, ...,
             count(DISTINCT response.user_id) AS commenters
      FROM public.report_comment JOIN answer ON answer.id = public.report_comment.answer_id
           JOIN response ON response.id = answer.response_id
      WHERE NOT (EXISTS (SELECT release_batch_member.answer_id
                         FROM release_batch_member
                         WHERE release_batch_member.answer_id = public.report_comment.answer_id))
      GROUP BY ...) AS anon_1
WHERE anon_1.section_id = ... AND anon_1.week_id = ... AND anon_1.stream = ...
```

The failure: "`student_comments` read `answer` outside the two gates: ['SELECT
anon_1.commenters ...']". The test's own sample for the commenter count has no
anti-join, so its instrument test passes while the real statement does not.

## The spec text I am relying on

SPEC §4: "a comment released in a batch is never shown again under its own
week"; ADR 0182: released comments do not count toward their week's
commenters. The anti-join inside the count is that rule, and the ruling on
E8-01-02 keeps the count inside the student read.

## What I tried

Nothing in the code: the statement is the instructor read's count, unchanged,
and removing its anti-join would break ADR 0182.

## Why I believe the test rather than my code is at fault

The ruling allows exactly this statement; the shape matcher cannot see it
because the moderation shape (`NOT EXISTS`) also matches the anti-join. A
likely repair, for the test author: anchor the moderation shape to the
classification it checks (`NOT ... EXISTS (SELECT classification`), or test the
commenter shape first, and add the anti-join to the commenter-count sample.
