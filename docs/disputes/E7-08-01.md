# E7-08-01 — Three invariant tests assert nothing in their own bodies, so CI's invariant gate fails

**Ticket:** E7-08
**Tests:**

- `tests/integration/test_the_leadership_gate_tells_another_role_from_an_ended_session.py::test_a_student_session_gets_the_403_from_every_leadership_route`
- `tests/integration/test_the_leadership_gate_tells_another_role_from_an_ended_session.py::test_the_instructors_launched_session_gets_the_403_from_every_leadership_route`
- `tests/integration/test_the_named_set_routes_admit_leadership_and_refuse_everybody_else.py::test_a_session_in_another_role_gets_the_gates_403_from_every_named_set_route`

## The test

The third, whole body after its docstring:

```python
    answered = ask(named_sets, route, token=token_for(named_sets, session))

    not_your_role_sentence(answered, f"The `{route}` route, asked by the {session} session")
```

The first two loop over the swept routes and call `not_your_role_sentence`,
`the_whole_body_is_the_sentence` and `assert_past_the_gate`, all helpers. None
of the three bodies holds an `assert`, a `with pytest.raises(...)` block or a
`pytest.fail(...)` call of its own. All three carry `@pytest.mark.invariant`.

## What I believe it asserts incorrectly

The tests are right about behaviour: with E7-08's code they pass, and they fail
correctly without it. What is wrong is their shape. `scripts/ci/check_invariant_assertions.py`,
which CI runs over `tests` (`.github/workflows/ci.yml`, the step that runs
`python scripts/ci/check_invariant_assertions.py tests`), refuses an
invariant-marked test whose own body asserts nothing, and it does not follow
helpers. On this branch it exits 1 and names exactly these three:

```
FAIL: 3 `invariant`-marked test(s) assert nothing. A marked test that runs and
asserts nothing is counted as a passing invariant by `check_invariants.py`,
which cannot see the difference.
  tests/integration/test_the_leadership_gate_tells_another_role_from_an_ended_session.py:325: test_a_student_session_gets_the_403_from_every_leadership_route
  tests/integration/test_the_leadership_gate_tells_another_role_from_an_ended_session.py:354: test_the_instructors_launched_session_gets_the_403_from_every_leadership_route
  tests/integration/test_the_named_set_routes_admit_leadership_and_refuse_everybody_else.py:268: test_a_session_in_another_role_gets_the_gates_403_from_every_named_set_route
```

`tests/unit/test_the_invariant_gate_halves_agree.py::test_the_collector_and_the_assertion_scan_count_the_same_invariant_tests`
runs the same checker and fails for the same reason, so the backend unit suite
is red too.

## The spec text I am relying on

`CLAUDE.md`, "CI and build discipline": "**Never merge or mark a pull request
ready with red CI.**" and "**The §4.1 invariant suite may never be skipped.**
CI runs it in an isolated pass and treats a skip, an xfail, or an empty
collection as a failure". The checker's own message: "The body must contain an
`assert`, a `with pytest.raises(...)` block, or a `pytest.fail(...)` call. An
assertion inside a helper the test calls does not count (E0-36 §3: helpers are
not chased); move one line into the test."

## What I tried

Nothing on the code side can change this: the checker reads the test source,
not the application, and `git diff 28f44595 -- tests` is empty on this branch,
so the failure was already present in the red commit. The fix is one line in
each of the three bodies, which is inside `tests/**` and not mine to write.

## Why I believe the test rather than my code is at fault

The checker is a static scan of test files, and its finding is a property of
the test text alone. A suggested repair that keeps each test's meaning: have
the helper's return value asserted in the body, for example
`assert not_your_role_sentence(...)` (the helper returns the sentence, which is
non-empty when it returns at all) in the third test, and the same around the
`gate.add(...)` call's argument, or a closing `assert len(gate) == 2` (the 401
sentence and the one 403 sentence), in the first two.

## Ruling

The test is wrong. `scripts/ci/check_invariant_assertions.py` requires every invariant test to assert in its own body, and the three tests assert only through helpers. The test author adds one assertion in each test body that states the test's own claim. No product code changes.
