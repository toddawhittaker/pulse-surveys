# E3-05-01 — E3-03's purity sweep and E3-05's committed contract cannot both be green

**Ticket:** E3-05
**Test:** `tests/unit/test_the_grading_module_reaches_no_network_ags_or_job.py::test_the_grading_module_imports_no_network_ags_or_job_name`

## The test

The assertion itself:

```python
def test_the_grading_module_imports_no_network_ags_or_job_name() -> None:
    canary = SWEEP_CANARY.read_text(encoding="utf-8") if SWEEP_CANARY.is_file() else ""

    assert found == {}, (

        "E3-05's, the schedule is E3-06's, and the whole value of keeping them out is that the "

```

and the detector it rests on:

```python
NETWORK_ROOTS = frozenset(
    {"httpx", "httpx2", "requests", "urllib", "urllib3", "aiohttp", "socket", "smtplib", "http", "ssl"}
)
JOB_ROOTS = frozenset({"celery", "kombu", "redis"})
JOB_FRAGMENTS = ("app.jobs",)
AGS_WORDS = ("ags", "lti", "line_item", "lineitem", "score_post")


def forbidden_imports(source: str, *, filename: str = "<sample>") -> dict[str, list[str]]:
    found: dict[str, list[str]] = {category: [] for category in FORBIDDEN_CATEGORIES}
    for path in imported_paths(source, filename=filename):
        lowered = path.lower()
        segments = lowered.split(".")
        root = segments[0]
        if root in NETWORK_ROOTS:
            found["network"].append(path)
        if root in JOB_ROOTS or any(fragment in lowered for fragment in JOB_FRAGMENTS):
            found["job"].append(path)
        if any(segment_names(segment, word) for segment in segments for word in AGS_WORDS):
            found["ags"].append(path)
    return {category: names for category, names in found.items() if names}
```

`imported_paths` walks the whole AST, so a function-local import counts the same
as a module-level one.

The module docstring states the subject: "E3-03's eighth criterion: 'No network
call, no AGS type, and no job import appears in the module.' … E3-04 and E3-05
own the posting and E3-06 owns the schedule, and the value of having the
arithmetic in a module none of them can reach is that the arithmetic can be
tested without any of them."

## What I believe it asserts incorrectly

Nothing about its own ticket. What it asserts incorrectly *now* is that
`backend/app/services/grading.py` will go on holding only the formula. E3-05 is
the ticket that puts the AGS passback path in that module, and the sweep refuses
all four of the imports that path is made of:

| The import D3 requires | Category the sweep refuses it under |
|---|---|
| `from app.lti.ags import find_or_create_line_item` | `ags` (segments `lti` and `ags`) |
| `from app.models.lti import AGS_LINE_ITEM_ADDRESS_COLUMN, RegistrationAddressError, refuse_invalid_fetched_address` | `ags` (segment `lti`) |
| `from app.jobs.celery_app import publish_once` / `from app.jobs.tasks import create_line_item` | `job` (fragment `app.jobs`) |
| `import requests` — the type of the `outbound_transport()` seam | `network` (root `requests`) |

So two committed suites now contradict each other, and both are inside
`tests/**`:

- E3-05's fixtures pin the module. `tests/fixtures/line_item_creation.py` line
  86: `GRADING_MODULE = "app.services.grading"`, with the reason written beside
  it — "D3: 'the creation service lives in `backend/app/services/grading.py`'
  (SPEC §13 line 433 names that module)". `GRADING_LOGGER = GRADING_MODULE`, and
  `test_a_staff_launch_is_prompt_with_the_broker_at_a_closed_port.py` requires an
  error-level record under a logger of exactly that name.
- E3-03's sweep forbids the module the imports that service is made of.

## The spec text I am relying on

SPEC §13, the services tree, line 433 and its neighbours:

```
├── services/               # domain logic (the real app lives here)
│   ├── validity.py         # synchronous comment gating (§3.3)
│   ├── grading.py          # participation formula + AGS passback (§3.4)
│   ├── reporting.py        # distributions, trend lines, benchmark assembly (§5.1)
```

The module's stated contents are "participation formula **+ AGS passback**". The
sweep's property therefore holds only for as long as the passback half is
unbuilt, and E3-05 is the ticket that builds it.

SPEC §3.4, the sentence E3-05 exists to wire: "One AGS line item per section:
**'Pulse Participation'**, created by the tool on first launch."

## What I tried

Four approaches, three of them rejected on their merits rather than by a test.

1. **The service in `grading.py`, exactly as D3 settles it.** Every E3-05 test
   that names the module goes green; this sweep goes red on all three categories.
2. **A separate module — say `app/services/passback.py` — re-exported from
   `grading.py`.** The sweep would pass, because `app.services.passback` matches
   no root, fragment or word. Rejected twice over. It is a closed-set guard
   defeated one level out: importing `grading` would still pull the AGS client,
   Celery and `requests` in transitively, so the property the sweep protects —
   "the arithmetic can be tested without any of them" — would be gone while the
   sweep reported it intact. And it does not actually work: the fixture
   substitutes `app.services.grading.outbound_transport`
   (`tests/fixtures/line_item_creation.py::reaching_the_platform`), which only
   reaches a worker that reads that attribute off *that* module at call time, and
   criterion 5 wants `logging.getLogger(__name__)` in the module that owns the
   enqueue to be `app.services.grading`.
3. **Dropping `import requests` by annotating the transport seam `Any`.** Removes
   one of the three categories and leaves the other two exactly where they were.
4. **E3-03's own escape.** Its attempts file, section 2, records the same
   over-match hit from the other side: `from app.models.lti import NrpsCall` was
   refused for the word `lti`, and the module reads `nrps_call` through
   `Base.metadata.tables` instead — "worked around, not disputed", with the note
   that "a later ticket may prefer to narrow the word list". There is no
   equivalent here: a metadata table gets you a row, and what this ticket needs is
   a function call into the AGS client and a Celery publish.

## Why I believe the test rather than my code is at fault

The sweep is not wrong about anything it was written to say; it has simply
outlived its scope, and it says so itself. Its own docstring names E3-05 as the
owner of the posting, and SPEC §13 names this module as the home of "participation
formula + AGS passback". A guard whose subject is "this module holds only half of
what the spec says it holds" is true until the other half is built and false
afterwards, and E3-05 is the change that makes it false. This is
`docs/MISTAKES.md` entry 1 arriving on the test side: a record went on asserting
something a later change made false.

The evidence that the test author of E3-05 intended this class of repair and
missed this one instance: the same commit (`30d669b`) edits the two *other*
committed inventories E3-05 makes stale — `SANCTIONED_WRITERS_EXPECTED` in
`tests/unit/test_a_sanctioned_writer_satisfies_the_chokepoint.py` and
`RUNTIME_COLUMN_PRIVILEGES` in `tests/integration/test_identity_grants.py` — each
with a paragraph explaining why E3-05 adds an entry. This sweep is a third
inventory of the same kind and was not visited. The manifest records what it
deliberately left out of the grading module's guards
(`test_every_writer_of_an_lms_owned_relation_names_the_guard.py`, considered and
excluded with a reason); this sweep is not in that list either way.

**The repair is small and it is on the test side.** What E3-03's criterion 8
protects is that the *arithmetic* is measurable without a platform, and that
survives the passback landing beside it — the formula's own functions still call
nothing that reaches a network. So the honest narrowing is a sweep scoped to the
formula rather than to the file: for instance, restricting the parsed subtree to
`participation_scores` and the private helpers it calls, or asserting that
importing the module performs no network call rather than that no such name is
imported. Either keeps E3-03's property, and both are the test author's to write,
not mine.

**What I did while this was open.** I did not edit, skip or work around the test,
and I did not route around it with option 2. I built the rest of E3-05 to its
committed contract, which leaves this one pre-existing assertion red and every
other test in the suite green; the state and the reason are in
`docs/tickets/e3/.attempts/E3-05.md` and in the pull request body. Stopping the
service instead would leave ten of the ticket's fifteen reds unbuilt and would not
change what the ruling has to decide, because every outcome here is a change
inside `tests/**`.
