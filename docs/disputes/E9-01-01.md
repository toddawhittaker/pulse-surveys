# E9-01-01 — the dependency-input test imports a FastAPI function that does not exist

**Ticket:** E9-01
**Test:** `tests/integration/test_the_leadership_scope_comes_only_from_the_session.py::test_the_leadership_scope_dependency_declares_no_request_input_beyond_the_session`

## The test

The test body (lines 175 to 224 at 1bd94352) calls this module helper, first on
the session readers and then on `leadership_scope`:

```python
def request_inputs(call: Callable[..., Any]) -> set[tuple[str, str]]:
    """Every request input a dependency's whole tree declares, as (kind, name)."""
    from fastapi.dependencies.utils import get_dependant, get_flat_dependant

    flat = get_flat_dependant(get_dependant(path="/", call=call))
    found: set[tuple[str, str]] = set()
    for kind in INPUT_KINDS:
        for field in getattr(flat, kind, ()):
            found.add((kind, str(getattr(field, "alias", None) or field.name)))
    return found
```

```python
    readers = [getattr(module, name) for name in SESSION_READERS if hasattr(module, name)]
    assert readers, f"`{DEPS_MODULE}` defines none of {SESSION_READERS}."
    allowed: set[tuple[str, str]] = set()
    for reader in readers:
        allowed |= request_inputs(reader)
```

## What I believe it asserts incorrectly

It does not reach its assertion. `fastapi.dependencies.utils` has no
`get_flat_dependant` in the FastAPI this repository pins (`fastapi==0.142.2` in
`pyproject.toml` and both lockfiles; I downloaded the wheel and read
`fastapi/dependencies/utils.py`) or in the one installed in the shared venv
(0.141.1). Both have `get_flat_params`, which returns a flat list of fields, not
a `Dependant`. So the import raises `ImportError` on the session readers, before
`leadership_scope` is looked at. The test is red whatever the code does, and the
manifest's predicted red (a `pytest.fail` for the missing dependency) was never
the failure it showed.

## The spec text I am relying on

Not a spec disagreement. The ticket's done-when 10: "No leadership route accepts
a person, assignment or scope id that decides whose scope is resolved." The
test's intent (the dependency tree declares no request input beyond what the
session readers declare, with a planted `person_id` dependency as the control) is
right and I am not disputing it.

## What I tried

I built `leadership_scope` and then checked the test's own intent with a helper
that walks `Dependant.dependencies` recursively instead of calling
`get_flat_dependant` (a scratch script, not a test edit):

- the session readers declare `{('query_params', 'secret'), ('query_params', 'token')}`
  (FastAPI reads `verified_session(token, secret)` as two query parameters);
- the planted dependency adds `{('query_params', 'person_id')}`, so the control
  holds;
- `leadership_scope` adds nothing.

The HTTP half of done-when 10
(`test_a_request_naming_another_persons_ids_is_answered_with_the_sessions_own_scope`)
is green.

## Why I believe the test rather than my code is at fault

No implementation can make an `ImportError` from inside the test's own helper go
away. A suggested repair for the test author: replace `get_flat_dependant` with
a recursive walk over `get_dependant(...).dependencies` that collects the five
`*_params` lists at every level, as above.

## Ruling (orchestrator, 2026-10-12)

The test is wrong. `get_flat_dependant` does not exist in the pinned FastAPI. The test author rewrites the helper to walk `Dependant.dependencies` recursively, as the builder's scratch check did, and keeps the planted `person_id` control.
