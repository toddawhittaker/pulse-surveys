# E9-07-01 — The cohort label's "U" is the start letter, and the test reads it as a section count

**Ticket:** E9-07
**Test:** `tests/integration/test_the_rollup_names_and_cohorts_on_the_seeded_institution.py::test_a_college_with_two_start_cohorts_carries_one_labelled_series_each_on_the_term_axis`

## The test

The part in dispute (the whole test is in the file at commit 2ed08f0f):

```python
    wrong_labels = []
    wrong_weeks = []
    for cohort in figures.cohorts:
        start = cohort.section_start_date
        count = sum(1 for begun in starts.values() if begun == start)
        pattern = rf"{count} sections? · started {start.month}/{start.day}"
        if not re.fullmatch(pattern, cohort.label):
            wrong_labels.append((str(start), cohort.label, f"{count} sections · started …"))
        ...
    assert not wrong_labels, f"Cohort labels (start, served, expected): {wrong_labels}."
```

Its docstring says: 'The label is "N sections · started M/D" (N counted over
the college's sections with that start date; "1 section" is allowed).'

## What I believe it asserts incorrectly

It requires the cohort label to begin with the **number of sections** in the
cohort ("9 sections · started 8/17"). The label the spec and the design give
begins with the cohort's **start letter** ("U sections · started 8/17", meaning
"the sections whose code starts with U"). The service serves the letters: on the
seed, "2/E/K/S/U/V/X sections · started 8/17", "R sections · started 9/7",
"Q sections · started 9/28". The test fails on exactly that difference and on
nothing else known.

## The spec text I am relying on

SPEC §2.2, the bullet before and the bullet in question:

> - Section codes follow `{startLetter}{ordinal}{modality}` (e.g., `R3WW`,
>   `Q2FF`): the start letter encodes length + start date within the term via a
>   per-term **start-letter map** (admin-configured data; Fall 2026 seed: 12-week
>   U/R/Q starting 8/17, 9/7, 9/28; ...).
> - **Two week axes.** ... Aggregate pages plot the **term axis** (TERM 01–18)
>   with one line per start cohort and a cohort selector (e.g., "U sections ·
>   started 8/17") — averaging week-3-of-course across cohorts that began five
>   weeks apart would be meaningless.

"U" and "8/17" are the start letter and start date the bullet above defines
together ("12-week U ... starting 8/17").

`design/CLAUDE.md`, the design notes: "Roll-up cohort chips = start letters (U ·
started 8/17, R · 9/7, Q · 9/28 for 12-week Fall)."

`design/LeadershipRollup.dc.html` lines 134 to 138, the mockup's cohort list:
`'U sections · started 8/17'`, `'R sections · started 9/7'`,
`'Q sections · started 9/28'`. A count would not be the same letter in three
mockups whose section counts differ.

The ticket's done-when 6 quotes the same example ("U sections · started 8/17")
without defining "U".

## What I tried

One approach: the service as the light builder wrote it, which joins the
cohort's distinct start letters (`leadership_rollup.label.cohort`,
"{letters} sections · started {month}/{day}"). I did not change it to a count,
because that would implement a label the spec and design do not give in order
to turn a test green.

## Why I believe the test rather than my code is at fault

The example string is the spec's, and the spec's preceding sentence defines
both of its parts: U is a start letter and 8/17 is that letter's start date. The
design notes say outright that cohort chips are start letters, and the mockup
uses the letters U, R and Q for three cohorts. Nothing in SPEC, the design or
the ticket says the label carries a count. The test author appears to have read
the placeholder "U" as "some number".

One open question the arbitrator may want to settle at the same time: on the
seed, several 8/17 letters (2, E, K, S, U, V, X: different course lengths)
share one start date, so one cohort's label lists seven letters. The spec's
cohort is "per start cohort" (a start date), so they are one line; how the
label spells several letters ("2/E/K/S/U/V/X") is the service's current choice
and is not in dispute here.

The rest of this test (one cohort per start date in date order; each point at
the term week of its course week) is not disputed, and the service was checked
against it separately (see `docs/tickets/e9/.attempts/E9-07.md`, attempt 2).

## Ruling

The test is wrong; the service is right. SPEC §2.2 gives the aggregate pages' cohort selector as "U sections · started 8/17", the ticket's done-when 6 quotes the same label, and design/CLAUDE.md says "Roll-up cohort chips = start letters". A cohort is a start date, so when several start letters begin on one date the label names each of them, joined by "/", as the service does. The test author changes the label assertion to the start-letter form; the rest of the test stands.
