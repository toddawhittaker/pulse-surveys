# E8-01-01 — the release-batch status test decides on week-3 comments before their verdicts exist

**Ticket:** E8-01
**Test:** `tests/integration/test_only_published_and_kept_comments_reach_a_student.py::test_a_release_batch_carries_its_published_and_kept_comments_and_none_of_the_others`

## The test

```python
def test_a_release_batch_carries_its_published_and_kept_comments_and_none_of_the_others(
    hold: HoldWorld,
) -> None:
    world = hold
    texts = texts_for("week three")
    ids = plant_every_state(world, HELD_WEEK, texts)
    canonical = [answer_id_of(world, text) for text in HELD_COMMENTS[HELD_WEEK]]
    a_batch(
        world,
        cut_at=report_opens(LATEST) - CUT_BEFORE_OPENING,
        answer_ids=[*canonical, *ids.values()],
    )
    decide(world, ids["kept"], KEEP)
    decide(world, ids["excluded"], EXCLUDE)
    student = world.a_student("statuses-released", world.taught)
    world.stand_after_the_opening(LATEST)
    ...
```

## What I believe it asserts incorrectly

It fails in its own world, before any E8-01 code runs: `decide(world,
ids["kept"], KEEP)` gets a 404 from E6-03's decision route and the fixture's
assertion reports "A broken world, not a red." It did so at the red head
a6a3753a too (the manifest predicted "red at read"; the recorded failure is the
`decide` assertion at `tests/fixtures/student_week.py:395`).

The cause, found by reading the rows from inside `comment_on_instructor_report`
during the run:

- The six planted week-3 comments carry a `COMMENT_VALIDITY` classification and
  **no `MODERATION` classification**. The three canonical week-3 comments carry
  `MODERATION:clear`.
- `report_comment` v004 shows only comments holding a moderation verdict, so the
  instructor's released list (`released_cards`) holds the three canonical
  comments and none of the six. The decision door finds only comments the report
  returns, so it answers 404.
- The verdicts are owed, not missing: `tests/fixtures/report_views.py`'s submit
  routes a comment's verdict through `PendingVerdicts.route_when_closed`, which
  holds it until the comment's window has closed by the world's clock. At the
  moment of the `decide` calls the world's clock has published course week 1
  only (the instructor's published-week list read there is `[1]`), so week 3's
  window has not closed and its verdicts are not routed.

So the `student_week.plant_comment` docstring's premise ("Planted while the
clock still stands where the world left it (after every window has closed), so
the verdict is routed at once rather than owed") does not hold in the hold
world for course week 3. `assert_the_care_record_holds` would fail for the same
reason (no verdict, so no `threat_case`).

The shown-stream twin in the same module plants into course week 1, whose
window has closed, and it passes.

## The spec text I am relying on

None is in question. SPEC §5.2 and ADR 0187: a comment is shown to any reader
only once it holds a moderation verdict. The product behaves as specified; the
world does not reach the state the test describes.

## What I tried

Nothing in the code can make this test pass without changing what a reader is
shown for a comment with no verdict, which would break ADR 0187. The test's
later assertions (the student's release group) are already satisfied by the
built code in its sibling tests (`test_the_release_group_...` and the
shown-stream twin here).

## Why I believe the test rather than my code is at fault

The failure is in the world-building, at the fixture's own "broken world"
assertion, and it reproduces at the red head before any E8-01 code exists. A
likely repair, for the test author to judge: before the two `decide` calls,
move the clock past course week 3's close and then route the owed verdicts.
Moving the clock alone is not enough: `HoldWorld.stand_at` calls only
`door.pretend`, which sets the override and routes nothing, while the canonical
world routes its owed verdicts with an explicit `world.plant_pending()` after
setting the clock (`tests/fixtures/report_api.py`, around line 1621).
