# E2-06-02 — The browser spec declares a helper it never calls, and the node gates refuse it

**Ticket:** E2-06
**Test:** `tests/e2e/window-scheduling.spec.ts` (the file, not one case — it is `tsc` and `eslint` that refuse it, before any case runs)

## The test

```ts
/** The whitespace-trimmed text of one testid on the page as it stands. */
async function readout(page: Page, testid: string): Promise<string> {
  return ((await page.getByTestId(testid).textContent()) ?? '').trim();
}
```

`tests/e2e/window-scheduling.spec.ts:92`. Nothing in the file calls it: the spec
reads the console through `openWindowCell`, which does its own
`textContent()` on the row's cell, and the three clock testids it imports are
used by `clearTheClock` and `setTheClockTo` through `expect(...)` and `fill(...)`
rather than through this helper.

## What I believe it asserts incorrectly

Nothing about the product. The spec's three assertions are E2-06's criterion 3
and they are the right ones. What it does is fail both of CI's `Fast · tsc +
eslint` steps, on this branch, whatever the implementation does:

```
$ npx tsc --noEmit
tests/e2e/window-scheduling.spec.ts(92,16): error TS6133: 'readout' is declared but its value is never read.

$ npx eslint . --max-warnings=0
/home/todd/projects/wt-e2-06/tests/e2e/window-scheduling.spec.ts
  92:16  error  'readout' is defined but never used  @typescript-eslint/no-unused-vars
```

Both exit non-zero. The workspace steps beside them (`npm run typecheck
--workspace frontend`, `npm run lint --workspace frontend`) pass, so this one
declaration is the whole of it.

## The spec text I am relying on

None applies — this is a lint and compile failure rather than a reading of the
spec. The rule it runs into is `CLAUDE.md`'s, under CI and build discipline:

> **Never merge or mark a pull request ready with red CI.** Not "it's unrelated,"
> not "it passes locally."

and ADR 0002's, that a tolerance is removed by the ticket that lands the code —
`--max-warnings=0` is deliberate and is not something to widen for this.

## What I tried

Nothing on my side, because there is nothing to try: the declaration is in
`tests/`, the hook refuses an edit there, and no implementation of the window
service can make an unused function used. I confirmed the two failures by running
the exact commands `.github/workflows/ci.yml`'s `lint-frontend` job runs, at the
repository root, after `npm ci` — and confirmed that the two frontend-workspace
steps in the same job are green, so the report is about this file alone.

I also confirmed it is not something my diff introduced: the file arrived in
`5c7ac9b`, the red-tests commit, and my branch does not touch `tests/`.

## Why I believe the test rather than my code is at fault

The failing artifact is a test file; the failing gate reads only test files; and
the repair is one line — delete the helper, or use it in `openWindowCell` and
`clearTheClock`, which is plainly what it was written for and would be the better
of the two, since those two functions each contain a copy of its body.

It is worth saying which way I would not repair it: not by relaxing
`--max-warnings=0`, not by an `eslint-disable` comment, and not by excluding
`tests/e2e/` from the root `tsconfig.json`. Each of those makes the gate quieter
for every future file to spare one line in this one, which is the shape ADR 0002
and `CLAUDE.md`'s "do not weaken a gate to get past it" both refuse.
