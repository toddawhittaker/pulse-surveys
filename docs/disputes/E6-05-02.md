# E6-05-02 — The copy inventory has no governed surface for the new `leadership_moderation.` copy module the ticket owns

**Ticket:** E6-05
**Test:** `tests/unit/test_the_shipped_copy_inventory_holds_to_items_four_and_five.py::test_every_collected_key_belongs_to_a_governed_surface`
(its `GOVERNED_SURFACES` and `SURFACES_WITH_NO_CONFIDENTIALITY_LINE` maps)

## The test

```python
def test_every_collected_key_belongs_to_a_governed_surface() -> None:
    ...
    inventory = collect_shipped_copy()
    assert inventory, "The inventory is empty, so this rule passed over nothing."
    stray = ungoverned_keys(inventory)
    assert not stray, (
        f"These collected keys belong to no governed surface: {stray}. ..."
        "Adding the surface is one row in `GOVERNED_SURFACES`, plus its "
        "confidentiality key in `CONFIDENTIALITY_KEY_OF_SURFACE` if that surface carries the line."
    )
```

`GOVERNED_SURFACES` holds twelve prefixes; none is the new module's.

## What I believe it asserts incorrectly

Nothing about the rule is wrong; the map it reads is one row short. E6-05's
ticket owns `backend/app/copy/leadership_moderation.py` (new), and the red
fixture `tests/fixtures/lead_review.py` requires the routes' refusal sentences
to be registered there (`lead_moderation_copy`, `lead_sentence_of`, which look
the module up through `copy_modules()`). Every registry module keys its entries
under a prefix, and this one's are `leadership_moderation.*`. With the module
built, the test fails:

```
AssertionError: These collected keys belong to no governed surface:
['leadership_moderation.no_review_grant', 'leadership_moderation.not_in_queue',
 'leadership_moderation.reason_blank', 'leadership_moderation.reason_too_long'].
```

That is `docs/MISTAKES.md` entry 22's shape: the ticket's new surface reached an
earlier ticket's inventory on the other side of the wall, and the red commit did
not add the row. Only the test author can.

## The spec text I am relying on

The ticket's "Owns":

> - `backend/app/schemas/moderation.py` (new) and
>   `backend/app/copy/leadership_moderation.py` (new).

The test's own instruction for exactly this case, in its failure message:
"Adding the surface is one row in `GOVERNED_SURFACES`, plus its confidentiality
key in `CONFIDENTIALITY_KEY_OF_SURFACE` if that surface carries the line."

SPEC §4.1 items 4 and 5, which the inventory exists to sweep: item 4's
vocabulary reaches every surface, and item 5's line is counted per surface.

## What I tried

Two alternatives, both rejected rather than built:

1. Keying the four sentences under an existing governed prefix
   (`leadership_comparison_sets.`). It would turn the test green and file the
   moderation review screen's refusals under the named-set screen, which is a
   different surface E5-09 renders; item 5's per-surface count would then be
   about the wrong screen.
2. Leaving the sentences inline in the router. The fixture requires them in the
   registry, and the copy package's rule is that no user-facing string lives
   anywhere else.

So the module is built as the ticket says, under its own prefix, and this one
test is red.

## Why I believe the test rather than my code is at fault

The code does what the ticket owns; the governance map needs the row the test's
own message prescribes. The amendment I would expect, beside the
`leadership_comparison_sets` row:

```python
    # E6-05's moderation review routes: the four refusals the queue, the decision
    # and the log answer with. E6-06's frontend copy for the same screens joins
    # this prefix or registers its own row.
    "leadership_moderation": LEADERSHIP_MODERATION,
```

with `LEADERSHIP_MODERATION = "leadership_moderation"` declared beside the
other surface names, and an entry in `SURFACES_WITH_NO_CONFIDENTIALITY_LINE`
giving the reason: the four sentences are refusals to a leader that say what is
not there to read, and none tells a student anything about their identity.
Whether the leadership moderation pages E6-06 builds owe item 5 a line is that
ticket's question; the backend refusals alone do not carry one.
