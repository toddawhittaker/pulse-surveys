# E5.1-03-01 — The deps sentence sweep reads the font name `'Spline Sans Mono'` as a sentence, so it cannot pass beside R6's token block

**Ticket:** E5.1-03
**Test:** `tests/unit/test_the_api_deps_module_ships_no_ungoverned_sentence.py::test_api_deps_holds_no_sentence_outside_the_copy_registry`

## The test

```python
def test_api_deps_holds_no_sentence_outside_the_copy_registry() -> None:
    """Criterion 2: the ungoverned-sentence sweep covers `api/deps.py` and finds nothing.
    ...
    **The near misses it spares** are the
    controls above: docstrings, the one `RuntimeError`, the template's styles and
    its two-word title.
    ...
    """
    source = require_the_deps_module()
    result = scan(source, str(DEPS_PATH))

    assert result.examined > 0, (...)
    assert not result.findings, (...)
```

The rule it applies is the module's `SENTENCE` pattern:

```python
SENTENCE = re.compile(r"(?<![\w-])[A-Za-z]+(?: [A-Za-z]+){2,}(?![\w-])")
```

## What I believe it asserts incorrectly

It names a CSS font-family name as an ungoverned sentence. On the built tree
the scan's only finding is this one:

```
line 448: ":root {\n  --chalk: #F6F8F4; ... --font-mono: 'Spline Sans Mono', ui-monospace, monospace; ... }"
sentence='Spline Sans Mono'
```

That string is `app.api.deps.DESIGN_TOKENS_CSS`, the one token block ruling R6
puts in `deps.py`. `Spline Sans Mono` is the name of a typeface. No person is
served it as words: it sits inside a `<style>` element on the door pages and in
the console's stylesheet.

The test module's own docstring states the intended reading. It lists
`'Schibsted Grotesk'` and `'Helvetica Neue'` as non-sentences the rule "must
leave alone", and its stylesheet control
(`test_a_stylesheet_a_testid_and_a_two_word_title_are_left_alone`) proves that
for two-word font names. The control has no three-word font name, so the case
was never exercised. `Spline Sans Mono` is three words, so the pattern names it.

## The spec text I am relying on

The ticket, `docs/tickets/e5.1/E5.1-03-api-edge.md`, "Done when":

> 2. **No literal is left behind.** The ungoverned-string sweep covers
>    `api/deps.py` and finds nothing.
> ...
> 5. **The token values have one source.** Both pages use one design-token CSS
>    block, and a test reads its values from `design/tokens.css`.

Ruling R6 of the work order:

> `deps.py` gains `DESIGN_TOKENS_CSS`: one `:root { ... }` rule holding the
> union of the custom properties both pages use, values exactly as
> `design/tokens.css` spells them — `--chalk --paper ... --font-display
> --font-body --font-mono ...` ... `dev.py` imports it from `app.api.deps`. No
> new module (rejected: a module for one constant).

Ruling R3 of the work order:

> Two-word strings are a disclosed limit (stated in the module docstring) — the
> font names `'Schibsted Grotesk'`, `'Helvetica Neue'` and the `<title>`'s
> `Pulse Surveys` are two-word strings the rule must leave alone.

And `design/tokens.css`:

> `--font-mono: 'Spline Sans Mono', ui-monospace, monospace;        /* Numerals, eyebrows, ... */`

## What I tried

One approach, built honestly: `DESIGN_TOKENS_CSS` in `deps.py` with every
value spelled as `design/tokens.css` spells it (commit 1d86b9a). Every R6 test
is green on it (19 of 19), and the focus-ring test is green. This one rule is
red, on that one finding only.

I then checked whether any honest build satisfies both tests:

- **`--font-mono` cannot be left out of the block.** The console's stylesheet
  uses `var(--font-mono)` four times. So
  `test_no_page_uses_a_token_the_block_does_not_declare[STYLE]` requires the
  block to declare it.
- **Its value cannot be spelled differently.**
  `test_every_token_the_block_declares_has_the_value_design_tokens_gives_it`
  compares it to `design/tokens.css` after normalising whitespace, quotes and hex
  case only. The two spellings that dodge the pattern and pass that comparison are
  a doubled space (`'Spline  Sans Mono'`) and a runtime join of the three words.
  The first names a different typeface to a browser. The second uses the blind
  spot the sweep's own docstring discloses ("a sentence assembled at runtime").
  Both defeat the sweep rather than satisfy it.
- **The block cannot live outside `deps.py`.** R6 rejects a new module for it.
  `app.api.dev` cannot hold it either, because `dev.py` imports from
  `app.api.auth`, which imports `app.api.deps`. Moving the constant only to get
  it out of the sweep's reach would be the same dodge.

So, on the rulings as written, the token tests and this rule cannot both be
green.

## Why I believe the test rather than my code is at fault

The code does what R6 says, with the value that `design/tokens.css` gives. The
sweep exists to find words a person is served that the copy registry does not
hold. A typeface name inside a stylesheet is not such a word. The test's own
docstring and its controls already treat quoted font names in a stylesheet as
non-sentences. They only failed to cover a font name of three words.

A possible fix for the test author, not a prescription: a control pair in which
a stylesheet carrying `'Spline Sans Mono'` (or any quoted three-word family
name followed by `,` or `;`) is left alone, while the same three words outside
quotes are named. The arbitrator may prefer a different rule. That choice
belongs to the test author.

Everything else in E5.1-03 is built and green. This item is the only red.

## Ruling

The test is wrong. The work order's R3 (three words in a row make a sentence)
and R6 (the token block carries `--font-mono` exactly as `design/tokens.css`
spells it) conflict, and the conflict was in the work order itself, not in
the code. The ruling rests on the ticket's purpose for criterion 2: the sweep
finds words a person is served, and a typeface name in a stylesheet is not
such words. The sweep now removes the value of every `font-family` declaration
and every `--font-*` custom property, up to the next `;` or `}`, before the
three-word rule runs. It does not exempt the constant by name, and it does not
exempt quoted strings in general. A new control pair holds both directions. A
three-word typeface in either declaration is left alone. The same words in a
`content:` declaration, or in a plain string, are each named.
