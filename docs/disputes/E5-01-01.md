# E5-01-01 — the `seed_rows` wrapper drops the positional-only marker `seed_row` needs, so no test can name a `comparison_set`

**Ticket:** E5-01
**Tests:**

- `tests/integration/test_a_comparison_set_declares_one_length_and_one_level.py::test_two_sets_may_not_share_a_name`
- `tests/integration/test_a_comparison_set_declares_one_length_and_one_level.py::test_two_sets_with_different_names_are_both_stored`
- `tests/integration/test_a_comparison_set_member_matches_the_declared_level.py::test_one_course_may_be_named_in_two_different_sets`

The defect is not in those three test bodies. It is in the fixture they reach
the database through, `tests/fixtures/supervision.py::seed_rows`.

## The test

The three tests fail before they touch the database, inside
`tests/fixtures/comparison_sets.py`:

```python
def write_set(seed: Any, *, length: Any, level: Any, name: Any = None) -> Any:
    values: dict[str, Any] = {LENGTH_COLUMN: length, LEVEL_COLUMN: level}
    if name is not None:
        values[NAME_COLUMN] = name
    return seed(COMPARISON_SET_TABLE, {}, **values)
```

with

```
E  TypeError: seed_rows.<locals>.seed() got multiple values for argument 'name'
```

`NAME_COLUMN` is `"name"`, so a caller that supplies a set's name calls
`seed("comparison_set", {}, name="One cohort")`.

The helper that finally runs the insert has been written for exactly this, and
says so in its own docstring (`tests/fixtures/supervision.py:601`):

```python
def seed_row(
    session: Any,
    tables: dict[str, Any],
    name: str,
    chain: dict[str, Any] | None = None,
    /,
    **overrides: Any,
) -> Any:
    """Insert one row into `name`, building whatever ancestors it requires.

    **The four parameters are positional-only**, and the `/` is load-bearing:
    `name` is also the name of a column on four of this schema's tables, so
    without it `seed_row(session, tables, "institution", name="…")` is a
    `TypeError` about two values for one argument rather than a row with the
    name the caller asked for. Every call site already passes these four
    positionally.
    """
```

The fixture that binds it to the session drops the marker
(`tests/fixtures/supervision.py:1295`):

```python
@pytest.fixture
def seed_rows(db_session: Any, metadata_tables: dict[str, Any]) -> Callable[..., Any]:
    _GRAPH_INTEGER_COUNTERS.clear()

    def seed(name: str, chain: dict[str, Any] | None = None, **overrides: Any) -> Any:
        return seed_row(db_session, metadata_tables, name, chain, **overrides)

    return seed
```

`tests/integration/test_the_comparison_set_schema_survives_a_downgrade.py:222`
declares a second closure of the same shape, with the same omission. It does not
fail today only because that module never passes a name.

## What I believe it asserts incorrectly

Nothing in the three test bodies is wrong, and nothing in the criterion they
cover is wrong. What is wrong is that the wrapper reintroduces precisely the
collision the `/` on `seed_row` exists to prevent, so the wrapper cannot write a
row to any table with a column called `name` — `institution`, `college`,
`department` and now `comparison_set`. E5-01 is the first ticket whose tests ask
it to.

The consequence for the criterion: the two halves of the uniqueness pair for
`comparison_set.name` (criterion 1) and the "one course in two sets" half of the
membership uniqueness pair (criterion 2) cannot execute at all, whatever the
schema does.

## The spec text I am relying on

This is not a disagreement about the spec. The rule the three tests assert is
SPEC §8's one-institution-per-deployment uniqueness applied to a set's name, and
SPEC §5.1's "leadership can define named sets", and I have implemented both:
`UNIQUE (name)` on `comparison_set`, and `UNIQUE (set_id, course_id)` rather than
`UNIQUE (course_id)` on the membership table.

## What I tried

1. **Implemented the schema as the breakdown settles it** — `comparison_set`
   with `UNIQUE (name)`, `comparison_set_member` with `UNIQUE (set_id,
   course_id)`, migration `b4d7e2a91c58`. Every other test in the ticket's seven
   modules goes green: 129 passed, these 3 failed, and each of the 3 fails with
   the `TypeError` above rather than with an assertion.

2. **Looked for a schema-side answer and there is none.** The column's spelling
   is not mine to choose: `NAME_COLUMN = "name"` in
   `tests/fixtures/comparison_sets.py` is what `write_set` writes, and
   `REACHED_TABLES_THAT_CARRY_NOTHING["comparison_set"]` in
   `tests/integration/test_identity_column_marker.py` pins the column tuple
   including `name` as an exact equality, as does
   `NAMES_THAT_HOLD_NO_PERSON[("comparison_set", "name")]`. A differently spelled
   column turns three further tests red.

3. **Proved the attribution rather than asserting it.** With the wrapper's
   signature changed to `def seed(name, chain=None, /, **overrides)` at run time
   from a scratch pytest plugin — no file in `tests/` edited, and the plugin is
   not committed — the two modules run **48 passed, 0 failed** against the schema
   as it stands. Nothing else was changed.

## Why I believe the test rather than my code is at fault

The fixture's own sibling documents the bug: `seed_row` carries the `/` and a
paragraph explaining that without it a table with a `name` column cannot be
seeded, and the wrapper one screen further down loses it. The repair is one
character in `tests/fixtures/supervision.py` — a `/` before `**overrides` — and
the same character in the closure at
`tests/integration/test_the_comparison_set_schema_survives_a_downgrade.py:222`,
which is a latent copy of the same defect rather than a live one.

The measurement above is what separates "the fixture" from "the schema": with
the one-character change and no other, every test in the two modules passes.

I have made no change to any file under `tests/`, and I am stopping on these
three tests only. The rest of the ticket is built and green.
