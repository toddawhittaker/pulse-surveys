# E5.1-03-02 — The new helper test is a repository-wide sweep to the docs-only-diff guard, and its ledger row is behind the test wall

**Ticket:** E5.1-03
**Test:** `tests/unit/test_a_documentation_only_diff_does_not_run_the_expensive_gates.py::test_every_repository_wide_sweep_runs_in_a_job_the_filter_cannot_switch_off`

## The test

The assertion that fails, as the whole-unit run printed it:

```
AssertionError: These test modules assert about files an inert diff can change — the whole
repository, or a directory the classification calls inert — and they run only in a job that
an inert diff switches off:
    tests/unit/test_the_api_edge_keeps_one_copy_of_each_helper.py  (uses .rglob() from the repository root)

A documentation-only pull request is exactly when such a sweep has something new to look at,
and it is exactly when it does not run. Either name the relevant node ids in the `lint-python`
job, or — if it genuinely needs no protection — record it in SWEEPS_THAT_NEED_NO_PROTECTION
with the reason.
```

The detector reads `root` as a name for the repository root:

```python
# Names that mean the repository root: the `…parents[N]` idiom this suite uses,
# the `repo_root` fixture in tests/fixtures/lti_services.py, and the bare `root` that a
# helper taking the root as a parameter is called.
#
# **`root` is in this list deliberately, and it over-detects.** ...
# Erring toward over-detection is the right direction: a false match is triaged once
# into SWEEPS_THAT_NEED_NO_PROTECTION with a reason, and a missed one is a gate
# that silently does not run.
```

## What I believe it asserts incorrectly

Nothing is wrong with the guard. What is missing is the triage it asks for. The
test author's new module,
`tests/unit/test_the_api_edge_keeps_one_copy_of_each_helper.py`, walks with
`modules_under(root)`, whose body is `root.rglob("*.py")`. The parameter name
`root` is on the guard's deliberate over-detection list. The module calls
`modules_under` only with `APP_ROOT` (`backend/app`) and `API_ROOT`
(`backend/app/api`), and it reads `*.py` files only. That is the shape of the
existing `SWEEPS_THAT_NEED_NO_PROTECTION` rows for the two E0-35 sweeps and the
E2-14 session-reader sweep: "sweeps *.py under backend/app, and a .py change is
never inert."

So the module needs one row in `SWEEPS_THAT_NEED_NO_PROTECTION`. That set is in
a test module, which the builder may not edit.

## The spec text I am relying on

`CLAUDE.md`, "How a ticket is built: two lanes":

> The heavy loop (`test-author` writes red; the builder-heavy codes to green
> without touching a test, disputes via `docs/disputes/`; ...)

And `docs/MISTAKES.md` entry 22, "A ticket's new rule made an earlier ticket's
tests unrunnable, and the repair was on the other side of the test wall."

## What I tried

Nothing in the implementation can reach this red. The guard reads `tests/`,
`.github/workflows/ci.yml` and `scripts/ci/`. `git diff --stat 267529c HEAD --
tests .github scripts/ci` is empty, so the guard's verdict on this branch is the
one it gave on the red-tests commit. The red belongs to the new test module, not
to any code change. It did not show in the twelve manifest files because the
guard is a different module; only the whole-unit run finds it.

The guard's message offers a second repair: name the module's node ids in the
`lint-python` job in `ci.yml`. That would run, on every diff, a sweep whose every
input is a backend `.py` file, which is never inert. It buys nothing and edits a
process file from a ticket branch. The ledger row is the precedent this module
fits.

## Why I believe the test rather than my code is at fault

The red comes from a test module and is resolved only by a test module. The
proposed row, for the test author:

```python
    # E5.1-03's helper sweep. It matches because its walker takes the root as a
    # parameter named `root`, which is on `ROOT_FIXTURE_NAMES` by design. It is
    # called with `backend/app` and `backend/app/api` only, over `*.py`, so every
    # file it reads is a backend Python file, and a .py change is never inert.
    "tests/unit/test_the_api_edge_keeps_one_copy_of_each_helper.py": (
        "sweeps *.py under backend/app, and a .py change is never inert"
    ),
```

## Ruling

The test is wrong. This red belongs to the new test module, and only a test
module can repair it. The ruling rests on the guard's own comment above
`ROOT_FIXTURE_NAMES`: `root` is on that list deliberately, it over-detects, and
a false match is triaged once into `SWEEPS_THAT_NEED_NO_PROTECTION` with a
reason. The row is added. The module matches only because its walker's
parameter is named `root`. It is called with `backend/app` and
`backend/app/api` only, and it reads `*.py` only, and a Python file is never
inert. This follows the E0-35 and E2-14 rows already in that set.
