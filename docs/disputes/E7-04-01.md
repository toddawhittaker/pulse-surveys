# E7-04-01 — Two repository gates need test-side edits the builder cannot make

**Ticket:** E7-04
**Tests:**
- `tests/unit/test_the_invariant_gate_halves_agree.py::test_the_collector_and_the_assertion_scan_count_the_same_invariant_tests`
- `tests/unit/test_the_committed_prompt_files_are_pinned_by_content.py::test_every_committed_prompt_file_has_a_recorded_hash`

Neither is a dispute with the code. Both are gates that the full backend suite
reds because of something on the test side of the wall. Every one of the 55 test
items this ticket owns passes on the head commit. Nothing in the code can turn
either of these two green.

## The tests

**1. The invariant gate.** `scripts/ci/check_invariant_assertions.py` (run by
the first test above) answers:

```
FAIL: 3 `invariant`-marked test(s) assert nothing.
tests/integration/test_a_draft_quoting_a_hidden_comment_is_refused.py:98: test_the_planted_texts_are_what_this_suite_says
tests/integration/test_a_draft_quoting_a_hidden_comment_is_refused.py:113: test_a_draft_reusing_a_run_of_a_hidden_comment_is_refused

The body must contain an `assert`, a `with pytest.raises(...)` block, or a
`pytest.fail(...)` call. An assertion inside a helper the test calls does not
count (E0-36 §3: helpers are not chased); move one line into the test.
```

Each of the three tests asserts only through a helper:
`assert_the_planted_texts_are_what_this_file_says()` or `assert_unusable(...)`,
both in `tests/fixtures/response_draft.py`.

**2. The prompt pin.** It answers:

```
these prompt files have no recorded hash: ['draft_check.v1.md', 'response_draft.v1.md'].
Add its row to `RECORDED_SHA256` in the pull request that adds the file:
    'draft_check.v1.md': '6289f2d21996f4f0db888362ad41d566c778d055df6510292c2b901125a03eda',
    'response_draft.v1.md': '6d8539faa86c175dd18bc2df959fff96634967f0cf6acebc517aab0847289c72',
```

## What I believe it asserts incorrectly

Neither gate is wrong.

1. The three new tests are each missing one assertion line in the test body
   itself. One example: `answered = drafted(...)` followed by
   `assert answered.status_code == UNUSABLE_ANSWER_STATUS` beside the existing
   `assert_unusable` call. For the control test, any direct `assert`. The
   behaviour is already asserted by the helpers; the gate only requires that
   it be visible in the test body.
2. `RECORDED_SHA256` needs the two rows above, pasted exactly. The ticket owns
   both prompt files, and ADR 0032 requires them to be pinned in the pull
   request that adds them.

## The spec text I am relying on

`CLAUDE.md`: "The §4.1 invariant suite may never be skipped. CI runs it in an
isolated pass and treats a skip, an xfail, or an empty collection as a failure."
The invariant assertion scan is part of that gate. ADR 0032 makes every
committed prompt immutable, and the hash table is how that is enforced.

## What I tried

I tried nothing to work around either gate. Both edits are under `tests/**`,
which this lane may not touch. The hook refuses even reading these files from a
shell.

## Why I believe the test rather than my code is at fault

For item 1, the test author's three tests fall foul of an existing repository
gate. For item 2, the prompt files must exist, the ticket owns them, and the
pin table is test-side. Both need only the edits named above, and neither
changes what any test asserts. I recommend that the orchestrator apply them on
this branch in one commit, as a test-side repair under `docs/MISTAKES.md` entry
22. Nothing else on the branch waits on them.
