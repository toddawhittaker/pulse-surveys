# E9-02-02 — the non-admin mappings read test needs a mapping its world never plants

**Ticket:** E9-02
**Test:** `tests/integration/test_the_people_graph_definers_answer_only_an_admin.py::test_a_read_definer_answers_a_non_admin_nothing[admin_read_lead_mappings-*]` (four cases: a dean, a Care holder, a person with no assignment, a null key)

## The test

```python
@pytest.mark.parametrize("who", REFUSED_CALLERS)
@pytest.mark.parametrize("function", list(READS))
def test_a_read_definer_answers_a_non_admin_nothing(
    people_graph: PeopleGraphWorld, function: str, who: str
) -> None:
    """Done-when 9's "A non-admin caller gets nothing": zero rows, not an error (settled).
    ...
    **The near miss:** the admin's answer to the same read in the same
    world, required non-empty here so that "nothing" is not what everybody gets.
    """
    world = people_graph

    _keys, rows, failure = world.read(function, caller(world, who))
    _admin_keys, admin_rows, admin_failure = world.read(function, world.admin)

    assert failure is None, (...)
    assert rows == [], f"`{function}` answered {who} {len(rows)} rows: {rows[:3]}."
    assert admin_failure is None and admin_rows, (
        f"`{function}` answered the admin {len(admin_rows)} rows ({admin_failure!r}), so the "
        f"empty answer to {who} is what everybody gets."

```

## What I believe it asserts incorrectly

The near-miss assertion requires the admin's answer to be non-empty. The
`people_graph` world (`tests/fixtures/people_graph.py::PeopleGraphWorld.__init__`)
plants four people and their assignments and **no lead mapping**. This test
plants none either. So `admin_read_lead_mappings` has nothing to return to
anyone, and the assertion fails whatever the definer does:

```
AssertionError: `admin_read_lead_mappings` answered the admin 0 rows (None), so the empty answer to a dean is what everybody gets.
```

The people and assignments cases pass, because the world plants rows for those
reads. The sibling test `test_a_read_definer_answers_the_admin_exactly_its_allow_listed_columns`
plants a mapping first (`world.a_mapping(person=world.admin, course=course)`)
for exactly this reason. This test does not.

## The spec text I am relying on

Done-when 9: "A non-admin caller gets nothing." The settled interface §1:
"Reads are written in `LANGUAGE sql STABLE`. A non-admin caller gets **zero
rows**, not an error." R3 returns every row of `lead_faculty_mapping`.

## What I tried

R3 as settled: every mapping, ordered by course, filtered by the admin check.
With no mapping in the database it returns zero rows to the admin, which is the
correct answer. The non-admin half of the test already passes: each of the
four refused callers gets zero rows and no error.

## Why I believe the test rather than my code is at fault

The near miss is meant to show that the admin gets something where the
non-admin gets nothing. That needs a row to exist. The world never plants one
for this read, so no correct implementation can pass, and returning rows that
do not exist would be wrong. That is `docs/MISTAKES.md` entry 30 the other way
round: the fixture fails to supply the value the near miss needs. The repair is
one line at the top of the test, as the sibling test does: plant a mapping
before both reads.
